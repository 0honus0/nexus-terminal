# 后端重构待实机验证

本文是 `refactor/backend-storage-v1` 上 **backend-next N0–N4** 的后续执行与证据清单，记录当前源码的静态检查结果与因缺少真实故障场景而**尚未得到行为验证**的事项。它不是新的软件需求规范、已通过报告或新增测试任务的授权：用户可见行为以 [USAGE](../USAGE.md) 为准，依赖与安全边界以 [Backend 架构](../architecture/BACKEND.md) 为准，测试组织方式和最终 CI 证据以 [E2E](E2E.md) 为准；实施范围见 [下一阶段方案](../后端重构下一阶段实施方案.md)。

**类型检查已通过，局部格式仍失败，行为专项仍待验证。** 当前 Node/pnpm 已可执行；先完成架构及静态收口，再用真实 SSH2/SFTP、隔离数据库及浏览器执行适用的专项；未经实际运行的检查、历史旧包的 PASS、源码审核和 `git diff --check` 均不能改写为本批行为 PASS。不在此文档增加测试源码，也不以放宽断言、扩大超时或重跑换绿替代排查。

## 执行环境与记录约定

首次执行前填写：日期、机器/系统、Node/pnpm 版本、分支及完整提交 SHA、隔离数据目录、实际 SSH2/SFTP 服务版本与网络形态、浏览器版本和所用命令。真实主机须使用专用测试账号、专用临时目录和可撤销的 Host Key/凭据；不得使用生产凭据或对生产服务器注入断线/阻塞。保留命令退出码、失败输出、必要的 fixture 计数器/网络 trace、最终资源和数据库状态。

每项验证结果只可填「待验证」「通过」「失败」「环境阻断」「不适用」，并注明所检 SHA、复现条件、证据路径和遗留风险。**环境阻断不是通过；部分子场景通过不代表该项整体通过。** 发现产品缺陷应回到对应 owner 修复并同步架构/USAGE；验收证据再更新 [E2E](E2E.md)，本清单只更新该缺口的状态或在完整收敛后删除。

## D. 有界 SFTP 与文件数据正确性（N2.1、N2.2）

| D-01 | 多次 `READDIR(handle)`、空目录、200 与 201 项、48 KiB metadata 临界值/超限                  | 使用 `OPENDIR → 分批 READDIR → CLOSE`；成功必须是完整列表，超限整体失败，不可先全量 `readdir(path)` 再截断；远端 handle 最终关闭 | 待验证 |
| D-02 | 元数据异常：负数/不安全 size、mode、mtime，畸形或超长文件名、目录/文件/符号链接类型         | 逐项拒绝非法第三方值；`stat` 跟随链接、`lstat` 保留链接自身身份；无假造的有效数据                                                | 待验证 |
| D-03 | UTF-8 文件为空、恰好 16 KiB、超过 16 KiB、无效 UTF-8、BOM、控制字符与二进制内容             | 有效文本字节数/内容一致；非法编码或二进制安全拒绝；超限读取无截断成功及无内存无界累计                                            | 待验证 |
| D-04 | `lstat` 与 `READ` 之间更换文件/符号链接、读取中增长/缩小、实际权限变化                      | 真实读入字节受限；不把符号链接预检查当作原子 `nofollow` 打开保证。需明确当前路径竞争下的可接受行为，不能宣称文件内容快照一致     | 待验证 |
| D-05 | 在 `OPENDIR`、`READDIR`、`CLOSE`、`READ` 不同阶段注入取消、deadline、晚到回调、SSH 传输断开 | 取消前未派发和派发后 unknown 明确区分；不可信 lease 退役，关闭失败保留因果；后续资源不误用旧句柄                                 | 待验证 |
| D-06 | 目录列表、`stat/lstat`、文本读取在远端长时间不响应、失去网络或取消后重入                    | 整项业务期限不因多个步骤重置；无长期保持“可用”的不可信资源；有失败证据并能继续建立独立的新文件连接                               | 待验证 |

**已知语义限制**：当前并未实现服务端原子 `nofollow` 文件打开、目录分页一致性或并发修改时文件内容快照，验证这些竞态时须记录观察结果与产品可接受范围；不能把缺少保证说成“已通过防竞态”。
