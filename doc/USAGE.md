# 使用

本文是实际软件需求与用户可见行为的唯一规范入口，记录当前功能、操作流程、限制与错误恢复，不记录实现计划或完成报告。Bug 修复和需求变更在同一提交更新对应行为；实现职责见 [Frontend 架构](architecture/FRONTEND.md)、[Backend 架构](architecture/BACKEND.md)，开发前必读 [AGENTS.md](AGENTS.md)。

## 连接、代理与通知管理

### 审计日志

审计列表沿用时间、操作类型、详情三列布局，一行一条，行之间有分隔边界；时间、操作类型及表头居中。详情以代码块样式直接显示原始记录，不重复展示中文字段说明，不需要点击展开或打开弹窗；长记录完整换行，不设置详情内部滚动，窄屏上下排列。审计页与首页快速连接共用搜索工具栏，关键词输入防抖自动筛选，操作类型选择后自动加载，无需额外筛选按钮。取消分页，每批加载 40 条，向下滚动接近底部时加载更早记录，也可点击加载更多；失败保留已有记录并支持重试。列表使用动态高度虚拟滚动，仅渲染可见区域及缓冲记录。首页快速连接搜索栏随内容滚动，不吸顶；桌面和手机均在滚动后提供右下角回顶部按钮，底色与背景轻微区分。

公共标准弹窗使用不透明的主题底色，亮色模式下不会透出深色遮罩而变灰；页面背景仍由遮罩压暗以突出弹窗，弹窗正文及操作区域保持自身主题对比度。

Agent 每个模型可在「能力配置」中独立选择调用协议，保存后测试及正式调用使用该模型的协议，不改变其他模型。未独立设置的模型沿用提供商默认协议；外层卡片及测试弹窗顶部不再显示共享协议选择。手机端能力配置中的协议选择占满可用宽度，模型操作保持紧凑两列。响应格式校验失败返回 `PROVIDER_RESPONSE_INVALID`，DNS/TLS/网络故障、超时及上游 HTTP 状态分别返回对应错误码，未知原因返回 `PROVIDER_REQUEST_FAILED`，不假称资源不可用；不自动降级协议，不伪造缺失的响应 ID。

| 错误码                                                                                | 含义                                           |
| ------------------------------------------------------------------------------------- | ---------------------------------------------- |
| `PROVIDER_RESPONSE_INVALID` / `PROVIDER_RESPONSE_EMPTY` / `PROVIDER_STREAM_TRUNCATED` | 格式不兼容、空响应或流未完成                   |
| `PROVIDER_HTTP_<status>`                                                              | 上游实际 HTTP 错误状态，401、403、429 分别保留 |
| `PROVIDER_DNS_FAILED` / `PROVIDER_TLS_FAILED` / `PROVIDER_NETWORK_FAILED`             | DNS、证书或网络连接故障                        |
| `PROVIDER_NETWORK_TIMEOUT` / `PROVIDER_TEST_TIMEOUT` / `PROVIDER_DISCOVERY_TIMEOUT`   | 网络、测试或发现模型超时                       |
| `PROVIDER_REQUEST_FAILED`                                                             | 尚未分类的请求失败                             |
| `PROVIDER_UNAVAILABLE`                                                                | 提供商不存在或已停用                           |

首页手机端快速连接的搜索与筛选栏随列表上滑，不固定遮挡连接卡片；快速连接和 SSH 资源列表滚动后提供悬浮回顶箭头，各自返回对应列表顶部。SSH 资源按主机去重后逐个请求，主机之间间隔 200ms，逐项更新结果，不在进入首页或刷新时同时发起所有主机请求；页面销毁时取消未完成请求与后续队列。

顶部导航以圆角悬浮条展示，本体高 48px，上下各留 6px，使用主题顶部栏底色并随页面宽度延伸；所有页面的导航外侧留白与终端外框一致，桌面两侧各 8px，手机不额外留白。导航保留正常布局空间，不覆盖页面内容。宽屏菜单居中；窄屏通过页面选择菜单访问全部入口。终端仍可隐藏顶部导航。

页面统一预留浏览器滚动条空间，避免长短页面切换时导航横向跳动；设置页和终端页使用同一导航高度计算可用空间。

连接列表以独立卡片显示名称、类型、地址和操作，支持搜索、筛选、排序与批量操作；宽屏卡片右侧操作区纵向居中，窄屏自动换行。代理与通知列表共用管理卡片布局，类型标签位于名称右侧，空间不足时换行；桌面编辑和删除按钮在右侧居中，手机放在卡片底部并等宽排列，长名称和地址不会撑宽页面。

手机连接批量工具栏分两排：第一排为全选、取消选择和反选，第二排为编辑和删除，按钮等宽排列；桌面保留横向工具栏。

代理与通知管理桌面操作按钮至少高 44px、宽 96px；代理卡片不展示更新时间。非编辑区域不显示文本插入光标，导航、按钮和功能标签不选择文字；输入框、可编辑区域和正文复制保留正常行为。

挂起会话移除、连接/代理/通知/文件删除、接管和放弃修改等公共确认提示统一使用项目表单材质、状态图标、清晰的标题与正文以及独立操作区；危险操作以危险色按钮区分。桌面按钮至少高 44px，手机等宽排列，长提示可换行并纵向滚动。上传同名文件冲突提示使用相同视觉规范，保留跳过、覆盖和应用到全部的选择。

仪表盘连接目录加载完成后即可结束目录加载提示，不等待审计和挂起目录请求；返回仪表盘保留已有内容并后台刷新。

仪表盘 SSH 资源按主机独立加载、独立展示结果或错误；单个慢主机不阻塞其他主机的资源卡片，探测采用有界并发。

手机顶部页面切换使用可左右滑动的圆角页面标签，点击标签切换页面，当前页面高亮并在切换后自动滚动到可见位置；导航滑动不切换页面，也不带动下方终端滚动。连接管理的四个操作按钮通常一排四列，卡片可用宽度过窄时改为两排两列。

横向导航不额外叠加背景色，与顶栏共用背景。桌面窄窗口下，顶部菜单和设置功能标签同样支持鼠标按住左右拖动，并保留触摸与触控板原生滚动；拖动结束不误触选项，普通点击仍切换页面或功能。

连接、代理及通知配置使用统一的不透明表单背景，分组以标题和留白区分。连接测试的延迟说明在表单底部完整换行显示。

通用确认提示与上传冲突使用同一确认面板组件；管理卡片及批量操作区共用公共操作组。统一样式由公共组件集中维护，登录控件使用 44px 触摸密度，编辑器编码和换行下拉使用紧凑密度，业务操作与保存行为保持不变。

登录控件保持 44px 高度，字号与圆角沿用公共触摸密度。Agent「已配模型与连通测试」的模型名称完整展示，长名称换行；四个操作统一位于模型信息下方，桌面四列、手机两列，按钮使用至少 32px 的紧凑高度，测试结果可换行。模型连通测试执行实际模型请求；失败时显示本地化错误类别与服务端错误码，网站可访问或模型列表可获取不代表模型调用一定成功。

设置中的工作区偏好使用扁平分组与分隔线，不再层层嵌套面板和字段卡片；手机单列、宽屏双列，保留各分组独立保存、未保存提示和高级设置折叠。

设置 → Agent 顶部的开启／关闭控件位于最右侧；窄容器中运行状态、活跃应用数量和开关三个区域等宽排列，长文本可换行，不互相覆盖或超出容器。

Agent 配置中的 SSH、模型与环境弹层统一使用公共 Popover 定位，首次打开完成测量后显示，尺寸限制在可用边界内；窗口缩放或内容变化时同步重新定位，不保留独立的首次定位补丁。

SSH 选择使用固定标题与全选栏、独立纵向滚动列表。全选复选框以空框、减号和勾分别表示未选、部分选中、全部选中，旁边显示已选数量；列表支持鼠标滚轮、触控板及手机上下滑动，底部主机可滚动到达并点选，滑动不切换选择。运行冻结时不可修改。

## SSH 会话

服务器状态按面板宽高自适应：普通布局展示 CPU、内存、Swap、磁盘及网络实时信息，容量区分已用数值、总量和单位；窄栏允许数据换行，矮面板使用紧凑布局，宽矮面板横排。网络上传／下载使用明确文字和颜色区分，不使用滚动作为查看数据的前提。历史模式顶部仅保留指标切换项，主要空间用于历史曲线，支持时间范围切换和关闭。极小面板会缩小字号，完整展示存在物理尺寸与可读性限制。

文件管理器顶部图标两端对齐，最小间距为 4px；窄面板命令栏输入在上、按钮在下。分栏结构或面板顺序变化时重新同步分栏实例，普通拖动只改变相邻面板尺寸。

上传使用有界 SFTP 批量写入，保留分块顺序、声明大小、临时文件与完成校验；下载使用有界并行预读并按文件顺序输出，支持 HTTP Range。性能取决于浏览器、后端、SSH 链路与远端磁盘，不承诺固定带宽。

终端断线重连后重新同步当前可见区域的行列数；浏览器从后台恢复、页面恢复或字体加载完成时重新测量。隐藏／后台状态下保留最近有效尺寸，不将临时缩小的布局写入远端 PTY；切回终端后按实际区域调整，无需手动拖动窗口恢复。

### Agent 长对话上下文

Agent 在模型请求前优先加载当前输入、Goal 和活动 Plan 明确指向的 Workspace 项目目录规则，再补已探索目录；支持显式 `/workspace/work/...` 与相对项目路径。归一化后拒绝仓库工作目录之外的候选，最多加载 8 个目标目录。没有全仓扫描，也不保证预先发现模型临时自行选址的所有嵌套规则；项目规则不改变工具权限。

工具输出因模型窗口预算被截断时，模型可用 `tool_result_read` 和返回的 Tool Call 引用／hash 分页读取当前 runtime 已捕获的完整结果，无需重新执行原工具。分页使用 Unicode 字符 offset／nextOffset，每页受工具输出预算限制；拒绝跨用户、应用、Run 或子任务访问及 hash 不匹配。读取成功不改变原操作的成功／失败或验证状态，无法恢复执行端 capture limit 之外的字节。

Run 审批保留 `ask` 与 `full_access` 两档：前者逐次等待用户批准需要审批的操作，后者仅在既有 capability、目标范围和 deny 边界内自动批准。没有按路径／命令模式记忆批准的第三档策略；自动批准不授予额外资源权限。

受治理的 Child worker 同样遵循 Run 审批模式：`ask` 提出 mutation 后暂停等待用户决定，批准后重新校验目标并执行；拒绝、过期或更新输入使旧审批失效，Child 收到未执行的结果后继续。取消和重启仍走现有终止／恢复链路，不重放未知副作用；`full_access` 自动批准不扩大 delegation grants。

`plan` 模式同样约束子任务：仅提供 read／control 工具，拒绝 Child mutation；已有写权限、governed profile 或 full_access 均不能解除禁写边界。禁写检查在执行及审批消费之前生效，不以最终完成检测代替。

Child 的 MCP 能力同样按需发现：使用 `tool_search` 查找、`tool_invoke` 携带版本绑定引用调用，不默认把全部 MCP schema 发给模型。引用过期或对应能力不在 delegation grants 内时拒绝，发现引用不授予执行权限；Child mutation 仍仅允许受治理的 Workspace 目标。

Child 模型调用遇到瞬态连接、429 或 502／503／504 等错误时，在既有重试次数、任务 deadline 与 Run／delegation 预算内退避重试。失败请求的 usage 同样计入预算；部分回复和未完成工具建议不会提交为结果，不消费 pending mailbox。不切换冻结模型，不重放工具副作用；非瞬态错误、取消、预算耗尽和重启遗留中断不自动重试。

Backend 正常停机时，Child 模型执行中断不作为用户取消，也不发布部分回复的最终交接。旧执行由既有生命周期恢复流程关闭；重启仅按安全 checkpoint 恢复契约创建新执行，不承诺原 Child 原地续跑或恢复旧模型 stream。

`/interrupt` 仅中断正在 streaming 的 Root 模型；仅 Child streaming 时返回不可中断冲突。普通输入、Goal 与 pending queue 更新不自动取消 Child；对子任务纠正使用 mailbox，终止使用既有取消链路。

工具在检查后版本或当前实现被替换时，实际执行会拒绝旧检查结果；授权等待期间变化也不能执行旧实现。模型须重新发现／检查当前工具，不自动用旧参数调用新版本。

Child 完成交接会从自身完整已保存工具历史收集成功且已验证的证据，不只保留最近 32 批。交接最多包含 64 个引用与 16 个工具摘要；引用超过上限或历史读取失败时明确失败，不静默丢引用后宣称成功。原始工具结果和 Artifact 仍由既有持久 owner 保存，摘要上限不删除原数据。

子 Agent 不继承主 Agent 的私有对话或 Recall，只使用委派约束、获授权资料及自身工具／协作历史。容量充足时保留自身全部工具交互与已消费的父级纠正，不因超过 8 组工具交互自动遗忘；接近窗口时，使用冻结模型分批生成历史交接摘要并保留近期完整交互。摘要计入同一 Run 和委派预算，不作为子 Agent 回复显示，不提前消费新 mailbox；失败、截断或取消不覆盖旧摘要，不静默丢历史继续。无法安全压缩或委派预算不足会明确结束子任务，父级可决定重新委派；不保证真实模型摘要无损保留所有细节。

长对话接近上下文容量时，Agent 使用当前冻结模型生成结构化历史交接摘要，保留近期完整对话和工具交互。历史按顺序分批送入模型，后续批次合并已有摘要，不按英文关键词、首尾四条或单条 220 字筛选；摘要关注目标、约束、纠正、决策、工作状态、阻碍、下一步和证据。原始对话保留，授权、审批、Goal、Plan 和待处理输入仍由原控制面管理，摘要不授予权限。

摘要调用计入 Run 的模型步数、执行时间和 token usage；预算不足时等待增额。摘要不会作为普通助手回复显示，也不提前消费待处理输入。空结果、截断、超预算、不缩小、取消或来源变化不会覆盖有效摘要；无法安全压缩时明确结束或中断当前执行，不静默丢弃旧历史继续。单条历史记录大于摘要请求窗口时会明确失败。语义摘要仍可能遗漏细节，不承诺模型对任意任务无损归纳；重要约束也可保留在当前 Goal 中。

### Agent 项目目录规则

- Workspace 自动读取项目根及已探索目录路径上的 `AGENTS.md` / `AGENT.md`，文件名大小写不限。多个规则文件同时存在时按目录由浅到深、同目录按文件名排序加载；不会将 `CLAUDE.md` 或其他文件当作别名。
- SSH 使用 `project_directory_bind(connectionId, directory)` 绑定绝对项目目录，`project_directory_read(connectionId)` 查看，`project_directory_clear(connectionId)` 清除。绑定按用户、应用、对话、连接隔离并持久保存，Root 和获得对应文件读取授权的子 Agent 共享；跨轮生效，删除对话或停用应用清除。绑定不是终端 cwd，不改连接配置、不授予权限，也不自动执行命令。
- SSH 规则只从绑定根到已探索子目录加载，不读取远端 home 或项目外目录；连接配置变更后旧绑定不自动换目标。Workspace 按最近 `.git` 目录或 worktree 文件确定项目根，没有仓库标记则使用 Workspace 工作根。
- 规则是发送给模型的项目指导，只适用于对应目标及目录子树，不覆盖用户要求、安全策略或工具审批；冲突应向用户提出。模型收到规则不等于每条要求已被强制验证，重要限制仍须由权限和审批控制。
- 每次模型请求重新读取，修改或删除规则在后续请求生效。投影最多 16 个文件、每文件正文 16 KiB、正文合计 64 KiB；超过 64 KiB 的源文件不加载，模型上下文预算可进一步截断。不可用时不伪造规则，不写入长期 Memory。

### Agent SSH 长会话与后台任务

- Agent 工具按功能模块命名：`shell_*`、`ssh_*`、`file_*`、`machine_*`、`workspace_*`、`collaboration_*`、`memory_*`、`browser_*`、`tool_*`、`skill_*`、`plan_*`、`user_*`、`artifact_*`、`acp_*`、`mcp_*`。只接受当前名称，不提供旧工具名别名。
- `ssh_session_open(connectionId, idleTimeoutSeconds?)` 打开对话级连接，返回 `sessionId`。默认空闲 1800 秒，0 表示不因空闲关闭；最大可配置值 86400 秒。每用户最多 32 条，服务最多 128 条连接。任务结束或停止不会自动关闭会话；对话删除、应用停用、权限撤销、连接配置变化和服务退出会清理。
- `ssh_session_list(connectionId, sessionId?)` 查看当前对话内指定目标的连接状态与活动操作数；`ssh_session_close(connectionId, sessionId, force?)` 关闭并移除连接。普通关闭拒绝活动会话；显式 force 按破坏性操作治理，可能中断全部活动命令，不保证远端进程已终止。
- `shell_execute` 与全部 `file_read/list/search/write/patch/move/delete` 接受仅限 SSH 的可选 `sessionId`。省略时仍每次临时建连后关闭；指定时检查、执行和验证使用已有连接。失效时不自动重连、降级或重放。
- 同一用户、应用和对话的 Root/Subagent 可以显式共享会话，但仍须有当前目标授权；跨用户、应用、对话禁止访问。命令各自使用独立 exec channel，文件使用独立句柄，不向其他任务插入输入，不继承前一命令的工作目录或环境变量；远端共享文件和服务仍可能相互影响。
- SSH `shell_execute(mode="background", sessionId=...)` 返回 `jobId`，任务继续运行；使用 `shell_job_control(target="ssh", id=连接ID, jobId, action="status/wait/cancel")` 查看有界输出、等待或取消。后台任务 timeoutSeconds 默认 3600 秒、最多 86400 秒，独立于提交工具期限；前台仍最多 300 秒且受工具预算约束。后台任务运行时不进行空闲回收，每用户最多 32 个活动任务。
- SSH 任务状态与终态结果持久保存，原始命令和凭据不写入任务记录。连接丢失、强制关闭或 Backend 重启后的未确认任务标记 unknown，不重放；单任务取消不关闭共享连接。取消只有收到远端执行结束证据才有确定结果，不把本地 channel 关闭当作远端进程已终止。
- `shell_job_control` 同时管理 Workspace Job；`workspace_code_query` 提供 TS/JS symbols、definition、references、diagnostics，其他语言使用文件搜索／读取。SSH Job 不使用 Runner，普通 SSH 功能不依赖 Runner 可用性。

全局 Agent 呼出悬浮按钮使用 44px 圆形、实心主色底与高对比图标，图标为对话框内的终端提示符；保留拖动位置、点击打开和任务数量徽标。拖到左右边缘附近松手后吸附贴边并半隐藏；鼠标悬停或键盘聚焦时完整展开，手机点击露出的半圆直接打开 Agent，也可拖回页面内取消贴边。贴边侧和纵向位置随布局保存，右键重置位置。

手机终端小键盘左侧六个固定键在普通页和功能键页保持相同顺序：第一排 Esc、Fn、Shift，第二排 Tab、Ctrl、Alt。Shift 使用文字显示，是修饰键而非方向键；右侧 ↑ 是终端方向上键，Fn 切换 F1–F12 页面。

### 挂起与恢复

SSH 标签页支持挂起会话。点击挂起只设置保留标记，不关闭当前标签或终端；关闭标签或浏览器断开时，后端接管并继续保持原 SSH/PTY。标记后的会话会显示在挂起面板中，具有会话访问权限的其他设备可以确认接管正在使用的会话，或恢复无人使用的会话；不需要持有原设备的普通 Workspace 恢复凭据。接管后原设备失去会话控制权，不允许两个设备同时写入同一 PTY。

挂起标记和提交成功必须返回真实的挂起会话 ID；注册结果缺失或 owner 已失效时返回失败，不发送没有 ID 的成功响应。

挂起会话保留最近最多 100MiB 的原始终端历史，恢复优先提供当前终端状态和有限尾部，更早历史按需分页。持续输出达到历史上限后仍可恢复原 SSH/PTY，不应因每次输出重写整个历史文件而耗尽恢复租约。

适合编译、下载、长时间运行任务等不希望因浏览器断线而中断的场景。

### 自动重连

浏览器网络抖动或 Workspace WebSocket 异常断开后，系统会在约 120 秒内保留原 SSH/PTY 和正在运行的压缩、复制/移动等后台任务。恢复网络后会优先续接原会话，并补回可用的终端输出和任务结果，不会新建 SSH 登录替换原终端。

手机切换应用后回到前台、页面从浏览器缓存恢复或网络恢复时，会对当前已连接的 Workspace 做有界存活检查；正常链路不重连，失效链路通过原会话凭据续接。标记为待挂起的断联标签会核对服务端目录并自动恢复无人使用的会话，不自动接管其他设备正在使用的会话，也不关闭用户后来打开的启动页。浏览器回收页面后不保留原标签内存，可通过启动页挂起目录恢复；未标记会话超过普通续接窗口时无法保证原 PTY 保留。

从其他管理页面返回终端同样检查旧链路存活；多个前台或网络恢复事件并发触发时复用正在执行的恢复，续接成功后不再次对已绑定链路发起续接。

恢复只接受当前标签持有的会话凭据，并校验登录用户、Workspace 和连接身份；打开同一连接的新标签不能接管旧 Workspace。主动关闭标签会立即释放会话，远端终端已退出或宽限期结束后则不能继续恢复。

连接处于断开状态时，可以通过以下方式提前触发恢复：

- 在命令输入框按回车。
- 在终端中按回车。
- 再次点击连接列表中的同一个 SSH 连接。

## 终端

- 点击 SSH 连接后立即进入终端；连接中显示状态并禁用输入，连接成功后自动启用。
- 自定义 HTML 终端背景会在终端可见时显示，切换回标签页后自动恢复。
- `Ctrl + Shift + C`：复制。
- `Ctrl + Shift + V`：粘贴。
- 终端输入单次最多 256 KiB；SSH 浏览器发送缓冲最多 1 MiB。未连接、输入过大或缓冲已满时显示错误，不自动重发被拒绝的输入，避免重复执行命令。文件二进制读取累计最多 128 MiB，终端历史单次二进制响应最多 1 MiB，超限取消该请求并释放累计缓冲。
- 弱网恢复期间，终端会先重放已保留输出；恢复暂停与网络背压分别解除后才恢复实时流，避免其中一个暂停原因提前放开输出。
- SSH 网页终端在浏览器解析输出过慢时自动暂停发送，解析后继续，不丢弃中间输出；历史浏览期间暂存的实时输出在恢复实时画面后继续消费。
- 清除或复制后取消的终端本地选区不会在拖动文件管理器分隔线、改变终端宽度后重新出现。
- 服务器状态卡片使用悬浮提示展示指标详情，支持鼠标悬停与键盘聚焦；采样更新时在原提示内更新文字，不通过反复修改浏览器原生 title 重启提示。
- 普通桌面终端有选区时右键复制，无选区时右键粘贴；接管鼠标的终端程序使用自己的右键功能，不弹出浏览器系统菜单。仍可按住 `Shift` 拖选，用 `Ctrl + Shift + C/V` 复制粘贴，启用右键复制粘贴时也可用 `Shift + 右键`；本地选区存在时不向应用上报无按键的鼠标移动。
- 应用自身的复制快捷键可通过标准 OSC 52 协议将完整文本复制到本机，无需网页识别应用或快捷键。仅接受当前聚焦、可输入终端在用户按键或松开鼠标后 2 秒内发出的有效 UTF-8 文本（Base64 最多 1 MiB），不允许远端读取本机剪贴板；浏览器须允许剪贴板写入。应用自身粘贴快捷键使用浏览器/终端标准粘贴通道。Shift 本地选区只覆盖终端缓冲区，不拼接全屏应用翻页重绘的内容。
- 已验证的默认操作：OpenCode v2.0.18 用 `Ctrl + X` 后松开，再按 `Y` 复制消息（完整文本，不限当前屏幕）；Codex CLI 0.159.2 用 `Ctrl + O` 复制最后一条回复。两者均可用 `Ctrl + Shift + V` 粘贴文字。应用版本或自定义键位可能改变复制操作，应以应用内快捷键说明为准；这些操作仅是使用示例，网页不持有应用键位映射。
- 移动端支持双指缩放终端字体。
- 手机终端的连接会话栏隐藏横向和纵向滚动条，仍支持左右滑动查看会话，不产生纵向滚动。
- 终端在没有会话时，以及点击标签栏 `＋` 后，桌面和手机均显示统一的“连接与会话”启动页，可恢复挂起会话或搜索并发起连接。手机使用整页纵向滚动，上下排列的快速连接与恢复会话区域之间显示细分隔线；桌面双栏布局不变。已有会话保持运行，可点击原标签或“返回当前终端”返回。标签栏的挂起入口可在已有会话时直接打开挂起列表。
  宽屏启动页将操作区置于左侧，发起连接在左栏、挂起会话在右栏，页面右侧为非交互装饰；小屏隐藏装饰并纵向排列列表。
  点击 SSH 连接后立即进入终端连接等待界面；连接过程中可再次点击 `＋` 打开启动页，后台连接完成不会自动关闭新打开的启动页。
  手机启动页优先展示发起连接，挂起会话在下方；桌面仍为左侧连接、右侧挂起。连接标签分组展开后，子项类型图标与分组箭头左侧对齐。

  连接标签分组标题使用中性浅底色和细边界区分，不使用紫色选中背景；适用的批量连接、分组管理和批量删除工具常显，无需悬停。

浏览器剪贴板能力通常要求 HTTPS 或 localhost 安全上下文。

## 镜像发布

Workspace 是独立的项目与运行环境管理模块。支持版本 JSON 保留 Node、Python、Go 的可选版本和架构，用户从列表选择；安装使用 mise 获取指定版本并检查实际版本，不限制该版本具体的上游构建来源，也不要求维护安装树摘要或选择指纹。已安装环境重复使用，不因上游重建自动替换；使用中的版本不能卸载，明确卸载后重新安装可获取该版本当前的上游构建。

镜像发布保留生产依赖 high 级安全审计；release channel 仅发布当前 main 提交，并要求该提交的完整 E2E（基础检查、全部 Playwright 分片和 Docker smoke）成功。Actions 运行标题显示 channel、架构和发布目标，主镜像与 Runner 任务使用固定名称，准备失败时仍可辨认任务。发布和部署方式见 [部署与更新](./DEPLOYMENT.md)。

## 当前限制与注意事项

- 双文件管理器布局属于实验性能力，复杂场景可能存在边界行为。
- 同一布局中添加多个文本编辑器目前并非完整支持场景。
- 请自行备份部署目录中的 `data`；项目本身不替代外部备份方案。
- 完整备份恢复会清理当前挂起会话，但保留挂起服务的维护任务与所有权撤销订阅，恢复成功或失败后仍可创建新的挂起会话。
- Runtime setup／pack uninstall 只有 Runner 明确成功才提交配置；失败、运行中或未知结果不提前启用／移除版本，同一确认重复提交复用原命令。远端成功后配置版本冲突会报错并保留有效确认，需检查实际安装状态后重新预览，不覆盖新配置，也不自动回滚远端。
- Runtime 管理命令明确失败后可用相同参数重新提交，新操作保留独立命令记录；相同参数仍在执行或结果未知时复用原命令，未知结果先 reconciliation，不盲目重放。
- Workspace 数量限制按用户所有 App 的未 deleted／failed 实例统计，并发创建在同一数据库提交边界检查名额；已有创建的幂等重试不占用新名额。每次请求使用其读取的有效配置上限。
- Workspace 创建在幂等记录有效期内用相同 key／参数重试时返回原 Workspace，不因已有实例而冲突，也不重新 provision；同 key 不同参数仍拒绝，未知结果仍需 reconciliation。
- 删除背景先清除设置引用，再清理旧图片；设置写入失败不会先删图片。旧文件清理失败记录服务端诊断，不改变已成功清除背景的结果。
- Passkey 认证在提交时重检签名计数器；并发认证导致旧快照失效时，该请求不登录，请重新认证。持续使用零计数器的同步 Passkey 不受递增限制。
- 文件编辑保存先完整写入同目录临时文件，再使用远端支持的 replace 操作替换目标；写入失败不提前截断原文件，编码和原文件 mode 保持。断链导致替换结果不明时仍需检查，不保证远端不支持原子 rename 时的原子性。
- TOTP seed、CAPTCHA 配置和通知配置使用部署密钥加密存储，升级启动时迁移旧明文；请保管原加密密钥，错误密钥不会被当作明文使用。Full Backup 中的配置受备份 envelope 保护，导入时用目标密钥重新加密；TOTP／用户身份不属于 Full Backup。迁移不擦除旧数据库页、WAL 或外部旧备份。
- 命令／路径历史的并发写入按值合并；旧数据中同值的重复条目在该值再次写入时合并，保留最小 ID 并刷新时间。旧备份仍可导入。
- Server Transfer 支持不同路径的同名源条目，每个子任务读取其原始条目；目标路径同名时仍遵循既有覆盖策略，不自动重命名。
- 初始管理员设置仅在空用户库允许一次；并发提交也只有一次成功，其他请求返回设置已完成。
- 文件传输失败／取消会等待并行写入结束和句柄关闭后清理临时文件。归档仅在有远端退出状态时确认已结束；断链、关闭或清理结果不明时报告 `OPERATION_OUTCOME_UNKNOWN` 并隔离相关资源，不自动重试，也不声称取消已回滚部分文件。
- 快捷命令新增／编辑与标签关联一起提交；标签无效或写入失败时整体回滚，不保留部分更新的命令。
- IP 封禁自然到期后，下一次失败开启新的计数周期，达到登录失败阈值会再次封禁；未到期的封禁不因额外失败请求自动延长。
- 并发登录失败按数据库原子事务逐次累计，同一封禁周期仅进入封禁的请求触发封禁通知。
- 审计记录写入失败不改变已经提交的业务操作结果；服务端记录安全错误诊断。审计不是阻断事务，也不保证存储故障期间每条记录都能落库。
- Proxy 或 SSH Key 仍被连接引用时不能删除；先修改相关连接解除引用或删除连接，不会自动切换路由／认证方式。
- 被其他连接的跳板链引用的连接不能删除或改为非 SSH 类型；先解除相关跳板引用。保存跳板链时会在提交事务中重检引用，不自动切换路由。
- 连接导入按记录独立提交；同一记录的内联 Proxy、Connection 和标签全部成功才计入成功，失败不留下新建孤立 Proxy。不同记录可以部分成功，既有 Legacy 导入格式保持支持。
- Full Backup 导出验证 ready Artifact 的大小／hash，以及已安装 Plugin 的包标记、入口和文件清单；文件缺失或内容不符会拒绝导出，避免成功生成带缺失引用的备份。并发文件持续变化也会报错，不保证导出冻结所有文件 writer。
- 导入备份前停止 Agent 调度和维护任务，关闭旧 Plugin／模型集成运行句柄；恢复完成后从恢复的数据重新初始化。无法安全停止时不执行恢复；文件／数据库恢复失败并回滚后也重新初始化存活数据，不复用旧执行队列或批准。
- 生产访问建议启用 HTTPS。
