## 1. Webhook JSON 模板安全插值

参考：[0bfb737：JSON 模板插值与对象解析](https://github.com/Heavrnl/nexus-terminal/commit/0bfb737653933268e6624f4f21c37f8a29e1c75a)。已查看 formatter 的字符串内/字符串外插值区分，以及 sender 的 JSON 处理。

本地 [`notification-formatter.service.ts`](../packages/backend/src/modules/notifications/notification-formatter.service.ts) 通过普通字符串 replace 处理自定义 bodyTemplate；[`network-notification-channel.adapter.ts`](../packages/backend/src/infrastructure/notifications/network-notification-channel.adapter.ts) 默认使用 JSON Content-Type。默认 body 已由 JSON.stringify 构造，重点是用户自定义模板。例如 `{"message":"{details}"}` 中的 details 包含引号、换行或反斜杠时，直接替换可能破坏 JSON。

可做：明确文本/JSON 模板语义，字符串位置按 JSON 字符串转义，完整值位置保留 number/boolean/object 的表示；完成插值后解析并验证，再交给 Adapter 发送。未知占位符和非法模板应在保存/测试边界报明确错误，不能悄悄发送无效 JSON 或写入日志中的原始正文。文本渠道不能共用 JSON 转义策略。

完成判据：引号、反斜杠、换行、中文、对象和数值均保持预期表示；不能让 payload 任意覆盖系统模板字段或把秘密带入投递诊断。上游的 any、打印正文和非法 JSON 后降级原文发送不直接采用。

## 2. 文件目录切换保留列表与行级反馈

参考：[a053cae：保留目录列表](https://github.com/Heavrnl/nexus-terminal/commit/a053cae6105b5cebaa7676564672eba26a4f6ae9)，[26d7962：移动端加载与滚动位置](https://github.com/Heavrnl/nexus-terminal/commit/26d7962)。已查看前者的行级 spinner 与列表保留 diff。

本地 [`useFilesystemBrowser.ts`](../packages/frontend/src/features/filesystem/composables/useFilesystemBrowser.ts) 已经保留旧 entries，并通过 loadToken 防止过期结果覆盖；但 [`FileManager.vue`](../packages/frontend/src/features/filesystem/components/FileManager.vue) 在 loading/searching 时通过 v-if 改为整区 spinner，旧列表及滚动容器会卸载。因此主要缺口在展示，不能再建第二套列表缓存。

可做：首次加载才显示整区等待；后续导航保留原列表，在目标行/工具栏显示加载反馈，成功后一次替换目录与条目。显示已提交路径和待进入路径的区别，加载期间禁止对旧条目执行误指向新目录的写操作。搜索结果与目录导航有不同的状态语义，不机械共用一条 loading 分支。

完成判据：失败保留可识别的旧目录；连续快速跳转不被旧响应覆盖；滚动位置按导航/刷新语义处理；虚拟列表、键盘焦点、选择和拖放都不因隐藏等待状态失效。

可做：限定手柄拖动、半屏/全屏吸附、向下关闭；pointercancel/capture 丢失及时收尾，关闭动画结束后再清理手势样式；键盘打开时依 visualViewport 调整高度，适配 safe area/reduced-motion。

## 10. 可选日志语义高亮

参考：[73bad5b：语义分组与冲突仲裁](https://github.com/Heavrnl/nexus-terminal/commit/73bad5bfc99de28f9b48ab89dc42ea182ea907c5)，[ef5b54f：多 matcher 共享样式](https://github.com/Heavrnl/nexus-terminal/commit/ef5b54f3dfd45886ef1e7eb01bb17b4bfc48f2fd)。已查看匹配器编译、优先级和向输出插入 ANSI 样式的实现。

产品思路可参考：日志等级、URL、时间、IP、关键词/正则分组，共享样式，规则重叠有确定优先级。我们的 Terminal 目前没有同类配置入口，需单独评估呈现机制；上游直接向字符流加入 ANSI 的方式不应直接移植。

设计前提：原始终端字节、offset、快照与回放事实不受高亮修改；不能破坏 ANSI 状态、UTF-8 分片、备用屏幕及交互应用。优先研究受支持的展示层装饰或独立日志视图，做不到时不强行在原始流上替换。正则应有长度/数量/处理预算，复杂规则不能阻塞主线程；规则变更需有明确缓存失效语义。

## 11. Docker 原生构建与依赖缓存

参考：[e2f086e：BUILDPLATFORM 构建阶段](https://github.com/Heavrnl/nexus-terminal/commit/e2f086efd81705440e8d785de450787efb9e434f)，[61f57b4：生产依赖层复用](https://github.com/Heavrnl/nexus-terminal/commit/61f57b40d417a4f3ba395498aad0f570ce4261a0)。已查看 Dockerfile 实际变更。

本地根 [Dockerfile](../Dockerfile) 已将依赖安装放在源码 COPY 之前，并使用 pnpm cache mount；不重复登记为缺失能力。可研究把纯前端/TypeScript 编译运行在 BUILDPLATFORM，减少多架构时 QEMU 开销，并将 runtime COPY 的变化顺序调整为更稳定的依赖先、频繁变化的 dist 后。

不能直接对整个 backend-builder 加 BUILDPLATFORM：本地 pnpm deploy 会把 node_modules 一起交给 runtime，含 native/平台相关依赖时必须为 TARGETPLATFORM 安装/构建；musl、Node ABI 和 CPU 架构要一致，cache mount 也要避免混用平台产物。保留当前 alpine:latest、nodejs-current 和 nginx 的选择，不采用上游 Node 20 固定版本。

完成判据：先记录 amd64/arm64 冷缓存与热缓存耗时，再验证两个真实目标镜像的运行行为；不要只看到构建变快就宣布成功。这一项在获得构建验证授权后实施，本次未构建镜像。

## 12. 工作区漫游与显式接管

参考：[22952d5：工作区同步与接管](https://github.com/Heavrnl/nexus-terminal/commit/22952d5bfafbfa5777295fc5939b7a4411d9e89e)。已查看 UI snapshot 字段、activeClientId、旧客户端会话移交和前端同步 Store。提交标题称“租约”，本次没有据此认定它已具备完整的持久 lease/fencing/故障恢复能力。

可参考的体验：标签顺序、布局、目录/滚动位置、编辑标签在设备间恢复，优先激活当前目标，并在重复操作中提供收敛的恢复反馈。

必须先分三类 owner：Preferences 管布局与展示快照；Remote 管真实 Session、接管与恢复；文件草稿若同步，需要单独的权限、大小、版本、保留和删除规则。快照版本及更新时间不能替代真实资源身份，浏览器提供的 terminalBuffer 也不能覆盖服务端权威终端历史。上游按 connectionId 或 sessionId 匹配快照不能直接采用，同一连接可以有多个独立会话。

本地现行普通续接要求原会话恢复凭据，挂起会话则由有权限的设备显式确认接管。不能为了“无缝”而自动取得同账号全部活动会话。设计需要明确服务端授权、原 owner 撤销、原子 ownership/version、晚到请求 fencing、过期与重启语义；取回 UI 快照不自动授予 SSH 控制权。

初期建议仅漫游不敏感 UI 配置，之后才评估草稿和真实会话接管；大批恢复需有并发上限及单项失败隔离，不采用无界全量并发，也不全局隐藏所有成功/告警通知。Shared 分开定义 UI 快照与资源协议，Platform 不下沉 Workspace/Agent 业务身份。

## 已具备或不建议照搬的变化

- **后台 SFTP 预热**：本地 workspaceRuntimeSession 在连接成功后已经异步 ensureLoaded/refresh，不以文件准备阻塞终端。可以测量实际慢点，不另建第二套预加载。
- **状态图表减少重建**：本地 StatusCharts 已禁用动画，也没有上游通过递增 chart key 强制重建的结构。参考 [45e9835](https://github.com/Heavrnl/nexus-terminal/commit/45e98356ba2a204a0bf0a0c364f565222c0ed83e) 的原则，不把已实现行为再列待办。
- **移动端传输进度入口**：本地 WorkspacePage 已聚合多个会话及跨服务器任务；参考 [92d8ae2](https://github.com/Heavrnl/nexus-terminal/commit/92d8ae21ea6e) 时先检查可达性，不重复搬状态 owner。
- **桌面/手机全量复制组件**：参考 [1055a8d](https://github.com/Heavrnl/nexus-terminal/commit/1055a8d661a3) 的体验改进，但只在交互确实不同处拆 presentation，controller、协议与数据不复制。
- **依赖自动更新**：本地已有 update-dependencies workflow。上游 [1bc64ee](https://github.com/Heavrnl/nexus-terminal/commit/1bc64eef2168c73370c4e6f879e83f8ee3ba832b) 的 auto-merge 条件包含安全警报、分组和 minor/patch 的 OR 分支，不能视为仅安全补丁或保证排除所有 major；不照搬自动批准逻辑，采用时仍须绑定必要的真实检查和仓库合并策略。
- **大范围源码格式/目录同步、版本号、删除文档、纯样式修饰**：不作为本次迁移候选。上游的大型同步 Store、any/非空断言、自动接管和日志正文输出不符合我们的边界，不整体复制。

上述完成判据供以后实施时细化，不代表本次已进行验证。选择一项施工时，先复查当前实现是否已变化，再维护正式需求和 owner 文档，按真实风险安排允许的检查及行为验证。
