# 特殊设计与系统级约束

[← 返回软件需求总览](../README.md)

本文件只记录跨模块、长期有效的特殊设计和非功能约束。具体业务细节仍以各模块 SRS 以及对应 FR/GREQ 为准。

| 编号           | 主题                        | 规范性设计 / 约束                                                                                                                                                                                                                | 主要来源                                                                                                                                                      |
| -------------- | --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SD-ARCH-001    | 单向架构与 Owner            | 前端保持 `foundation → shared/client → feature → runtime → app` 的单向组合；跨 Feature 依赖必须经过公开 surface。Backend 保持 `interfaces → modules → platform` 及 Infrastructure/Bootstrap 约束，完整依赖图必须无环。           | [Frontend Architecture](../../architecture/FRONTEND.md) · [Engineering Constraints](../../ENGINEERING_CONSTRAINTS.md)                                         |
| SD-ARCH-002    | Clean Contract              | Frontend/Backend HTTP 与 WebSocket Interface 使用 clean camelCase 合同；历史 `legacy-api`、NXTM/NXUP、旧 `/sftp`/旧 Workspace framing 不得重新成为生产接口。SQLite/persistence 内部可保留 snake_case。                           | [Engineering Constraints](../../ENGINEERING_CONSTRAINTS.md) · [GREQ](../traceability/git-requirements.md)                                                     |
| SD-RUNTIME-001 | Workspace 生命周期          | Workspace runtime 必须独立拥有连接绑定、重连、suspend handoff 与 capability adapter；页面切换不得销毁正常 live session，登出/认证丢失必须回收 runtime。                                                                          | [Workspace requirements](../requirements/workspace.md)                                                                                                        |
| SD-RUNTIME-002 | Future Agent 边界           | Future Agent 必须拥有独立 runtime/protocol/session；不得复用 Workspace raw socket、SSH client、shell、SFTP handle、cwd/process state 或 upload socket。未存在明确 Agent 公共协议前不构造 Agent 产品行为。                        | [Frontend Architecture](../../architecture/FRONTEND.md) · [Engineering Constraints](../../ENGINEERING_CONSTRAINTS.md)                                         |
| SD-XFER-001    | 上传完整性                  | 上传保持精确字节、相对路径、目录、空文件；依赖目录树在文件流之前准备。完成只在 Backend flush/size 验证/原子替换后成立；异常/取消必须清理 `.part`。                                                                               | [Transfers SRS](../requirements/transfers.md) · [GREQ-XFER-001](../traceability/git-requirements.md#greq-xfer-001)                                            |
| SD-XFER-002    | 有界并发与公平调度          | Upload 数据与 Terminal/FileManager 控制流隔离；浏览器/服务端缓冲有界。调度器允许容量匹配的后续小任务绕过阻塞队首，但绕过次数有上限以防止队首任务饥饿。                                                                           | [Transfers SRS](../requirements/transfers.md) · [GREQ-XFER-001](../traceability/git-requirements.md#greq-xfer-001)                                            |
| SD-XFER-003    | 重连 / 取消语义             | Workspace 断线时未完成上传转为 paused，重连后重新准备目录并从 byte 0 重启未完成文件；单独 upload socket 失败是明确文件失败，不做无限自动重试。非 upload copy/move/archive 取消只有收到 Backend correlated cancelled 才进入终态。 | [GREQ-XFER-002](../traceability/git-requirements.md#greq-xfer-002) · [GREQ-XFER-003](../traceability/git-requirements.md#greq-xfer-003)                       |
| SD-SEC-001     | Secret preservation         | 编辑 password/private key/passphrase/CAPTCHA/notification secret 时不得把已存 secret 回填浏览器；空白输入按各领域规则表示“保留”，显式 clear 必须是独立意图。                                                                     | [Identity/Security](../requirements/identity-security.md) · [Connections](../requirements/connections.md) · [Notifications](../requirements/notifications.md) |
| SD-PREV-001    | 远程内容安全与大小限制      | Preview owner 在渲染前决定 eligibility/inline limit；Markdown 2 MiB、Spreadsheet 10 MiB、Image/PDF/DOCX 20 MiB；远程 SVG 不作为图片预览；Markdown 必须清理可加载资源/交互内容。                                                  | [File Preview](../requirements/file-preview.md) · [GREQ-PREVIEW-001](../traceability/git-requirements.md#greq-preview-001)                                    |
| SD-STATE-001   | 状态 Owner 与 remount       | Terminal snapshot、Filesystem cwd、Editor/Preview tabs、Transfer tasks、Status/Docker session controller 等必须归各自 capability/session owner，不能依赖 pane/component 是否当前挂载。                                           | [Frontend Architecture](../../architecture/FRONTEND.md)                                                                                                       |
| SD-PERSIST-001 | Latest-value persistence    | 高频 UI 变更（布局尺寸、字体、窗口大小等）允许 debounce，但 teardown 前必须 flush 最新值，避免最后一次用户修改丢失。                                                                                                             | [Functional Requirements](../traceability/functional-requirements.md#fr-arch-004)                                                                             |
| SD-TEST-001    | E2E-only product validation | 自动化 product behavior 测试只保留 `test/e2e`。E2E 只能通过真实 UI/HTTP/WS/ingress 断言，不增加 `data-testid`/test seam；完整浏览器证据以 GitHub Actions pinned 环境为准。                                                       | [Engineering Constraints](../../ENGINEERING_CONSTRAINTS.md)                                                                                                   |
| SD-PERF-001    | 重型功能按需加载            | 不删除行为以缩包；Markdown/PDF/Spreadsheet/DOCX、Monaco/CodeMirror、StatusCharts 等可按需拆分。Terminal/xterm 作为 Workspace 主路径保持即时可用。                                                                                | [Frontend Architecture](../../architecture/FRONTEND.md) · [Refactor handoff](../../FRONTEND_REFACTOR_CURRENT_HANDOFF.md)                                      |
