| <a id="srs-xfer-005"></a>**SRS-XFER-005**   | Shared Progress Display                    | Long-running upload, copy/move, archive and server-to-server transfer work is registered in a shared progress model independent of the File Manager component that initiated it.                                                                                                                                                                                                                                                 | • closing/unmounting a File Manager does not orphan an in-flight task;<br>• hiding a source is presentation-only and must not pause/cancel the underlying operation;<br>• the floating progress window can hide and later be restored;<br>• upload/transfer progress shows aggregate progress and transfer-rate information in addition to per-file/task rows;<br>• aggregate speed is derived from monotonic byte-count deltas over time; transport protocols do not need a second authoritative `speed` state;<br>• hidden tasks are shown in a shared Progress Display, grouped by source/operation where appropriate, with per-task progress and source-level Cancel All/Restore;<br>• completed/failed/cancelled/partial statuses remain distinguishable; unknown totals may use indeterminate progress instead of fake percentages;<br>• the progress window is draggable/resizable, persists a sane position/size where supported and clamps inside the viewport;<br>• mobile progress UI stays inside the viewport;<br>• cancelling from the shared Progress Display returns control immediately enough that File Manager refresh/browsing is not blocked on slow remote cleanup. | [**FR-XFER-005**](../traceability/functional-requirements.md#fr-xfer-005) · [GREQ-XFER-005](../traceability/git-requirements.md#greq-xfer-005) · [GREQ-XFER-003](../traceability/git-requirements.md#greq-xfer-003) | 已实现 / 基线保留 |
