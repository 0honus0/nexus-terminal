| <a id="srs-ws-005"></a>**SRS-WS-005** | Suspended-session lifecycle                           | A live SSH session can be marked for suspend. When its browser socket disconnects/reloads, the backend keeps the shell/session alive so it can later be resumed. Resuming a long-running suspended session restores a bounded newest tail first so the terminal becomes usable without waiting for the complete retained log; older retained output is loaded only when the user navigates upward toward the beginning of the currently loaded terminal history. Active suspended sessions are surfaced from both Workspace and the authenticated Dashboard so users can discover and reopen the suspended-session manager without first reconstructing the original terminal tab.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | • marking/unmarking is only presented as successful after the backend confirms the operation;<br>• while a live Workspace remains marked, terminal output produced after the initial snapshot is appended to the retained suspend log in order;<br>• normal reconnect must not replace a marked/suspended shell with a fresh SSH login; if automatic recovery cannot find the hanging session while the local tab is still marked, the stale tab is closed instead of silently starting a fresh SSH shell;<br>• resuming reattaches to the same remote execution context, replays only a bounded newest retained tail before Backend commit/response, and must not make resume latency proportional to the entire retained log size;<br>• the live terminal output listener is attached only after that retained-tail stream has drained and before the paused shell is resumed, so newly arriving PTY output cannot interleave ahead of or inside the restored tail;<br>• after resume, the terminal initially remains at the newest/bottom output; earlier retained pages stay Backend-owned and are requested only when upward scrolling/navigation reaches the loaded-history boundary;<br>• prepending an older page preserves the user’s current visible terminal anchor instead of jumping the viewport, while live terminal output arriving during the prepend/rebuild is retained and rendered afterward in order;<br>• the lazy-history cursor is released after history is exhausted; the retained log itself stays alive while the resumed Workspace is still marked for suspend and is deleted only when no suspend/history owner remains;<br>• successful resume does not implicitly cancel suspend: the replacement Workspace remains marked, so closing it suspends the same shell again unless the user explicitly unmarks it;<br>• if a resume transaction fails or its WebSocket closes mid-handoff, Backend rollback returns ownership to the original suspended record and Frontend closes only the temporary recovery runtime;<br>• any terminal snapshot included in suspend handoff is size-bounded and preferentially keeps recent terminal output rather than growing without limit;<br>• suspended entries can be searched by visible identifying information and distinguish marked/hanging/backend-disconnected state;<br>• users can rename, resume, terminate, export retained logs and remove suspended entries as supported by the backend;<br>• exporting a retained log downloads backend bytes using the backend-provided filename when available and reports export failure without mutating the suspended entry;<br>• background suspended-session polling starts promptly, backs off on HTTP 429/temporary failures up to a bounded interval, recovers toward a normal interval after success, and suppresses repeated identical error toasts; a deliberate/manual load may still surface an error;<br>• after a marked live Workspace is closed and its Backend suspend handoff is still materializing, the Frontend performs a short bounded burst of silent catalog refreshes so the new suspended entry appears promptly instead of waiting for the next ordinary poll interval;<br>• Dashboard and Workspace consume the same suspended-session catalog; Dashboard shows an active-session count/entry point when such sessions exist, and that entry opens the Workspace suspended-session surface rather than creating a separate management implementation;<br>• when resume replaces an already-visible stale/marked Workspace slot, the replacement runtime takes that tab position atomically so mobile/foreground recovery does not temporarily show a duplicate second tab; failure restores the original visible slot;<br>• constrained suspended-session cards reflow by their actual container size: wide cards keep labeled actions to the right; medium-narrow cards collapse those actions to fixed-size icons but keep the compact icon group beside the identity/status content while space remains; only the minimum-width band moves that compact group below the content, where it stays content-width and centered instead of stretching across the whole card. Long names/metadata wrap before colliding with actions, and short-height panes compact search/card/action spacing without changing the underlying session list or layout percentages;<br>• automatic termination events are reflected in the UI. | [**FR-WS-005**](../traceability/functional-requirements.md#fr-ws-005) · [GREQ-SSH-001](../traceability/git-requirements.md#greq-ssh-001) · [GREQ-SSH-002](../traceability/git-requirements.md#greq-ssh-002) · [GREQ-SSH-003](../traceability/git-requirements.md#greq-ssh-003) | 已实现 / 基线保留 |
| <a id="srs-ws-006"></a>**SRS-WS-006** | Workspace layout and popup presentation configuration | Desktop Workspace supports a recursive pane/container layout, left/right sidebars and persisted sizes. Layout can be locked to prevent accidental edits. File Manager and File Editor can also expose popup-oriented presentations **in addition to** the embedded/sidebar presentation; enabling a popup must not replace an existing layout pane with a placeholder or create a second business-state owner.<br><br>Supported layout editing includes pane/container creation/removal, horizontal/vertical container direction, drag-and-drop child ordering/placement, assigning available panes to the main tree or sidebars, and restoring the shipped default layout/sidebar configuration. Runtime splitters remain the user-facing size editor; the configurator does not expose persisted internal percentage floats as raw numeric fields. The layout configurator preview must render each container’s direct children on the axis represented by that container direction: `horizontal` lays direct children out side-by-side and `vertical` stacks them top-to-bottom. Changing a container direction updates that preview without changing the child nodes’ identity, type or assigned pane content. On desktop with no active session, the initial Connection list remains horizontally resizable from its divider and restores the persisted Connection pane width after reload. | • the configurator preview and runtime layout use the same horizontal/vertical axis semantics; direction is not a label-only property;<br>• the configurator preserves the legacy draggable-pane interaction: available panes, recursive main-layout children and left/right sidebars use visible drag handles/drop regions, while raw persisted size percentages stay internal;<br>• the no-active-session Connection pane uses the same bounded `sidebarPaneWidths.connections` presentation preference as the active Workspace Connection sidebar; dragging its divider persists the final width rather than remaining a fixed startup-only size;<br>• layout initialization prefers backend-saved layout/sidebar data; if unavailable it may fall back to valid browser-local cache and finally to the shipped default;<br>• missing node ids can be regenerated as presentation identity; invalid/duplicate/unknown sidebar pane names are rejected rather than rendering an incoherent layout;<br>• one logical pane should not be accidentally duplicated where the final configuration treats it as a unique placement; the configurator tracks which panes are already used;<br>• Save persists both main layout and sidebars before closing the configurator; Reset restores both sides of the configuration, not just the visible main tree;<br>• when popup File Manager is enabled, Command Bar exposes an action that opens the File Manager for the owning active Workspace session while any configured embedded/sidebar File Manager remains a real File Manager surface; on desktop that popup exposes a visible bottom-right resize affordance, persists its last browser-local width/height, restores and clamps that size inside the current viewport, and keeps responsive minimums (360×320 when the viewport permits); mobile does not inherit the desktop resize handle/persisted desktop size;<br>• when popup File Editor is enabled, Command Bar exposes an editor action and file-open intents reuse the same feature-owned editor tabs/controller; embedded editor presentation remains real rather than a popup placeholder, while Preview is mounted only in its active presentation to avoid duplicate document/search DOM;<br>• mobile keeps File Manager/Editor reachable from the command bar even when desktop popup visibility settings would otherwise hide those buttons;<br>• switching between embedded/sidebar/popup presentation must not duplicate Filesystem/File Editor business state;<br>• normal modal/document overlays must stack above the compact Workspace rail; the expanded sidebar and resize handle keep their own higher interaction layers only while active.<br>• Workspace can hide/show the application top navigation from the tab bar; this visibility is persisted independently from the pane layout and changes the Workspace usable height without destroying sessions.<br>• on desktop, the Workspace shell preserves the legacy four-side frame geometry: the tab bar has an 8px top margin and 8px left/right margins; the content frame directly below shares those 8px left/right margins, has no extra vertical gap below the tab bar, and keeps an 8px bottom margin. The active-session content frame has visible 1px left/right/bottom borders, no duplicate top border beneath the tab bar, and bottom corner rounding; the no-session placeholder uses the same frame geometry and border treatment. Top-corner rounding on the tab bar is allowed. Mobile does not inherit these desktop outer margins or frame borders.<br>• pane percentages remain user/layout-owned and are not rewritten merely because a directory or suspended-session list is short; File Manager and Suspended Sessions switch to a compact internal presentation when their actual pane height is constrained, while existing splitter resize/maximize interaction remains the layout owner.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | [**FR-WS-006**](../traceability/functional-requirements.md#fr-ws-006) · [GREQ-WORK-003](../traceability/git-requirements.md#greq-work-003)                                                                                                                                     | 已实现 / 基线保留 |
