# 架构重构入口

开发从 [AGENTS](AGENTS.md) 开始；本文仅维护迁移范围与去向，不复制人工规则、编码规范和详细模块设计。长期设计分别由 [Backend](architecture/BACKEND.md)、[Frontend](architecture/FRONTEND.md)、[Shared](architecture/SHARED.md) 按 [模块模板](architecture/MODULE_TEMPLATE.md) 维护。

## 当前迁移范围

保留 `backend` 与 `backend-next` 双包用于实际功能核对，正式前后端入口尚未切换。新后端独立装配 Access、Targets、Remote 和有限 Agent 状态；共享技术能力归 Platform/Adapter，应用类型与授权/生命周期归模块。已有源码不等于产品完整迁移或真实行为通过。

新 Agent 已有状态 HTTP，但没有 Shared Agent 和真实新前端消费者；这是明确的实施缺口，列入 [当前任务](后端重构下一阶段实施方案.md)，不能通过空目录或搬出后端对象关闭。

## 迁移顺序

先收口现有功能的共享协议和真实消费者，再按任务设计 Remote 写入/传输及 Agent 执行治理等切片。每个切片先确认旧产品正常行为、真实 owner 和安全/持久不变量，再设计新边界，不机械复刻旧文件结构。已发布数据与接口是否兼容在该切片明确说明，不擅自假定。

每版同步 [USAGE](USAGE.md#每版产品行为维护)，阶段门禁见 [实施方案](后端重构下一阶段实施方案.md#任务组织与阶段门禁)，真实行为缺口见 [待实机验证](testing/后端重构待实机验证.md)。正式流量与数据切换另行完整设计、验证并按授权交付。
