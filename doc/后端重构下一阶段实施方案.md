# 后端重构下一阶段实施方案

本文维护本批尚未收口的架构/编码任务、验证门禁、真实行为验收缺口与后续批次。N0–N3 主要源码已经施工，但审核发现下列未完成项，不能只剩验证任务。长期规则唯一入口为 [Backend 架构与开发约束](architecture/BACKEND.md)，尤其是人工类型规则 4–7；行为需求见 [USAGE](USAGE.md)，Agent 治理见 [AGENTS](AGENTS.md)，验证入口与证据见 [E2E](testing/E2E.md)。开发前完整读取这些入口。

## 当前进度与范围

按完整后端替换（含 Agent、Remote 全部功能、正式前端迁移及交付）估算，此前粗估约 **30%，合理区间 25%–35%**；本批增加有限只读文件能力，未重新做全产品工作量估算。这是按功能工作量的粗估，不按文件数、提交数或测试数量计算，也不是验收通过率。SQLite/SSH/HTTP/WS 和模块边界骨架约 80%；Targets 基础管理已具备，Access 仍缺完整因素/策略，Remote 已有 PTY 与独立只读文件切片，Agent 只有有限持久状态。主要剩余工作在 Agent 执行链、Remote 产品能力、系统配套及正式切换。

## 当前交付边界与未完成收口任务

N0–N3 主体源码已具备，已完成施工细节不重复列出；长期实现事实统一见 [Backend 架构](architecture/BACKEND.md) 与 [Frontend 架构](architecture/FRONTEND.md)，独立开发页行为见 [USAGE](USAGE.md)。本批已提交 Worker 完整 envelope 解码与 fail-closed、Access/Remote Model 类型与内部 owner、Targets 重复规则归一、PTY WebSocket 流职责独立、expectedFingerprint 单快照核验、真正有界的 SFTP 列目录及元数据/字节范围解码、独立 Remote Files Machine/SFTP/用户会话资源、Shared file HTTP 契约和三语言开发消费者。Agent 执行、写入/编辑、下载上传/完整传输、挂起/恢复和正式入口切换均未施工，不应把这批源码视为产品迁移完成。

本批架构收口已落实到源码：PTY 通过当前状态读取保留 await 后终态保护；Files 应用资源封装技术句柄并统一具名清理失败；应用类型与 Shared 基础取值归一；Agent、Host Key 和技术迁移/事务 SQL 均归对应 Adapter。只完成源码及静态收口，真实行为专项仍开放，不把此前问题继续列为未修复。

## 每阶段任务的静态门禁

所有阶段均执行下列要求；任务编写时必须将适用命令和通过判据写进该阶段，不能把检查失败统一推迟到最后。阶段中可以暂时不通过，结束阶段前必须解决；有明确环境阻断时保留该阶段未完成及真实证据，不清除任务、不把依赖阶段标为完成。

1. 审核依赖方向、Model/存储/公开类型转换、SQL owner、异步资源与关闭责任；边界问题修 owner，不新增空层、断言或兼容入口。
2. `pnpm --filter @nexus-terminal/backend-next check` 必须退出 0；根 check 不能替代新包检查。Shared 修改另执行 Shared check/build，双端契约修改同步 Frontend 类型检查和构建。
3. 修改范围 ESLint、函数/export 间隔和 Prettier 必须通过；阶段收口执行 `pnpm run check`、`pnpm run format:all:check`、`git diff --check`，失败必须修复后复查，不放宽规则换绿。
4. 适用包 build 必须通过；迁移、安装、Worker 路径或 Shared exports 改动必须构建相关实际消费者，不能只检查类型。
5. 记录所检提交/工作区、命令、范围和退出结果。源码、静态检查及行为验收分别判断；测试是否执行按用户授权，不新增单元测试，未执行的故障/浏览器专项保留待验证。

| 当前阶段               | 需要检查的实际 owner                                             | 必须通过的静态检查与构建                                                                                                              |
| ---------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| N0 基础边界            | Worker、Access/Remote 内部类型、Targets 共用规则、PTY Stream     | Backend-next check/build；本阶段 ESLint/Prettier；根 check/format 与 diff 检查。                                                      |
| N1 可信目标解析        | Targets 单快照、expectedFingerprint、公开请求投影                | Backend-next check/build；Targets 范围 ESLint/Prettier；根 check/format 与 diff 检查。                                                |
| N2 SFTP 与 Files       | 技术有界操作、应用资源封装、晚到 resolve/reject 清理、准入与关闭 | Backend-next check/build；Shared check/build；本阶段 ESLint/Prettier；根 check/format 与 diff 检查。                                  |
| N3 Shared 与前端消费者 | 文件 values/model/http/codec、Frontend Remote-next 与开发视图    | Shared check/build；Backend-next check/build；Frontend `vue-tsc --noEmit`/build；双端 ESLint/Prettier；根 check/format 与 diff 检查。 |
| N4 整批静态与行为验收  | 本批全部消费者和安装/运行入口                                    | 上述适用命令全部通过后，按授权执行真实专项并记录行为证据；静态通过不能关闭未执行的专项。                                              |

本轮已执行的静态结果和待执行真实 SSH2/SFTP 故障注入、Worker/Targets 竞争、文件资源关闭、HTTP/WS 及浏览器专项见 [后端重构待实机验证](testing/后端重构待实机验证.md)。最终 CI 及真实行为证据仍由 [E2E](testing/E2E.md) 维护。本轮未新增或运行测试，未切正式入口。

**正式交付前置条件**：先完成该清单中适用的静态门禁与真实行为专项，再依据对应提交 SHA 核对 canonical Actions 和 Docker smoke；不得将已有静态审核或旧包 PASS 当作新包行为验收。此处不再重复维护具体待验证事项，也不把 Agent 执行、文件写入、完整传输和正式入口切换误列为本批已实现功能。
