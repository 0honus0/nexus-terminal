# 后端重构下一阶段实施方案

## 当前范围及验收边界

本批施工位置为 `packages/backend-next`，正式产品仍由 `packages/backend` 服务。按照[架构重构](架构重构.md)，新后端将业务数据、模块出口、通用机器能力和实例生命周期分开。

当前源码已经覆盖 SQLite Worker 的错误分类/事务失败与关闭、Targets 安全错误出口和统一跳板图限制，并提供通用 SSH 技术实现与 Remote 最小 Shell 会话装配。上述具体实现及调用方向维护在[Backend 架构](architecture/BACKEND.md)和[架构重构](架构重构.md)，不再在本文件复制已实施任务清单。

这一批**不新增或运行测试**。静态类型、格式及构建通过只证明源代码与依赖可编译，**尚不证明**网络/SSH/Proxy/SFTP 的真实结果、SQLite Worker 崩溃窗口、Remote 生命周期和产品 E2E。当前没有 Access 授权、HTTP/WS 路由或前端切换，不开放未认证管理能力；也不把技术连接成功当作远端执行成功。

## 待完成的真实行为验证

在允许运行集成验证后，按照故障风险而不是简单 happy-path 覆盖开展以下工作。测试放在仓库根目录 `tests/`，不得添加单元测试或源码文本扫描门禁。

1. **SQLite 故障窗口**：确认真实 `node:sqlite` 数值 `errcode` 及扩展码的 constraint、外键与 busy/locked 分类；Worker 异常退出后已接纳和排队操作被明确拒绝；事务回调、COMMIT 失败、ROLLBACK 失败分别有可识别结果，未知提交不重放；事务回调内嵌套默认入口或关闭不会自我等待。两次 `close()` 共享整个 drain/Worker 终止/路径释放 Promise，启动失败清理保留全部错误证据。
2. **Targets 错误出口及图**：输入、SQLite 外键/唯一键、密钥/代理引用、可信解析和 `importMany` 失败只对外暴露安全错误码；正常 `updated/not_found/version_conflict` 状态保持原语义。检查主目标深度 0、最多 16 条边、最多 256 个展开节点，修改被引用子链不能使上游已有目标成为非法配置。所有失败写入完整回滚。
3. **SSH 技术能力**：以可控的真实 SSH Server/Proxy 验证密码与密钥认证、Host Key 验证、直连、HTTP CONNECT、SOCKS5、有序多级跳板以及每个跳板自身 Proxy/Jump 路由。总体 connect deadline/AbortSignal 不在每跳重置；故障窗口包括前跳 ready 后、后跳尚未完成时的 error/close，以及建连监听向运行期监听交接；失败/取消及时关闭半建连资源，重复关闭不泄露 Socket、Client、channel 或订阅。Host Key 策略由调用方提供，配置指纹不代替公钥信任。
4. **Shell、Command、ACP 与 SFTP**：PTY 输入/输出/resize、pause/resume、drain 与背压；命令 stdout/stderr/退出码/信号，非零退出与超时/断连未知结果；已取消输入不得派发命令，持续命令及原始无 PTY 双向通道打开后的取消须关闭 channel。SFTP stat/lstat、目录枚举、读写流、rename/remove、mkdir/rmdir，覆盖请求默认期限、独立取消/期限及 Lease 关闭时仍有待完成请求或流的窗口；核实 `not_started/unknown` 区分与关闭等待。取消远程副作用的未知结果不能作为确定失败自动重试。
5. **Remote 会话与停机**：从 SQLite Targets 凭据出发，经 Remote Model 解析目标、逐字段转换 MachineEndpoint 并打开 Shell；Service 通过独立应用资源契约管理按 ID 订阅、写入/背压、resize 和关闭。并发开会话与停机竞争时，迟到的成功结果必须释放；活动表已移除但底层尚未关闭时，重复关闭仍等待同一次清理并取得相同失败结果；先 quiesce/取消并等待 Remote 的 pending/live 资源，再关闭 SQLite。没有 Host Key 策略时明确拒绝 SSH 建连。

本批网络能力尚无真实 SSH 服务器集成验证，不能宣布满足正式流量切换条件。发现协议或资源所有权问题时，应先修复对应 Platform Adapter 或 Remote owner，再进行真实验证；不要用延长 timeout 或假返回绕过故障。

## 后续批次，当前不施工

- **Access 与 HTTP/前端切换**：首先建立真正的认证/授权，再引入 Targets HTTP/WebSocket，校验 `unknown` 输入，按消费者将共享取值/DTO 迁至 `packages/shared`。旧 wire 的 `route:null` 与新内部 `direct` 在 API 边界显式转换；同时迁移 Frontend API、Store、Protocol 消费者，不能只迁新 Backend 或暴露无认证路由。
- **Agent 的首个持久状态切片**：Run、审批、事件及幂等记录在一个 SQLite 事务内读取最新状态、决策与条件更新；提交成功后才触发调度/通知。状态决策 owner 属于 Agent，Platform 不定义 Agent 业务类型或 Slot。恢复、授权、Unknown outcome 的语义需要独立设计与验证。
- **Remote 扩展**：挂起/恢复、文件编辑/浏览、跨服务器 Transfer 的独立任务生命周期、远端执行与 Docker、RDP/VNC 会话和票据；不能把 Transfer 变成普通 Workspace Session 的附属类。
- **其他独立模块**：Preferences、Notifications、Audit、System 与备份恢复按各自业务 owner 施工；System 负责跨 Agent、Remote 与 SQLite 的停机/恢复编排。

只有真实认证授权、SSH/RDP/VNC、Agent、文件/传输、通知审计、备份恢复和部署路径达到当前产品要求后，才能统一切换正式后端、删除旧 Backend 与 Protocol。内部 SSH 链接的存在不表示完整产品已迁移。
