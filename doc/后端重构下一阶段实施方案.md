## 每批共同遵守的编码与架构规范

完整规范以[全局编码约定](架构重构.md#全局编码约定)和[AGENTS.md](AGENTS.md)为准。下列事项在每批开发和人工代码审核中逐项检查，不能仅靠格式检查判定：

1. **封装与组织**：按数据和生命周期 owner 划分大模块，功能在模块内细分。入口表达清楚步骤；完整校验、转换、事务和清理流程提取具名函数。复杂表达式先命名局部值，简单回调不机械拆分。单文件 helper 不导出，不新增无消费者的一行包装、兼容别名或杂项 utils。
2. **命名**：类型/类 PascalCase，变量/方法 camelCase，文件小写连字符；读取 get/list，转换 toX，校验 validateX，解析 resolveX，生命周期 open/quiesce/close。避免无语义缩写和含义不明的位置布尔参数，复杂选项使用具名对象。
3. **类型与转换**：公共方法有明确返回类型；用例、复用记录和复杂结果使用所属模块的具名类型，状态结果使用可辨识联合。Service 用应用类型，Model 转换存储契约和技术契约，SQLite Adapter 解码行并实现 SQL；Platform 不引入业务对象。所有模块对象出入均逐字段白名单转换，即使字段一致也不能直接返回内部对象或展开内部记录。管理出口与含明文的可信出口分开。
4. **Shared**：先盘点两端真实消费者。双端同义同表示契约统一迁入 Shared，基础取值单独 values.ts；业务 model、API、events 分文件，精确子路径导出。不同表示显式映射；内部存储、密文、权限上下文和前端 UI 状态不得进入 Shared。不能通过 as/any/非空断言代替边界验证。
5. **控制流与错误**：控制语句用花括号，优先提前返回；三元不承载复杂流程。catch 必须有清理、映射或恢复目的；技术包装保留 cause，多项失败 AggregateError，公开错误只暴露安全码。不能把 timeout/cancel 解释成副作用未发生，也不能自动重放 unknown。
6. **异步与资源**：每个 Promise 有等待/拒绝处理 owner；关闭 Promise 先保存再清理，重复关闭等待同一结果。事务只做原子状态操作，不等待 SSH/HTTP 等外部 I/O。Socket、channel、stream、timer、listener 的创建与释放成对，晚到成功也释放；deadline 不在每步重置，旧异步结果用身份/version/generation 防止过期覆盖。
7. **注释与格式**：注释解释约束及原因，TODO 写明缺少的能力、owner、补齐批次和未开放路径。Tab、单引号、分号、120 列；函数/方法及所有独立 export 声明前后保留一行空行，注释贴近声明，连续 import 不强制分隔。由现有 ESLint/Prettier 执行，不加 prettier-ignore 或人工对齐。
8. **交付**：修改所有实际消费者、文档和命令；删掉失效导出与已解决待办。每个独立事项本地提交，不自动推送。不新增源码文本扫描门禁或单元测试，不以假返回、默认密钥、默认信任或空事务占位。

## A 批修正项（代码已调整，真实行为待验收）

本节是 A 批代码审查收口记录，不代表授权进行真实 HTTP/SQLite 故障测试；修正后的静态结果不能替代运行验收。以下六项不应被写成未解决的假 TODO，也不应因通过 TypeScript 而删除其行为验证要求：

1. Access HTTP 只对业务调用应用安全错误映射；通用传输的 JSON 格式、Content-Type 与 body 上限仍由 Platform 返回 400/415/413。Access 路由拒绝自己的未知 query，Platform 不封禁其他业务的分页和 cursor。
2. Account 存储命令归 `accounts/storage`，Model 明确构造字段，SQLite Adapter 不再依赖 `accounts/model` 的应用命令。
3. 登录失败的封禁阈值与期限归 Access Service/策略持有；仅明确启用时用于公网，内网 loopback、私有及链路本地地址永远跳过。SQLite 只持有原子计数、检查和更新，不默认对所有来源强制封禁。独立部署入口尚无完整持久 IP 管理设置、白/黑名单和验证码产品界面，归后续 Access 网络策略批次。
4. HTTP 会跟踪所有已接纳的处理 Promise；停止接纳并关闭连接后，仍等待已进入密码验证或数据库写入的操作收敛，再关闭 Remote/SQLite。重复关闭等待同一 Promise。
5. ESLint 空行规则以声明行与注释真实位置判定；上一声明同行尾注释不作为下一声明的前置注释，独立 `export const` 仍检查空行。
6. 文档区分服务端 session **有效期**与持久记录**物理删除**：当前在读取到过期/密码版本失效的会话时删除，该会话在期限到达时立即不能认证，但没有为从未再次访问的过期行安装扫除任务。该物理清理属于后续 Access 会话保留策略，不能称为已实施的 30 天物理回收。

完成判据保留为行为待验收：分别核实 HTTP 400/413/415、内网地址绕过已启用封禁、并发失败计数、查询参数归业务路由、断线中的 scrypt 操作与停机数据库生命周期，以及 ESLint 尾部注释的 AST 判定；当前不新增或运行测试。

## C：Remote 受认证 SSH 终端入口（代码切片已施工，待行为验收）

- Remote 本模块的 `RemoteSessionOwner` 把新 PTY 的 ID 绑定到初始管理员的 **Access token 摘要和用户 ID**；打开、查询、关闭、WS upgrade、每条输入及流输出均验证 Session 当前有效性，另有周期性校验。一次 PTY 只能绑定一个 WS，未接入订阅 30 秒后自动关闭；连接断开直接关闭对应 PTY，不实现挂起、接管或恢复。HTTP 中断时传递 AbortSignal 并释放迟到的资源。
- `modules/remote/interfaces/http` 实际提供 `POST /api/v1/remote/sessions`、`GET/DELETE /api/v1/remote/sessions/:id` 及 `/api/v1/remote/stream?sessionId`；拒绝无权限用户，失败只返回安全码，不直接输出解析明文、SSH 连接对象或内部异常。Platform HTTP 拥有通用 WS Upgrade、固定 Origin/可信代理校验、单帧大小限制、发送缓冲上限及升级中业务 Promise 跟踪；Remote 拥有 frame 解码、PTY 背压、输入大小、已消费字节确认与释放。接收队列总量及正常退出的输出 drain 尚有下文审核缺口。
- `targets/host-keys` 独立拥有 SSH 服务端密钥信任，v2 迁移建立真实 `target_host_keys` SQLite 表，管理 HTTP 允许查看、显式确认和删除 SHA256 公钥指纹。操作员**必须另行通过独立可信渠道核对**指纹后才能确认，未信任的目标和每级跳板都会拒绝 SSH 握手；`Targets` 配置指纹与真实 SSH 公钥指纹互不混用。确认不自动扫描远端，不会默认接受未知密钥；删除/更新信任影响后续建连，当前活动 SSH 会话不自动终止。
- Shared 新增 `remote/model,events,api` 以及 `targets/host-keys` 精确子路径，连接端点的指纹字段明确命名 `configurationFingerprint`。Frontend `runtimes/remote-next/transport` 自己持有 WebSocket、输入/输出及消费确认；xterm 组件只使用 Transport 句柄和字节写入。现有 `/__targets-next` 开发入口现在可选新实例 SSH 连接、确认 Host Key 与打开基础 PTY，仍不复用旧 Workspace Store/Socket。开发 Vite `/__next` 需显式配置代理并支持 WS 升级；新后端的 Public Origin 必须与浏览器面向的 Origin 一致。
- 流式消息 JSON 类型解码，二进制字节用 base64 表示；每条输入最多 32 KiB，WebSocket 帧 64 KiB，Browser/WS 发送缓冲 1 MiB，SSH 输出靠 128 KiB credit window + `consumed` ack 与暂停/恢复控制。现有输出队列超限会显式关闭，但不能据此声称接收积压有界或正常退出不会丢失末尾输出。关闭编排先关 HTTP/WS 并等待已接纳业务任务，再清理 Remote 会话与底层 SSH，最后关闭 SQLite；完整等待和失败传播仍须按下文审核项收口。

**待真实验收**：第一次确认和变更 Host Key、SSH 密钥算法/公钥指纹与多级跳板、错误/撤销/跨登录令牌访问、HTTP 创建断线/WS 非法帧/多设备竞争、SSH 背压/ack/大输出、网络断连与关机 Promise 窗口。静态检查与构建通过不等于这些行为验收通过。当前不新增或运行测试。Agent 后续必须自行实现目标 grant/审批，不继承普通 Remote PTY 访问权限。

## D：Agent 首个持久状态切片（代码已施工，真实行为待验收）

- `modules/agent` 独立持有 `scope / runs` 的 Service、Model、Storage 契约与 SQLite Adapter；并非搬运旧 Agent 的所有 Provider/Runtime/审批实现。App 创建关联 Access 的真实 `userId`，Thread 创建必须验证同一用户和 App 的数据库引用；业务 HTTP 从 Access 服务端会话取得用户 ID，目前明确只允许初始管理员，不接受客户端传入 owner。
- Bootstrap 的全库签名迁移 v3 增加 `agent_apps`、`agent_threads`、`agent_runs`、`agent_run_events`、`agent_command_idempotency`。SQLite 使用真实外键/复合归属键、`run_kind='root'`、`status='pending'|'cancelled'`、`(thread_id)` 上条件唯一活动 Root 索引、`(run_id,sequence)` 唯一事件序号，以及 `(user_id,app_id,command_name,operation_key)` 幂等主键。输入原文作为冻结字段持久保存，不出现在管理返回值、事件或公开错误里。
- `RunService` 校验 App/Thread ID、内容、用户、版本和 Idempotency-Key（UUID）；命令哈希包括 schema 版本、操作名及严格顺序的字段（创建：App/Thread/输入文本；取消：App/Run/expectedVersion）。`RunService` 构造独立应用命令；`RunModel` 逐字段转换为存储命令，纯状态规则只接收应用 `status/version`。SQLite 事务参与者在 `BEGIN IMMEDIATE` 内读取最新 App/Thread、幂等键与活动 Run；创建首事件序号为 `1`，只有真正取消时才读取事件最大序号并追加 `max+1`，最后按规则原子写 Run+事件+幂等快照。相同操作键及同样请求返回初次提交的视图，并用 `replayed/originalStatus` 明示原始结果而不产生第二次副作用；复用键提交不同参数拒绝；不同键并发创建时最多一个 `pending` Root Run。不存在的 scope/run 不暴露记录，事件查询再次检查用户/App/Run。
- 取消按 `expectedVersion` 条件更新，在同一事务中追加 `run.cancelled` 并存幂等结果；`version_conflict`、`already_cancelled`、幂等 `replayed` 有独立结果，重复取消不追加事件。事件以 Run 为范围按 `after` 和 `limit<=100` 分页，单次事务内检查访问归属和读取页；事件序号单调增长。SQLite `commit_unknown` 仍向外暴露安全的不可用错误，不自动重放未知写入；调用方必须用原键自行核对或重试。
- `public.ts` 只定义窄的 App/Thread/Run/事件管理视图及可辨识结果；`registerAgent` 对输入和输出逐字段映射。新 `/api/v1/agent` 路由只提供 App/Thread 创建、Run 创建/查询/取消、事件查询，HTTP 严格校验来源、方法、参数、字段和服务端会话，不提供假的 Run 执行或完成路由。Agent 对外类型暂只有后端和 HTTP 消费者，**没有相同表示的前端消费者**，故不抢先加入 Shared，也不修改旧 Agent/Protocol 或正式运行期。
- **TODO（Agent runtime/scheduling，E1–E4）**：接入真实 Provider、grant/审批/lease、调度与恢复后，仅对已确认新提交的创建结果调度，取消只对新提交结果发布和清理；幂等重放和回滚绝不通知。当前没有调度器，Run 仅为真实持久的 `pending`，不得伪造 `running/completed` 或假结果。Root 执行按下文 E 批施工，最终生产切换另批。

**运行验收保留**：真实 SQLite 并发与第二进程争用、相同/不同 Key 和 payload 重放、Scope 隔离、Thread 活跃索引、CAS 版本竞态、取消与事件编号、一次成功一次失败的回滚、重启后的幂等结果、Worker 死亡及 COMMIT 不明窗口、真实 Access HTTP 鉴权。当前仍不新增或运行测试；静态类型/构建通过不代表已验证事务行为。

## A–D 审核收口记录（源码已修正，运行待验收）

以下“证据”记录修正**之前**的调用链；“Owner 与方案”保留原审核决策，便于之后核对实现是否满足设计。不把后续 Provider、Transfer 等尚未施工的能力登记为这六项缺陷；本次没有进行运行复现或故障测试，不把源码收口写成行为通过。

**当前源码修正**（对应下方 1–6，均待运行验收）：

1. Platform WebSocket 每条连接最多保留 64 个待处理/处理中消息、总计 256 KiB，超过即终止 Socket；入站仍按顺序处理，停机跟踪处理任务。
2. Remote 区分正常 EOF 与错误/撤销。正常 EOF 停新输入，允许同一已认证 owner 排完输出及客户端 `consumed`，再发送 `closed` 并由 Platform 有界握手关闭；EOF 确认最长等待 10 秒，握手最长 5 秒，不因活动 PTY 已移除而误判输出鉴权。
3. Remote SessionOwner 按 ID 共享释放 Promise；底层 Service 保留失败的清理结果供重复释放和实例 shutdown 收集，实例停止时 drain 已接纳任务与清理失败。
4. Targets、Remote、Agent 的模块 `register.ts` 各自安装管理路由和内部生命周期。Bootstrap 仅调用模块公开安装入口，不再直接实例化 SessionOwner 或导入业务模块内部 HTTP 工厂。
5. 新前端 PTY Transport 缓存同一个关闭 Promise，客户端已收到的数据先完成终端写入，再通知自然关闭；组件用 generation、AbortController 和资源释放函数阻止旧回调污染重连，断开/失败/卸载清理 Terminal 与 ResizeObserver。未确认的 DELETE 失败不算成功释放。
6. 对新 Remote/Agent 与开发前端采用现有 ESLint 的 `curly` 修正，复杂错误码分支改用具名函数，Agent Run 应用复用类型独立到 `run-types.ts`，Remote 与 Targets-next 错误经三语言 i18n 展示。生产旧包及其他目录不进行全仓风格重写。

### 1. P1：Platform WebSocket 接收积压没有总量限制

**证据**：`platform/http/http-server.ts` 的 `upgrade` 为每条消息向 `incoming` Promise 链追加任务，并登记到 `websocketTasks`；只有单帧 `maxPayload` 限制，没有待处理消息数/字节数上限。Remote 每条消息等待 Access/SQLite 鉴权，连续的小帧可以在处理完成前不断积压。发送缓冲上限与 SSH 输出 credit 不保护这个接收队列。

**Owner 与方案**：Platform 提供通用、有界且保持顺序的接收队列，计入正在处理和排队的消息，明确超限拒绝/关闭及停止接纳后的释放语义；不引入 Remote/Agent 类型。Remote 继续负责业务解码和授权。完成判据是慢处理期间积压有界、正常消息有序，断线/停机不遗留任务；以后 Agent WS 可复用这项技术能力。真实洪泛/慢处理验证留待授权。

### 2. P1：PTY 正常退出没有末尾输出 drain

**证据**：`remote/interfaces/http/remote-http.ts` 的 `flush` 在发送队列数据前异步等待 `owner.allowed`；`RemoteSessionService.closeActiveSession` 先从活动集合删除会话，`allowed` 又要求会话仍在集合中。随后 `onClosed` 直接发送 `closed` 并调用 `channel.close()`，Platform 当前通过 `ws.terminate()` 关闭，不等待排队输出或 WS 已接受的发送完成。最后一段数据进入队列后紧接 EOF 时，可能被身份检查或立即断开截断。

**Owner 与方案**：Remote 区分正常 EOF 的输出收尾、主动取消、鉴权失效和传输失败；正常退出停止新输入，但保留独立的输出收尾状态和身份验证，不因 PTY 从活动集合移除就误报未认证。有限期限内排空输出并完成所需消费确认，再发终态；超时/溢出明确失败。Platform 提供通用正常关闭/发送完成能力与强制终止能力，不能要求业务直接操作 `ws`。Frontend 按序等待已收到输出的渲染，再宣布正常关闭。取消、权限撤销及停机采用各自明确的终止策略，不为了 drain 继续未经授权的输出。

### 3. P2：Remote SessionOwner 的重复释放不等待同一次清理

**证据**：`sessions/service/session-owner.ts` 的 `release` 先删除 `owners` 再等待 `remote.closeSession`，第二次释放发现 owner 不存在便立即返回；底层 Service 虽保存按 ID 的关闭 Promise，该保证没有完整传到 owner 层。`close` 也只聚合本次 `release` 的失败，等待 `pending` 的结果被丢弃，先前已开始的释放失败可能不向实例关闭传播。

**Owner 与方案**：SessionOwner 按 ID 保存关闭 Promise，先发布再启动清理，重复内部释放共享完成与失败结果；关闭中的授权判断不得为了幂等而开放给其他 token。明确 HTTP 重复 DELETE 的产品结果与内部资源 drain 是不同契约。实例关闭等待全部自己拥有的任务并保留清理失败，底层 Service 的共享 Promise 保留。完成判据覆盖并发释放、超时回收与 WS 关闭交叉、清理失败和停机。

### 4. P2：Bootstrap 仍在组装模块内部 HTTP 与业务 owner

**证据**：`bootstrap/module-manifest.ts` 深层导入 `RemoteSessionOwner`，直接创建实例并组合 owner/Service 的 quiesce 和 close；同时直接调用 Targets、Remote、Agent 的内部 HTTP 工厂。Access 已经通过模块注册返回 routes，两种装配边界不一致。

**Owner 与方案**：各模块 `register.ts` 或明确的模块安装出口在模块内部装配 routes、owner 和生命周期，接收所需的 Access/Targets 窄公开能力。Remote 内部统一持有 SessionOwner 和 Service 的关闭顺序，Targets/Agent 同样返回其安装能力。Bootstrap 只创建基础运行时、连接模块公开依赖、安装通用路由并编排模块间生命周期；不能为减少 import 把业务注册槽位放进 Platform，也不能将私有 Service 补导出到 `public.ts` 代替封装。为 E 批增加调度 owner 前先收口这一边界。

### 5. P2：Frontend 终端失败/自然关闭后的展示资源未完整释放

**证据**：`RemoteNextTerminal.vue` 在连接时创建 Terminal、FitAddon 和 ResizeObserver；连接失败仅设置 issue，自然关闭回调仅清空 handle/active。再次连接会覆盖这些引用，旧 Terminal/Observer 未被 dispose/disconnect。只有主动 disconnect/卸载才清理当前引用。Transport 的 `close` 以 finished 提前返回，也没有共享正在执行的 DELETE/关闭 Promise。

**Owner 与方案**：组件为每次连接持有独立资源和 generation，重连之前、失败和卸载时清理所属资源；晚到回调不能清除新连接句柄。正常 EOF 要先完成第 2 项的输出渲染，再释放展示资源。Transport 统一发布共享关闭 Promise，重复 close 等待同一次清理，DELETE 失败不能被当作已经确认 PTY 释放。完成判据包含失败后重试、自然退出后重连、打开期间卸载和关闭并发，不改变独立开发入口与正式 Workspace 的隔离。

### 6. P2：新增切片的编码规范尚未全部落实

**证据**：Remote/Agent 和 Remote Frontend 多处无花括号控制语句，HTTP 错误到状态码有多层三元；`run-model.ts` 等实现文件同时持有多项复用应用类型。现有 ESLint 默认通过不等于这些规范已经满足。本轮仅临时使用现有 ESLint 的 `curly` 规则审查上述三个目录，报告 89 处违规，不新增门禁或测试。开发页还直接显示 transport 英文异常/错误码，不能把提供三份翻译文件等同于全部错误展示已本地化。

**Owner 与方案**：各模块按既有规范补全花括号、用具名映射/函数收敛复杂状态决策、将复用应用类型移到所属类型文件；前端由边界映射稳定错误并使用现有 i18n。状态联合保持状态与对象对应，结果转换用完整分支和穷尽检查，不把新增状态默认为 `version_conflict`。Model/Storage 与 Public 的映射各留在自己的边界，不集中成一个全局 mapper；不为无表示差异的基础状态增加额外层。使用现有格式工具，不扩大为全仓风格重写。

**施工结果**：按 1 → 2 → 3 → 4 → 5 → 6 顺序修正了实现；仍需真实洪泛/缓慢消费、SSH 尾帧/ACK、并发释放与失败、关闭窗口、前端重试/卸载及本地化展示的行为验收。D 批事务内纯规则、Run/事件/幂等原子提交未推翻；重放仍返回初次快照。Agent 当前没有同义前端消费者，不提前迁 Shared。

## E：Agent Root 执行链（待施工，按依赖分项交付）

本批目标是把 D 批的**持久 `pending` Root Run**接到真实、受限、可恢复的执行链，而不是复制旧 Agent 全部实现。开始前阅读 [Agent 架构](AGENTS.md) 的执行状态、预算、审批和 unknown outcome 规则；审计旧 `packages/backend` 的真实 Service/HTTP/Frontend 消费者与新 `agent/public.ts`、`runs/storage`、`migrations.ts`、`module-manifest.ts`，列出仍需迁移的用户流程与所有权。旧 Backend 不作为运行依赖，正式入口和现有开发入口保持隔离。

### E1：定义持久执行身份、准入和恢复（与 E2 的真实消费者配套交付）

- **Owner**：`modules/agent/runs` 持有 Run 与状态事务，新增 `modules/agent/runtime/scheduling` 时由它持有可关闭的执行准入、lease/fence 与启动恢复循环；Bootstrap 仅负责实例化、启动、停止准入、等待任务收敛，不把调度塞入 Platform 或 HTTP。若还没有 E2 的真实执行消费者，不安装空轮询或“已调度”假状态。
- **先确定的契约**：Run 身份 `userId/App/Thread/runId`、冻结的输入与选定执行配置、预算/期限、`operationKey`，以及可持久重取的执行工作身份；区分 `accepted`、`claimed`、`executing`、`settled`、`interrupted` 和业务取消的实际语义。当前 v3 只支持 `pending/cancelled`，新增状态、版本、work、事件和索引必须由 **v4 及后续编号的新迁移**实施，不改 v1–v3 的 DDL 或签名。
- **提交和调度**：创建、Run version、初始执行工作/可枚举待执行事实、事件与幂等快照同一事务提交；调度只能读取已提交的待办，`created` 以外的 `replayed`、冲突、回滚绝不创建第二份工作。读取任务时重新校验 Run 未取消、scope、version/fence、预算与配置快照；多个实例或重启不允许双重所有权。
- **关闭与恢复**：`quiesce` 停止取新工作；已接纳任务传播取消信号并 drain。重启仅根据 durable work 和 lease/fence 回收可确定的本地准入；超时、Worker 退出、`commit_unknown` 不等于操作未发生。外部调用 outcome 不明时留在待核对/隔离状态，不自动重放。
- **完成判据**：应用层命令、存储命令和 SQL 记录分离；数据库唯一约束与 CAS 承担并发正确性；事件序号、幂等快照和待执行事实同事务更新；没有进程内“通知丢失就丢 Run”的窗口；静态检查与构建通过，真实并发/断电/重启行为列为待验收，不能宣称已经验收。

### E2：最小真实 Provider Root 回合（依赖 E1，优先无工具执行）

- **Owner**：Agent 的 Model/Provider Service 决定请求、预算和结果语义，具体 Provider 网络协议由可注入的技术 Adapter 完成；Platform 不知道 Run、消息、模型供应商配置或费用。仅在完成真实 Provider 配置、凭据保护、请求边界和冻结模型能力之后才启用入口；不返回固定内容或空成功作为占位。
- **流程**：在持久 claim/fence 内读取当前 Run 和冻结输入，构建有界模型请求；一次真实请求的开始/结束/usage/错误与消息结果均经 Agent 状态提交边界写入。允许中断但不得把中断自动记成用户取消；模型完成和用户可见 Ledger/Run 终态必须同一权威提交，不能先向 HTTP/WS 发送未提交的成功。
- **边界**：Provider 超时/连接中断与已产生远端效果不等价，区分可确定的本地未发送、已确认失败和 unknown。限额、deadline、AbortSignal、重试与退出释放有统一 owner；不得修改旧 Agent/Protocol 以伪装新回合已执行。
- **完成判据**：能够在独立后端中对真实 Provider 完成一次**无工具** Root 回合，Run/事件/结果可在重启后再次读取；竞争取消不会提交过期 completion；幂等重放不会重复请求 Provider。没有完成这一步前，不开放新的 `running/completed` 假状态或假结果。

### E3：Tool 治理和 SSH 执行（依赖真实 E2 回合）

- **Owner**：Agent 自己的 capability/grant、policy、approval、lease、ToolCall 和 settlement；Targets 只暴露可信目标解析与配置指纹，Platform SSH/SFTP 只执行机械连接，Remote 的普通 PTY SessionOwner 不授予 Agent 执行权。
- **流程**：严格遵循 `inspect → grant → policy → approval → lease/fence → execute → verify/reconcile → durable settle`；每次变更操作冻结 tool schema/arguments、scope、SSH connection ID/configuration hash 与 operation identity，执行前再次验证过期、撤销、配置变化和授权。先迁入确有真实消费的受限 Tool，不搬运旧 Plugin/MCP/ACP 全家桶。
- **未知结果**：远端命令/文件或工具已经发出后，断线/超时不能声称没有副作用；记录 durable unknown/quarantine 并要求证据核对。批准只允许明确匹配的操作，不覆盖 hard deny；取消不能“回滚”已执行的 SSH 操作。
- **完成判据**：至少一个真实受治理的只读操作和一个需授权/审批的变更操作可追踪到持久结果；拒绝、撤销、审批过期、相同 ToolCall 重试及未知副作用均按既定状态处理；不泄漏密文或复用终端会话。

### E4：对外结果与恢复收口（依赖 E2/E3，正式切换另批）

- **接口和消费者**：由 Agent 模块接口层提供已提交 Run 状态、持久事件游标和真实结果投影；出现新的**双端同义同表示**契约与前端消费者时才增加 Shared `agent/` 子路径并同步迁移。前端不能重用旧 Agent Store/Socket 来消费不兼容的新协议。
- **重启验证点**：重启后重建 claim、预算、冻结配置、Ledger 与事件游标；重复 HTTP Key、延迟的 Provider 回答、旧 generation 的 Tool 结果和已撤销权限都不能复活终态 Run。确认停机先断准入、释放 Provider/SSH 句柄与定时器，等待 in-flight 状态处理后才关闭 SQLite。
- **完成判据**：独立实例的真实用户流程、失败恢复和错误码一致；每个模块出口仍逐字段白名单映射；文档同步更新真实 owner、Shared 消费者与用户可见行为。E4 完成不代表旧版全部 Agent/Remote 产品能力已经迁移，也不自动切换正式 Backend。
