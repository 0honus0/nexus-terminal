# 后端重构下一阶段实施方案

## 本阶段目标与使用方式

下一阶段是 **HTTP/WebSocket 协议边界整理与真实消费者同步迁移**。现有新后端已提供有限的 Access、Targets、Remote、Agent 路由，本阶段在这些实现上收口契约、解码、错误映射和资源生命周期，不重新搭建后端。P0 完成了真实端点与消费者盘点，P1 的 HTTP/WS 来源与停机边界和 P2–P4 的 Shared 目录、完整 HTTP/WS 解码及实际消费者已完成源码施工。P5 仍以静态检查和未执行行为验收分开记录；**协议代码完成不代表正式 Backend 已切换或真实产品功能验收通过**。

长期约束统一遵守 [AGENTS.md](AGENTS.md) 与[架构重构](架构重构.md)，尤其是[全局编码约定](架构重构.md#全局编码约定)、[模块出口约束](架构重构.md#全局模块出口约束)、[HTTP/WebSocket 接入与协议长期约束](架构重构.md#httpwebsocket-接入与协议长期约束)。实际 owner 与调用关系同步维护 [Backend 架构](architecture/BACKEND.md)、[Frontend 架构](architecture/FRONTEND.md)；历史专项证据和未通过项统一放在[验收文档](testing/E2E.md)，本文不保留旧 A–D 审核报告或执行阶段施工清单。

实施顺序为 P0 → P1 → P2 → P3 → P4 → P5。P2–P4 可按 Access、Targets、Remote 的完整功能逐项推进，每项同时修改所有真实消费者；不一次铺满空类型、空客户端或空接口目录。每个独立事项完成后同步文档、检查并本地提交，推送按用户指令进行。

## P0：盘点端点、协议与消费者

**目的：先确认真正需要调整的契约及其 owner，避免由类型名称推测行为。**

逐条读取现有路由、Shared、前端调用与旧正式消费者，为本阶段端点建立契约表。每条记录包含：method/path、path/query/header/body、成功与业务失败形状、HTTP 状态码、鉴权与资源归属、敏感字段、版本/幂等、输入上限、公开消费者，以及未接入功能。契约表在本文对应批次就地维护，收口后将长期约束移入正式架构文档，不另建长期接口进度台账。

必须盘点：

- Access 的 `needs-setup/setup/login/status/logout/password`：初始管理员、未认证结果、登录轮换、注销/密码变更撤销、rememberMe 与 cookie 设置/清除；确认开发页所有内联 fetch 消费者。
- Targets 的 Connection/Proxy/SSH Key/Tag 管理，Connection clone、关联 Tag、导入、凭据变更/删除，以及 Host Key list/confirm/remove；区分管理结果与后端可信 SSH 解析，确认后者从不进入公开 HTTP。
- Remote 的 `POST /sessions`、`GET/DELETE /sessions/:id` 和 `/stream?sessionId`；列出每种客户端/服务端事件、合法次序、owner/token 绑定、正常与异常退出结果。
- Agent 的 App/Thread 创建、Run 创建/查询/取消、事件分页；记录 Idempotency-Key、expectedVersion、scope、replayed/originalStatus 和 cursor 语义。当前 Run 仍限 pending/cancelled，无前端消费者的类型留在模块内。
- Shared 的已有 `connections/proxies/ssh-keys/tags/targets/remote` 契约及精确 exports；检查是否遗漏真实双端类型、重复定义或只靠类型断言的解析。

**完成判据：** 所有范围内端点都能追到生产代码的输入解码、用例、输出映射和实际消费者；需要更改的协议有明确理由、受影响方和迁移办法。旧生产消费者只用于发现遗漏，不据此扩大到完整产品迁移。

| ------- | ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |

## P1：收口通用 HTTP/WS 技术能力

**主要位置：** `platform/http`、模块 `register.ts` 和 Bootstrap 的安装/关闭入口。

1. 按 P0 结果确认通用 route/context/channel 的最小能力：原始参数、`unknown` JSON、响应发送、cookie、来源信息、AbortSignal 与关闭责任。若契约和技术实现确实需要独立演进再拆文件；不为目录对称增加空转包装。
2. Platform 负责监听、匹配、JSON/Content-Type/body 上限、Origin/Fetch Metadata、受信代理与技术输入错误。业务 route 负责自己的 query、分页、header、权限和状态语义。保留非法 JSON 400、过大 body 413、不支持媒体类型 415，不让模块 catch 改为 500/503。
3. 复核路由重名/冲突、响应是否已结束、异步失败和 WS upgrade 拒绝路径；错误后不能二次发送或遗留未处理 Promise。只补充真实安装所需的通用检查，不引入业务路由注册槽位、万能 RPC 或全局业务分发器。
4. 保留 WS 有序消息处理与累计上限，发送背压、finish 和强制 close 的责任明确。Platform 不读取 Remote/Agent frame，不持有 Session/Run 状态。
5. 关闭停止准入，等待 HTTP 任务、升级鉴权和 WS 已接纳任务；模块完成建连/会话清理后才关闭 SQLite。浏览器断开不能被当成密码验证/已开始事务已取消，失败仍继续必要释放并聚合。

**完成判据：** Access、Targets、Remote、Agent 均只依赖通用技术契约；Bootstrap 只安装模块提供的能力和编排生命周期。技术 4xx、安全检查、队列上限和停机等待没有退化。Platform 不导入业务 DTO/状态，也不制造无人使用的抽象。

**P1 源码收口**：`http-server.ts` 已拒绝完全重复、参数名等价及交叉重叠歧义模板；已发 HTTP 头或未结束响应不再二次发送 JSON，序列化在发送头前完成；默认 JSON body 16 KiB、Agent Run 专属 128 KiB，配置硬上限仍是 128 KiB。可信代理转发的 Host/Proto 均须单值，Cookie 写请求对已声明的 Origin/Fetch Metadata 校验精确同源，未带浏览器来源头的非浏览器调用仍须真实鉴权，WS Upgrade 待鉴权 Socket 与在线连接在停机前同步拒绝/终止，已接纳 HTTP/WS/清理任务在 SQLite 关闭前收敛，WS 关闭回调错误进入聚合。Platform 仍无业务 DTO/状态。**上述是静态代码事实**；真实代理、输入 4xx、shutdown 极端并发行为仍按 P5 待验收。

## P2：Shared 层级重组、共享字段统一与完整协议迁移

**主要位置：** `packages/shared/src`、`packages/shared/package.json`、Backend-next 模块公开/HTTP 边界、Frontend API/Transport，以及旧正式包中实际消费相同基础取值的引用。

**P2 源码迁移完成（行为仍待验收）**：原平铺目录与 `api.ts` 已实际删除，Access 拆为 `model/http`；Targets 移到 `targets/{connections,proxies,ssh-keys,tags,host-keys}/{model,http}`，基础枚举在子域 `values`，共用业务错误在 `targets/values`，通用纯校验在 `targets/http`，实际需要复杂 JSON 校验的子域拥有 `http-codec`；Remote 移到 `remote/sessions/{model,http,events}`。新的精确 exports、Backend-next、前端开发消费者及旧正式包中确实共用的基础取值引用已同步，没有兼容重导出。请求/响应、CAS、凭据写入、导入分项、Host Key 与 Session 释放均有明确 Shared 类型及纯解码。Shared/backend-next/frontend 的静态构建已通过，未运行新的行为测试，不能把迁移标为真实验收。

### P2.1：目标目录与职责

Shared 顶层按 Backend 大业务模块 owner 划分，模块内再按功能划分；Connections、Proxies、SSH Keys、Tags、Host Keys 归 Targets，普通终端会话归 Remote，Agent Run/审批等归 Agent。两侧共用的目标对象只在 Targets 定义，不分别复制到普通 SSH 和 Agent 目录。

```text
packages/shared/src/
  access/
    model.ts
    http.ts
  targets/
    values.ts                    # Targets 域共同有限取值，如稳定业务错误码
    http.ts                      # Targets 域共同 HTTP 错误响应
    connections/{values,model,http}.ts
    proxies/{values,model,http}.ts
    ssh-keys/{model,http}.ts
    tags/{model,http}.ts
    host-keys/{model,http}.ts
  remote/
    sessions/{model,http,events}.ts
```

以上为本批目标布局；部分目录已在并行迁移中建立，仍需逐项核对字段归属、完整契约及全部消费者。没有实际内容的文件不创建；Remote Sessions 等子域确有共用基础取值时才补 `values.ts`。后续 Remote Files/Transfers/Operations 与 Agent Runs/Approvals 等按真实迁移消费者增加子目录，当前不建空的 Agent Shared 域，不复制旧 Agent wire 来制造新消费者。

| 文件        | 唯一职责                                                                | 依赖边界                                                                  |
| ----------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `values.ts` | 有限取值类型、取值常量和确需共用的基础取值                              | 不依赖对象、HTTP、事件、业务模块或框架                                    |
| `model.ts`  | 双端同义同表示的业务对象与业务结果，例如连接视图                        | 引用所属基础取值；真实组合需要时引用其他 owner 的公开业务对象，不形成循环 |
| `http.ts`   | 完整请求/响应、query/path/header 的共享语义、公开 HTTP 错误与纯边界解码 | 引用所属 values/model；子功能可引用模块共同 HTTP 错误契约                 |
| `events.ts` | WebSocket 消息与事件的载荷、状态联合和解码                              | 引用所属 values/model，不依赖 HTTP 路由实现                               |

`model.ts` 不导入 `http.ts/events.ts`；模块共同 `targets/http.ts` 不反向汇总所有子功能 DTO，避免父子循环和巨型入口。复杂纯解码确需拆文件时可使用所属子域 `http-codec.ts`，通过精确子路径消费，保持 `http-codec → http/model/values` 的单向依赖，不让 http 文件再重导出该 codec。Shared 不依赖 Node、SQLite、Backend、Vue 或具体 HTTP 库。

### P2.2：共享字段唯一定义与类型归属

**所有前后端共同消费且语义、表示一致的字段、有限取值、对象、业务结果及通信契约，统一由 Shared 持有唯一定义。** 不在 Frontend、Backend public、HTTP 文件或旧 Protocol 再手写一份同义结构，不在两端分别维护枚举或 wire 字段清单。按完整语义对象组织，不机械为每个 `string/number` 字段建立别名，也不引入一个可任意 Pick 的全局大对象。

- 同义业务对象及可跨调用方式复用的业务结果归 `model.ts`；创建/更新/导入等 HTTP 专用输入、响应封装与传输错误归 `http.ts`。例如完整 `{version, changes}`、`{items}`、`{deleted: true}`、`{closed: true}` 都要有 Shared 契约，不能只共享内部 payload、由双方各自拼外壳。
- HTTP 响应字段与业务对象确实相同时，响应类型直接引用 Shared model，不复制字段；对象白名单转换依然执行。协议对象中的同义基础取值引用 values，不能重新声明相同字面量联合。不同状态用具名可辨识联合，不把结果改成宽泛 status 加可选字段。
- 前端表单可以直接引用或组合 Shared 字段类型；UI 状态、草稿控制、组件 props 的专有表示仍在前端。Backend 应用/存储对象含义或表示不同，继续保留内部类型及显式映射，不为了统一字段把存储结构搬进 Shared。权限、业务引用、Host Key 核对、事务和持久数据校验仍由业务模块负责。
- 普通 SSH 与 Agent 共同使用的 ConnectionType、目标引用等，只引用所属 Targets 共享定义；Remote Session、Agent Run/审批/Tool 结果分别按 owner 定义。后端可信明文解析、授权上下文、事务句柄、SQL 行、密文及 Worker 结果不共享。密码/私钥可出现在必要的写入请求，绝不进入公开响应、事件或错误。
- 旧生产包只使用 Shared 的相同语义与表示。既有 route:null、旧 jumpChain 等 wire 与新对象不同，保持各自表示，不强行别名为新 DTO；相同基础取值的旧导入仍必须随本次路径移动同步更新。此批不接管正式流量或完整迁移旧 Store/Workspace。
- 请求/响应从 unknown 严格解码；相同结构的双端校验规则收口到 Shared。后端业务约束、前端展示校验和仅单端存在的处理不混入共享纯解码。不得用 `as DTO`、对象展开或类型返回签名替代校验/出口字段投影。

### P2.3：现有文件到目标位置的迁移表

| 迁移前位置                          | 目标位置及拆分依据                                                                                                                                        |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |

## P3：按模块接入协议与安全映射

**主要位置：** 各模块 `interfaces/http`、public 契约与出口 mapper。

通用调用链为：技术请求 → 模块协议解码/鉴权 → 模块公开输入 → Service/Model → 模块公开结果 → 协议响应。协议 helper 只处理接入问题，不直接调用 Storage/SQLite，不复制 Service 业务规则。

### Access

将 P2 的认证契约用于现有六类路由，逐项定义 needsSetup、登录/身份状态、未认证状态、注销与密码变更结果；返回只包含公开身份字段。保留 cookie 的 HttpOnly/SameSite/部署 Secure 设置及清除路径、固定 Origin 策略和当前管理员限制。登录因素未迁移时明确拒绝，不能悄悄绕过。业务错误由 Access 映射，通用 HTTP 输入错误继续交由 Platform。

### Targets

补齐管理输入/响应与 Host Key 的解码/编码。CAS 更新、版本冲突、引用占用、缺失对象、凭据操作、clone、关联 Tag 和按条导入结果必须逐个保留语义；导入上限 50 条、按条事务和部分成功不改成批量假原子。确认 Host Key 使用可信核对后的 SHA256，不默认信任；只暴露允许的端点/指纹管理信息，可信明文解析仍是后端专用出口。

模块 public 白名单与 Model 存储转换保持分工：前者限制出口字段，后者转换应用和持久表示。不能把 `connection-mapper.ts` 搬入 public mapper，也不能因 Shared 字段相同直接返回内部对象。

### Remote

Session HTTP 的创建/查询/释放结果与 WS frame 使用真实契约；校验 sessionId、frame 类型/长度、base64、resize 和 consumed 字节。明确 ready/data/drain/blocked/closed/error 的合法状态，未知消息或超额 ACK 不继续执行。HTTP 与 WS upgrade 均从 Access 获取身份并检查 owner/token；Access 撤销与来源失败不能退化为匿名接入。

保留当前限额与关闭语义，详见[Backend 架构 Remote 章节](architecture/BACKEND.md)：正常 EOF 尾字节等待渲染 ACK，再 closed/正常握手；SSH 断线/清理失败返回安全错误；主动关闭/撤销/停机有独立路径。最近释放缓存只在读取时清过期项，插入后超容量才淘汰；它只确认有限窗口内相同 token 的释放结果，不承担恢复或持久幂等。

### Agent

仅整理当前后端私有契约、输入解码和公开结果。userId 由服务端身份取得；App/Thread/Run 归属、Idempotency-Key、expectedVersion、事件 after/limit 均有界验证。保留首提交冻结结果的 replayed/originalStatus、创建/取消/冲突的独立联合与最多 100 条事件页；公开视图不包含输入原文、请求 hash 或内部 userId。commit_unknown 仍是安全不可用，不通过 HTTP 自动重放未知写入。不扩大 Run 状态或开放假执行入口。

**完成判据：** 每条端点具备明确输入、公开字段、安全错误/状态码与权限边界；所有联合分支完整处理，不默认为某个现有状态。没有技术原始异常泄露、通用 4xx 被吞、重复对象定义或 Storage 越界调用。

## P4：同步真实前端 API 与 Transport

**主要位置：** `features/targets-next/api`、`features/targets-next/views/TargetsNextDevView.vue`、`runtimes/remote-next/transport` 及对应 i18n。

1. 将开发页内联 Access fetch 和认证响应处理移到明确的 API owner，View 只执行公开操作、管理展示状态。Access 语义不同于 Targets 管理，不塞入连接 CRUD 客户端；存在独立跨功能消费时再建立相应 Feature 公开入口。
2. Targets API、Access API 和 Remote Transport 分别消费 Shared 请求/响应/事件解码。HTTP JSON 与 WS JSON 均先按 unknown 处理，不能用 `as DTO` 代替验证；未成功响应不能按成功对象解析。
3. 抽取通用 fetch 前确认实际重复的网络语义、错误与取消责任。若 Access/Targets/Remote 确实共用，在现有 Frontend foundation 的适当 owner 提供最小技术请求能力，通过公开入口消费；否则保留局部 helper。不依赖旧 Agent 业务 HTTP client，不建立巨型客户端框架。
4. 处理非 JSON/空正文/网络失败、稳定错误码与 AbortSignal；业务 payload 解码归对应 API/Transport。提交未知或幂等操作不能由通用客户端自动重试；同一操作重试沿用原键和语义参数。
5. 保留 Remote Socket、frame、ACK、generation 和共享 close Promise 的 Transport owner。组件不接管 wire，不复制服务端 Session 状态；渲染完成才 ACK，旧连接迟到错误不覆盖新连接，晚到成功/卸载仍释放资源。DELETE 未确认或关闭失败必须可见。
6. 用户文本同步现有 `i18n` 的 en-US/zh-CN/ja-JP，移除失效 key；不新增 `locales` 目录或显示原始技术异常。隔离开发页 `/__targets-next` 继续通过显式 `NEXUS_VITE_BACKEND_NEXT_ORIGIN` 配置的 `/__next` 代理接入，不影响正式登录态/Store/Workspace。

**完成判据：** 两端每项变更均有真实消费路径，页面无散落的业务 fetch/frame 处理，API/Transport 不把未验证数据传给 UI。取消、失败、重试及卸载仍有唯一 owner，没有旧包运行时依赖或旧 generation 覆盖。

**Access 子域 P2–P4 源码收口**：Shared `access/model` 只包含公开用户身份，`access/http` 定义写入凭据、6 类端点完整成功/安全失败、严格运行时解码。Backend 的 setup/login/password 从该契约解码，开发页 `access-next-api.ts` 与相同契约联动，明确 401 未认证、异常/非 JSON 安全失败。Session Cookie 和后端身份恢复仍留 Access。当前开发页没有密码修改界面，不能把仅有的改密 API 当作产品 UI。

**Remote Sessions 子域 P2–P4 源码收口**：Shared `remote/sessions/model` 拥有同义 Session View 与 ID 规则，`http` 拥有开终端/释放、公开 Session、HTTP 安全错误与完整成功响应，`events` 拥有双向 WS 可辨识联合及严格解码。Backend 与独立 Remote Transport 同时消费；输出 ACK、异常 EOF、WS 资源/Backpressure、权限和 owner 校验仍由 Remote 负责。本轮未新增/运行真实网络或浏览器测试。

**Targets/Agent P2–P4 源码收口**：Targets 五个子域的创建、查询、CAS/Tags、clone、凭据设置/清除、导入逐条、删除/Host Key 响应均由 Shared `http` 类型与纯 `http-codec` 在 Backend 和开发管理 API 共用；DTO allowlist 和真实引用/事务规则仍归原模块。非 JSON、未知码及异常网路使用安全兜底，三语言错误文案同步。Agent 仅整理原后端私有协议及全部结果分支，Run 不增加假执行和新 Shared 空域。真实浏览器、Origin/Proxy 与异常关闭场景仍在 P5 待验收。
