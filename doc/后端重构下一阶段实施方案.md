## 每批共同遵守的编码与架构规范

完整规范以[全局编码约定](架构重构.md#全局编码约定)和[AGENTS.md](AGENTS.md)为准。下列事项在每批开发和人工代码审核中逐项检查，不能仅靠格式检查判定：

1. **封装与组织**：按数据和生命周期 owner 划分大模块，功能在模块内细分。入口表达清楚步骤；完整校验、转换、事务和清理流程提取具名函数。复杂表达式先命名局部值，简单回调不机械拆分。单文件 helper 不导出，不新增无消费者的一行包装、兼容别名或杂项 utils。
2. **命名**：类型/类 PascalCase，变量/方法 camelCase，文件小写连字符；读取 get/list，转换 toX，校验 validateX，解析 resolveX，生命周期 open/quiesce/close。避免无语义缩写和含义不明的位置布尔参数，复杂选项使用具名对象。
3. **类型与转换**：公共方法有明确返回类型；用例、复用记录和复杂结果使用所属模块的具名类型，状态结果使用可辨识联合。Service 用应用类型，Model 转换存储契约和技术契约，SQLite Adapter 解码行并实现 SQL；Platform 不引入业务对象。所有模块对象出入均逐字段白名单转换，即使字段一致也不能直接返回内部对象或展开内部记录。管理出口与含明文的可信出口分开。
4. **Shared**：先盘点两端真实消费者。双端同义同表示契约统一迁入 Shared，基础取值单独 values.ts；业务 model、API、events 分文件，精确子路径导出。不同表示显式映射；内部存储、密文、权限上下文和前端 UI 状态不得进入 Shared。不能通过 as/any/非空断言代替边界验证。
5. **控制流与错误**：控制语句用花括号，优先提前返回；三元不承载复杂流程。catch 必须有清理、映射或恢复目的；技术包装保留 cause，多项失败 AggregateError，公开错误只暴露安全码。不能把 timeout/cancel 解释成副作用未发生，也不能自动重放 unknown。
6. **异步与资源**：每个 Promise 有等待/拒绝处理 owner；关闭 Promise 先保存再清理，重复关闭等待同一结果。事务只做原子状态操作，不等待 SSH/HTTP 等外部 I/O。Socket、channel、stream、timer、listener 的创建与释放成对，晚到成功也释放；deadline 不在每步重置，旧异步结果用身份/version/generation 防止过期覆盖。
7. **注释与格式**：注释解释约束及原因，TODO 写明缺少的能力、owner、补齐批次和未开放路径。Tab、单引号、分号、120 列；函数/方法及所有独立 export 声明前后保留一行空行，注释贴近声明，连续 import 不强制分隔。由现有 ESLint/Prettier 执行，不加 prettier-ignore 或人工对齐。
8. **交付**：修改所有实际消费者、文档和命令；删掉失效导出与已解决待办。每个独立事项本地提交，不自动推送。不新增源码文本扫描门禁或单元测试，不以假返回、默认密钥、默认信任或空事务占位。

## A 批修正项（代码已调整，真实行为待验收）

本节是 A 批代码审查收口记录，不代表授权进行真实 HTTP/SQLite 故障测试；修正后的静态结果不能替代运行验收。以下六项不应被写成未解决的假 TODO，也不应因通过 TypeScript 而删除其行为验证要求：

1. Access HTTP 只对业务调用应用安全错误映射；通用传输的 JSON 格式、Content-Type 与 body 上限仍由 Platform 返回 400/415/413。Access 路由拒绝自己的未知 query，Platform 不封禁其他业务的分页和 cursor。
2. Account 存储命令归 `accounts/storage`，Model 明确构造字段，SQLite Adapter 不再依赖 `accounts/model` 的应用命令。
3. 登录失败的封禁阈值与期限归 Access Service/策略持有；仅明确启用时用于公网，内网 loopback、私有及链路本地地址永远跳过。SQLite 只持有原子计数、检查和更新，不默认对所有来源强制封禁。独立部署入口尚无完整持久 IP 管理设置、白/黑名单和验证码产品界面，归后续 Access 网络策略批次。
4. HTTP 会跟踪所有已接纳的处理 Promise；停止接纳并关闭连接后，仍等待已进入密码验证或数据库写入的操作收敛，再关闭 Remote/SQLite。重复关闭等待同一 Promise。
5. ESLint 空行规则以声明行与注释真实位置判定；上一声明同行尾注释不作为下一声明的前置注释，独立 `export const` 仍检查空行。
6. 文档区分服务端 session **有效期**与持久记录**物理删除**：当前在读取到过期/密码版本失效的会话时删除，该会话在期限到达时立即不能认证，但没有为从未再次访问的过期行安装扫除任务。该物理清理属于后续 Access 会话保留策略，不能称为已实施的 30 天物理回收。

完成判据保留为行为待验收：分别核实 HTTP 400/413/415、内网地址绕过已启用封禁、并发失败计数、查询参数归业务路由、断线中的 scrypt 操作与停机数据库生命周期，以及 ESLint 尾部注释的 AST 判定；当前不新增或运行测试。

## B：Targets API、Shared 与前端连接管理（代码切片已施工，待行为验收）

- `modules/targets/interfaces/http` 安装 Connection（含标签、凭据、克隆和批量导入）、Proxy、Tag、SSH Key 的读写路由；路径为 `/api/v1/targets/**`。每次请求都用 Access 的服务端会话恢复身份，当前尚只有首次管理员有授权（初始 ID 1），其他身份拒绝；客户端不能自行指定 owner。Origin/JSON/body 限制由通用 HTTP 持有，业务严格解码结构、类型、字段和有界数组/字符串，再调用 `TargetsPublicApi`；所有返回值由显式 wire allowlist 构建，不直接回传内部对象/密文，也不提供 `trustedSshTargets` 路由。错误仅返回安全码。

- 双端同义类型位于 Shared 的 `connections/model,api`、`proxies/model,api`、`ssh-keys/model,api`、`tags/model,api` 与 `targets/api` 精确子路径。已有旧连接/代理表单的有限取值类型来源也统一到 Shared；旧 `Protocol` 中 `route:null`、认证、跳板 JSON、显示信息等表示不同的 wire 与旧运行期 Store、Workspace 保持原行为，不被强行重命名或混接新实例。
- Frontend 新增独立开发入口 `/__targets-next`，使用 `features/targets-next` 的 typed API/显式解码及单独管理表单，不复用旧 Connection/Proxy Pinia Store。需通过 `NEXUS_VITE_BACKEND_NEXT_ORIGIN` 显式启用 Vite 的 `/__next` 代理，`backend-next` 的 publicOrigin 应与浏览器打开的 Origin 一致；这个页面单独走新 Access 认证 Cookie，绝不把该记录交给旧 Workspace 或终端。开发入口提供基础管理及独立最小 SSH PTY，不宣传连接测试或完整 Remote 已迁移；生产路由不切换。
- 前端开发入口的文本同步提供 `en-US/zh-CN/ja-JP` i18n，无第二套 locales。

## C：Remote 受认证 SSH 终端入口（代码切片已施工，待行为验收）

- Remote 本模块的 `RemoteSessionOwner` 把新 PTY 的 ID 绑定到初始管理员的 **Access token 摘要和用户 ID**；打开、查询、关闭、WS upgrade、每条输入及流输出均验证 Session 当前有效性，另有周期性校验。一次 PTY 只能绑定一个 WS，未接入订阅 30 秒后自动关闭；连接断开直接关闭对应 PTY，不实现挂起、接管或恢复。HTTP 中断时传递 AbortSignal 并释放迟到的资源。
- `modules/remote/interfaces/http` 实际提供 `POST/GET/DELETE /api/v1/remote/sessions` 及 `/api/v1/remote/stream?sessionId`；拒绝无权限用户，失败只返回安全码，不直接输出解析明文、SSH 连接对象或内部异常。Platform HTTP 拥有通用 WS Upgrade、固定 Origin/可信代理校验、大小限制、缓冲上限及升级中业务 Promise 跟踪；Remote 拥有 frame 解码、PTY 背压、输入大小、已消费字节确认与释放。
- `targets/host-keys` 独立拥有 SSH 服务端密钥信任，v2 迁移建立真实 `target_host_keys` SQLite 表，管理 HTTP 允许查看、显式确认和删除 SHA256 公钥指纹。操作员**必须另行通过独立可信渠道核对**指纹后才能确认，未信任的目标和每级跳板都会拒绝 SSH 握手；`Targets` 配置指纹与真实 SSH 公钥指纹互不混用。确认不自动扫描远端，不会默认接受未知密钥；删除/更新信任影响后续建连，当前活动 SSH 会话不自动终止。
- Shared 新增 `remote/model,events,api` 以及 `targets/host-keys` 精确子路径，连接端点的指纹字段明确命名 `configurationFingerprint`。Frontend `runtimes/remote-next/transport` 自己持有 WebSocket、输入/输出及消费确认；xterm 组件只使用 Transport 句柄和字节写入。现有 `/__targets-next` 开发入口现在可选新实例 SSH 连接、确认 Host Key 与打开基础 PTY，仍不复用旧 Workspace Store/Socket。开发 Vite `/__next` 需显式配置代理并支持 WS 升级；新后端的 Public Origin 必须与浏览器面向的 Origin 一致。
- 流式消息 JSON 类型严格解码，二进制字节用 base64 表示；每条输入最多 32 KiB，WebSocket 帧 64 KiB，Browser/WS 发送缓冲 1 MiB，SSH 输出靠 128 KiB credit window + `consumed` ack 与暂停/恢复控制。背压达到上限时显式拒绝/关闭，不丢弃无提示字节。关闭顺序先关 HTTP/WS 并等待已接纳业务任务，再清理 Remote 会话与底层 SSH，最后关闭 SQLite。

**待真实验收**：第一次确认和变更 Host Key、SSH 密钥算法/公钥指纹与多级跳板、错误/撤销/跨登录令牌访问、HTTP 创建断线/WS 非法帧/多设备竞争、SSH 背压/ack/大输出、网络断连与关机 Promise 窗口。静态检查与构建通过不等于这些行为验收通过。当前不新增或运行测试。Agent 后续必须自行实现目标 grant/审批，不继承普通 Remote PTY 访问权限。

## D：Agent 首个持久状态切片（代码已施工，真实行为待验收）

- `modules/agent` 独立持有 `scope / runs` 的 Service、Model、Storage 契约与 SQLite Adapter；并非搬运旧 Agent 的所有 Provider/Runtime/审批实现。App 创建关联 Access 的真实 `userId`，Thread 创建必须验证同一用户和 App 的数据库引用；业务 HTTP 从 Access 服务端会话取得用户 ID，目前明确只允许初始管理员，不接受客户端传入 owner。
- Bootstrap 的全库签名迁移 v3 增加 `agent_apps`、`agent_threads`、`agent_runs`、`agent_run_events`、`agent_command_idempotency`。SQLite 使用真实外键/复合归属键、`run_kind='root'`、`status='pending'|'cancelled'`、`(thread_id)` 上条件唯一活动 Root 索引、`(run_id,sequence)` 唯一事件序号，以及 `(user_id,app_id,command_name,operation_key)` 幂等主键。输入原文作为冻结字段持久保存，不出现在管理返回值、事件或公开错误里。
- `RunService` 校验 App/Thread ID、内容、用户、版本和 Idempotency-Key（UUID）；命令哈希包括 schema 版本、操作名及严格顺序的字段（创建：App/Thread/输入文本；取消：App/Run/expectedVersion）。`RunModel` 提供纯状态规则；SQLite 事务参与者在 `BEGIN IMMEDIATE` 内重新读取 App/Thread、幂等键、活动 Run 和事件序号，然后按规则写 Run+事件+幂等快照。相同操作键及同样请求返回初次提交的视图，并用 `replayed/originalStatus` 明示原始结果而不产生第二次副作用；复用键提交不同参数拒绝；不同键并发创建时最多一个 `pending` Root Run。不存在的 scope/run 不暴露记录，事件查询再次检查用户/App/Run。
- 取消按 `expectedVersion` 条件更新，在同一事务中追加 `run.cancelled` 并存幂等结果；`version_conflict`、`already_cancelled`、幂等 `replayed` 有独立结果，重复取消不追加事件。事件以 Run 为范围按 `after` 和 `limit<=100` 分页，单次事务内检查访问归属和读取页；事件序号单调增长。SQLite `commit_unknown` 仍向外暴露安全的不可用错误，不自动重放未知写入；调用方必须用原键自行核对或重试。
- `public.ts` 只定义窄的 App/Thread/Run/事件管理视图及可辨识结果；`registerAgent` 对输入和输出逐字段映射。新 `/api/v1/agent` 路由只提供 App/Thread 创建、Run 创建/查询/取消、事件查询，HTTP 严格校验来源、方法、参数、字段和服务端会话，不提供假的 Run 执行或完成路由。Agent 对外类型暂只有后端和 HTTP 消费者，**没有相同表示的前端消费者**，故不抢先加入 Shared，也不修改旧 Agent/Protocol 或正式运行期。
- **TODO（Agent runtime/scheduling，后续执行批次）**：接入真实 Provider/Runner、grant/审批/lease、调度与恢复后，仅对已确认新提交的创建结果调度，取消只对新提交结果发布和清理；幂等重放和回滚绝不通知。当前没有调度器，Run 仅为真实持久的 `pending`，不得伪造 `running/completed` 或假结果。Root 执行与最终生产切换属于后续明确批次。

**运行验收保留**：真实 SQLite 并发与第二进程争用、相同/不同 Key 和 payload 重放、Scope 隔离、Thread 活跃索引、CAS 版本竞态、取消与事件编号、一次成功一次失败的回滚、重启后的幂等结果、Worker 死亡及 COMMIT 不明窗口、真实 Access HTTP 鉴权。当前仍不新增或运行测试；静态类型/构建通过不代表已验证事务行为。
