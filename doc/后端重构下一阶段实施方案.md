## 每批共同遵守的编码与架构规范

完整规范以[全局编码约定](架构重构.md#全局编码约定)和[AGENTS.md](AGENTS.md)为准。下列事项在每批开发和人工代码审核中逐项检查，不能仅靠格式检查判定：

1. **封装与组织**：按数据和生命周期 owner 划分大模块，功能在模块内细分。入口表达清楚步骤；完整校验、转换、事务和清理流程提取具名函数。复杂表达式先命名局部值，简单回调不机械拆分。单文件 helper 不导出，不新增无消费者的一行包装、兼容别名或杂项 utils。
2. **命名**：类型/类 PascalCase，变量/方法 camelCase，文件小写连字符；读取 get/list，转换 toX，校验 validateX，解析 resolveX，生命周期 open/quiesce/close。避免无语义缩写和含义不明的位置布尔参数，复杂选项使用具名对象。
3. **类型与转换**：公共方法有明确返回类型；用例、复用记录和复杂结果使用所属模块的具名类型，状态结果使用可辨识联合。Service 用应用类型，Model 转换存储契约和技术契约，SQLite Adapter 解码行并实现 SQL；Platform 不引入业务对象。所有模块对象出入均逐字段白名单转换，即使字段一致也不能直接返回内部对象或展开内部记录。管理出口与含明文的可信出口分开。
4. **Shared**：先盘点两端真实消费者。双端同义同表示契约统一迁入 Shared，基础取值单独 values.ts；业务 model、API、events 分文件，精确子路径导出。不同表示显式映射；内部存储、密文、权限上下文和前端 UI 状态不得进入 Shared。不能通过 as/any/非空断言代替边界验证。
5. **控制流与错误**：控制语句用花括号，优先提前返回；三元不承载复杂流程。catch 必须有清理、映射或恢复目的；技术包装保留 cause，多项失败 AggregateError，公开错误只暴露安全码。不能把 timeout/cancel 解释成副作用未发生，也不能自动重放 unknown。
6. **异步与资源**：每个 Promise 有等待/拒绝处理 owner；关闭 Promise 先保存再清理，重复关闭等待同一结果。事务只做原子状态操作，不等待 SSH/HTTP 等外部 I/O。Socket、channel、stream、timer、listener 的创建与释放成对，晚到成功也释放；deadline 不在每步重置，旧异步结果用身份/version/generation 防止过期覆盖。
7. **注释与格式**：注释解释约束及原因，TODO 写明缺少的能力、owner、补齐批次和未开放路径。Tab、单引号、分号、120 列；函数/方法及所有独立 export 声明前后保留一行空行，注释贴近声明，连续 import 不强制分隔。由现有 ESLint/Prettier 执行，不加 prettier-ignore 或人工对齐。
8. **交付**：修改所有实际消费者、文档和命令；删掉失效导出与已解决待办。每个独立事项本地提交，不自动推送。不新增源码文本扫描门禁或单元测试，不以假返回、默认密钥、默认信任或空事务占位。

## A 批修正项（代码已调整，真实行为待验收）

本节是 A 批代码审查收口记录，不代表授权进行真实 HTTP/SQLite 故障测试；修正后的静态结果不能替代运行验收。以下六项不应被写成未解决的假 TODO，也不应因通过 TypeScript 而删除其行为验证要求：

1. Access HTTP 只对业务调用应用安全错误映射；通用传输的 JSON 格式、Content-Type 与 body 上限仍由 Platform 返回 400/415/413。Access 路由拒绝自己的未知 query，Platform 不封禁其他业务的分页和 cursor。
2. Account 存储命令归 `accounts/storage`，Model 明确构造字段，SQLite Adapter 不再依赖 `accounts/model` 的应用命令。
3. 登录失败的封禁阈值与期限归 Access Service/策略持有；仅明确启用时用于公网，内网 loopback、私有及链路本地地址永远跳过。SQLite 只持有原子计数、检查和更新，不默认对所有来源强制封禁。独立部署入口尚无完整持久 IP 管理设置、白/黑名单和验证码产品界面，归后续 Access 网络策略批次。
4. HTTP 会跟踪所有已接纳的处理 Promise；停止接纳并关闭连接后，仍等待已进入密码验证或数据库写入的操作收敛，再关闭 Remote/SQLite。重复关闭等待同一 Promise。
5. ESLint 空行规则以声明行与注释真实位置判定；上一声明同行尾注释不作为下一声明的前置注释，独立 `export const` 仍检查空行。
6. 文档区分服务端 session **有效期**与持久记录**物理删除**：当前在读取到过期/密码版本失效的会话时删除，该会话在期限到达时立即不能认证，但没有为从未再次访问的过期行安装扫除任务。该物理清理属于后续 Access 会话保留策略，不能称为已实施的 30 天物理回收。

完成判据保留为行为待验收：分别核实 HTTP 400/413/415、内网地址绕过已启用封禁、并发失败计数、查询参数归业务路由、断线中的 scrypt 操作与停机数据库生命周期，以及 ESLint 尾部注释的 AST 判定；当前不新增或运行测试。

## B：Targets API、Shared 与前端连接管理（代码切片已施工，待行为验收）

- `modules/targets/interfaces/http` 安装 Connection（含标签、凭据、克隆和批量导入）、Proxy、Tag、SSH Key 的读写路由；路径为 `/api/v1/targets/**`。每次请求都用 Access 的服务端会话恢复身份，当前尚只有首次管理员有授权（初始 ID 1），其他身份拒绝；客户端不能自行指定 owner。Origin/JSON/body 限制由通用 HTTP 持有，业务严格解码结构、类型、字段和有界数组/字符串，再调用 `TargetsPublicApi`；所有返回值由显式 wire allowlist 构建，不直接回传内部对象/密文，也不提供 `trustedSshTargets` 路由。错误仅返回安全码。
- 新管理 API 明确采用 `direct/proxy/jump`、`jumpIds`、`rdpRemoteApp` 等新的应用表示；更新使用显式 `{version,changes}`，未传字段表示不修改，null 仅用于可空字段，错误版本为 409。导入只接受 `{items:[{connection,inlineProxy?,tagNames?}]}`，每批最多 50 条，单条依次提交并返回自己的结果；没有旧格式 JSON 兼容或模拟连接测试。
- 双端同义类型位于 Shared 的 `connections/model,api`、`proxies/model,api`、`ssh-keys/model,api`、`tags/model,api` 与 `targets/api` 精确子路径。已有旧连接/代理表单的有限取值类型来源也统一到 Shared；旧 `Protocol` 中 `route:null`、认证、跳板 JSON、显示信息等表示不同的 wire 与旧运行期 Store、Workspace 保持原行为，不被强行重命名或混接新实例。
- Frontend 新增独立开发入口 `/__targets-next`，使用 `features/targets-next` 的 typed API/显式解码及单独管理表单，不复用旧 Connection/Proxy Pinia Store。需通过 `NEXUS_VITE_BACKEND_NEXT_ORIGIN` 显式启用 Vite 的 `/__next` 代理，`backend-next` 的 publicOrigin 应与浏览器打开的 Origin 一致；这个页面单独走新 Access 认证 Cookie，绝不把该记录交给旧 Workspace 或终端。开发入口只提供基础管理，不宣传连接测试/Remote 已迁移；生产路由不切换。
- 前端开发入口的文本同步提供 `en-US/zh-CN/ja-JP` i18n，无第二套 locales。

**后续需要真实验证**：认证/无权限访问、CSRF/代理 Host、动态 URL 参数、响应只含允许字段、输入越界/错误版号/null vs 省略、Proxy/Key 密文隔离、导入部分成功与回滚及三语言展示。当前不新增或运行测试，不能把静态构建当作行为通过。正式旧管理页面与运行期不会在 B 批自动切换；C 批提供真实 Remote 授权后才可讨论替换。

## C：Remote 受认证 SSH 终端入口

依赖 A/B；复用现有 Remote Model/Service 和 Platform SSH，不新增第二套连接 owner。

1. 打开/查询/关闭会话、订阅、输入、resize 的 owner 必须绑定认证身份与会话身份；校验每一次写入和关闭权限，不能只在 open 时认证。先明确会话创建者、访问者与传输订阅的生命周期，再设计公开 DTO/events。
2. 补 Shared 的必要 session/events contract 和 Remote 的 HTTP/WS 安装入口。通用 WS upgrade、来源限制、大小限制和发送背压属技术能力；Remote 解释消息并调用本模块公开能力，不经 Platform 万能消息总线分发业务。
3. Host Key 信任必须有明确业务 owner，提供实际的已信任指纹读取及确认流程；Targets 配置指纹与 SSH 公钥指纹是不同事实。未知公钥不能默认接受，也不能靠全局 verify=true 绕过；Agent 后续复用同一信任事实，但自行实施 grant/审批。
4. 终端字节传输有界，消费暂停/恢复与 Shell 背压衔接，消息解码严格限制；关闭、断开和停机沿同一资源 owner 取消/等待，晚到建连必须清理。当前未实现挂起/续接时拒绝相关消息，不宣称普通产品恢复已迁移。
5. 前端 terminal/Workspace transport 从共享 contract 消费，组件不持有 socket/重连状态；这批只安装最小新链路，挂起/接管、恢复凭据与历史窗口在独立 Remote 扩展批次实现。

完成判据：从认证连接配置到 Host Key 验证、真实 PTY 与受保护输入输出形成同一实例的完整调用链；订阅、会话 owner 和停机顺序明确。没有真实 SSH 验证前仍标记待验收。

## D：Agent 首个持久状态切片

A 的身份上下文和现有 SQLite/Targets 足以启动本批存储施工；不等待全部 Remote UI 功能，但不会跳过自己的授权。不要一开始复制旧 Agent 全部目录。

1. 选择一个完整的状态用例：带 user/App/Thread scope 的 Run 创建及幂等返回，随后补同一 Run 的取消和安全事件查询。先定义允许状态/条件、expectedVersion、幂等身份与 request hash、事件序号及结果，不能用任意 setStatus 接口代替。
2. 在 `modules/agent` 内定义应用命令/视图、Model、独立存储命令/提交结果和 SQLite Adapter；状态规则属 Agent，存储参与者在同一个显式 tx 中读最新 App/Thread/Run/幂等事实、决策并写入。决策不移入 Platform，Model 不取得 SQL 执行器。
3. Run、事件、幂等记录及本批需要的 Thread 活跃约束同事务提交；同 key 同 payload 返回原结果，同 key 不同 payload 拒绝，并发创建不能产生两条活动 Root Run。取消对终态/重复请求/版本冲突有明确结果。
4. 存储提交结果经 Model 转为应用结果，提交成功后才发布或调度；回滚不通知，幂等重放不重复通知。SQLite commit_unknown 保持未知，不自动重放；本批没有真实调度器时留明确 TODO，不伪造运行/完成状态。
5. 公开 Run/事件视图逐字段转换；Agent 目标授权、审批、lease、Tool、后台 SSH Job 属 Agent，不依附普通 Remote 终端会话。后续接 Targets 可信目标和 Platform SSH 时仍经过 Agent Model，冻结 scope/配置身份并重新校验。

完成判据：独立 Agent 语义化存储契约能表达 scope/CAS/幂等/事件的原子性和安全出口，不要求本批假装已完成 Provider、工具执行、审批或前端 Agent 全功能。真实故障与并发行为待授权验证。

## 待完成的真实行为验证（授权后执行）

在允许运行集成验证后，按照故障风险而不是简单 happy-path 覆盖开展以下工作。Access 仍需验证空库并发首次创建仅一次成功、session 轮换与已撤销/过期 cookie、记住我 30 天及普通 browser cookie、旧会话在密码变更后失效、启用但未实现第二因素的拒绝、来源伪造/Origin/Fetch Metadata、可信代理/IP 和停机期间连接释放。测试放在仓库根目录 `tests/`，不得添加单元测试或源码文本扫描门禁。

1. **SQLite 故障窗口**：确认真实 `node:sqlite` 数值 `errcode` 及扩展码的 constraint、外键与 busy/locked 分类；Worker 异常退出后已接纳和排队操作被明确拒绝；事务回调、COMMIT 失败、ROLLBACK 失败分别有可识别结果，未知提交不重放；事务回调内嵌套默认入口或关闭不会自我等待。两次 `close()` 共享整个 drain/Worker 终止/路径释放 Promise，启动失败清理保留全部错误证据。
2. **Targets 错误出口及图**：输入、SQLite 外键/唯一键、密钥/代理引用、可信解析和 `importMany` 失败只对外暴露安全错误码；正常 `updated/not_found/version_conflict` 状态保持原语义。检查主目标深度 0、最多 16 条边、最多 256 个展开节点，修改被引用子链不能使上游已有目标成为非法配置。所有失败写入完整回滚。
3. **SSH 技术能力**：以可控的真实 SSH Server/Proxy 验证密码与密钥认证、Host Key 验证、直连、HTTP CONNECT、SOCKS5、有序多级跳板以及每个跳板自身 Proxy/Jump 路由。总体 connect deadline/AbortSignal 不在每跳重置；故障窗口包括前跳 ready 后、后跳尚未完成时的 error/close，以及建连监听向运行期监听交接；失败/取消及时关闭半建连资源，重复关闭不泄露 Socket、Client、channel 或订阅。Host Key 策略由调用方提供，配置指纹不代替公钥信任。
4. **Shell、Command、ACP 与 SFTP**：PTY 输入/输出/resize、pause/resume、drain 与背压；命令 stdout/stderr/退出码/信号，非零退出与超时/断连未知结果；已取消输入不得派发命令，持续命令及原始无 PTY 双向通道打开后的取消须关闭 channel。SFTP stat/lstat、目录枚举、读写流、rename/remove、mkdir/rmdir，覆盖请求默认期限、独立取消/期限及 Lease 关闭时仍有待完成请求或流的窗口；核实 `not_started/unknown` 区分与关闭等待。取消远程副作用的未知结果不能作为确定失败自动重试。
5. **Remote 会话与停机**：从 SQLite Targets 凭据出发，经 Remote Model 解析目标、逐字段转换 MachineEndpoint 并打开 Shell；Service 通过独立应用资源契约管理按 ID 订阅、写入/背压、resize 和关闭。并发开会话与停机竞争时，迟到的成功结果必须释放；活动表已移除但底层尚未关闭时，重复关闭仍等待同一次清理并取得相同失败结果；先 quiesce/取消并等待 Remote 的 pending/live 资源，再关闭 SQLite。没有 Host Key 策略时明确拒绝 SSH 建连。

本批网络能力尚无真实 SSH 服务器集成验证，不能宣布满足正式流量切换条件。发现协议或资源所有权问题时，应先修复对应 Platform Adapter 或 Remote owner，再进行真实验证；不要用延长 timeout 或假返回绕过故障。
