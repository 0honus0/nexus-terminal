# 后端重构下一阶段实施方案

本文只维护尚未实施的任务；上一协议阶段施工清单已清除。长期规则唯一入口为 [Backend 架构与开发约束](architecture/BACKEND.md)，尤其是人工类型规则 4–7；行为需求见 [USAGE](USAGE.md)，Agent 治理见 [AGENTS](AGENTS.md)，验证入口与证据见 [E2E](testing/E2E.md)。开发前完整读取这些入口。

## 当前进度与范围

按完整后端替换（含 Agent、Remote 全部功能、正式前端迁移及交付）估算，当前约 **30%，合理区间 25%–35%**。这是按功能工作量的粗估，不按文件数、提交数或测试数量计算，也不是验收通过率。SQLite/SSH/HTTP/WS 和模块边界骨架约 80%；Targets 基础管理已具备，Access 仍缺完整因素/策略，Remote 只有 PTY，Agent 只有有限持久状态。主要剩余工作在 Agent 执行链、Remote 产品能力、系统配套及正式切换。

| 范围       | 当前可依赖能力                                                                          | 后续缺口                                                                                         |
| ---------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Platform   | SQLite Worker/事务/迁移、SSH 路由/命令/SFTP、HTTP/WS、密码学、关闭结果/失败证据有界管理 | 新切片按实际需要补技术能力及完整资源语义，不预建业务注册槽                                       |
| Access     | 初始管理员、密码、会话、登录失败策略与 HTTP                                             | 因素、角色、来源策略及配置管理、撤销通知                                                         |
| Targets    | 连接/代理/密钥/标签/导入/CAS/凭据/Host Key、可信解析                                    | 连接测试、Agent 冻结指纹的同快照核对、完整正式前端迁移                                           |
| Remote     | 普通 PTY、认证 HTTP/WS、背压/ACK、关闭与 EOF                                            | 文件/编辑、传输/任务、挂起恢复、桌面及其他远程能力                                               |
| Agent      | user/App/Thread scope、pending/cancelled Root、幂等、原子事件、分页                     | Provider、StateCommit 扩展、调度、grant/审批/工具、SSH Job、恢复、Plugin/MCP/ACP/Artifact/Memory |
| 其他与交付 | 双包参考、独立开发入口、静态检查                                                        | 偏好/通知/审计/系统/备份、全部正式消费者、真实验收与入口切换                                     |

保留 `backend`/`backend-next` 双包；新包不运行时引用旧包或 Protocol。正常产品结果保持一致，异常文案与未发布兼容分支不机械保留。当前不新增或运行测试，不切正式流量；未实施功能可以带 owner 标记 TODO，当前切片所需 SQL、事务、解码、权限、未知结果和清理必须真实实现。这里只制定后续任务，不代表授权立即实施所有批次。

## 下一批：可信 SSH 解析与 Remote 文件读取

目标是用一个真实文件读取切片检验普通 SSH 与后续 Agent 对共用技术能力的需求，同时补齐冻结目标校验。按 N1 → N2 → N3 → N4 顺序实施；完整传输、Agent 执行和挂起恢复不进入本批。

### N1：Targets 同快照解析与指纹核对

位置：`targets/public.ts`、resolver 的 Service/Model/storage/SQLite Adapter、public mapper、所有解析消费者。

1. 增加具名后端公开解析请求，包含 targetId、可选 expectedFingerprint；逐字段转换为 resolver 内部请求，不把 Run/权限/审批放入 Targets 或 Platform。
2. 在一次存储事务快照内读取目标、凭据、代理和全部跳板；Model 根据这同一份事实计算 fingerprint，核对 expectedFingerprint 后才返回可信结果。配置变化明确返回安全冲突类别，不返回明文、SQL 或 destination 诊断。
3. 不能先调用 fingerprintStored 再 resolveStored 来证明快照一致。盘点真实调用者后，保留确有独立展示/检测用途的 fingerprint 能力；无消费者方法删除，不建立兼容别名。
4. Remote 和后续 Agent 都使用该窄解析能力；Targets 不获得 Agent grant、用户 PTY 或调度生命周期。

完成判据：一次解析可以证明返回机器目标与核对指纹来自同一次快照；公开类型不引用私有应用类型；没有先比较后重新读取的窗口。

### N2：Remote 文件应用资源与只读用例

位置：`modules/remote/files/{model,service}`、Remote register、公有能力，按真实持久化需要才增加 storage。

1. 盘点旧文件 list/stat/文本读取消费者、路径表示、排序与界面限制；遵守现行路径规则，不假定“SSH 文件管理器必须锁定项目目录”。Agent 项目目录授权是独立能力，不能直接套普通用户会话权限。
2. 建立 `model/file-types.ts` 的内部路径命令、文件记录、读取结果及资源类型。Model 只取得 Targets 可信解析和 Platform SSH/SFTP，逐字段转换技术目标/结果；Service 不接触 SSH2、Node Stream 或 SqlExecutor。
3. 为普通用户定义 Remote 自有文件资源 owner，绑定 Access 会话、目标 ID/指纹、准入、期限、并发、闲置回收与关闭。是否复用现有 PTY 的机器连接必须先证明生命周期和借用责任；不要默认关闭 PTY 就关闭所有文件任务，或让文件借用者关闭共享技术连接。
4. 实现目录列表、stat 与有界文本读取；源记录解码、symlink 信息、编码/二进制识别、内容大小和取消由明确 owner 负责。下载流与全量目录分页的支持方式须根据真实消费者制定，不以截断数据伪装完整结果。
5. Platform 已有 SFTP 能力可复用；缺失能力只在技术 owner 补齐。接入前补齐读取范围的安全整数与次序校验，明确正常流完成、强制 destroy、本地 lease 释放和底层关闭确认各自保证；本地释放不代表远端副作用已停止或成功。Agent 后续文件能力复用技术接口，保留自己的 grant/inspection/冻结目标与资源管理，不调用普通用户文件会话。

完成判据：真实数据读取而非假内容；失败、取消、超时、断线和晚到资源均有关闭责任；内部应用结果不含第三方句柄或凭据。

### N3：Shared 文件协议与独立开发消费者

位置：`shared/remote/files` 精确 exports、Remote interfaces、Frontend `runtimes/remote-next` 的公开入口及 transport、独立开发页。

1. 同时设计实际请求、完整响应、分页/有界读取事实、错误码和容量；基础取值与容量在 `values`，双端对象在 `model`，完整 HTTP 在 `http`，复杂纯解码在 `http-codec`。没有 WS 消费者就不创建 events。
2. 协议输入严格解码后，经 Remote mapper 转内部命令；输出经白名单转 Shared。操作状态、文件大小/截断事实及错误联合不能由前端自行猜测，后端私有资源 ID 与令牌的用途需明确。
3. Frontend transport 持有 HTTP、取消、响应解码和迟到响应处理；View 只消费能力与展示状态。先接独立开发入口，不提前替换正式 Workspace 文件管理器；中英日文案同步。
4. 管理员/会话权限与资源归属由 Access/Remote owner 保证，客户端不能自报 owner；公开错误不带路径、命令、私钥或底层 cause。

完成判据：一个开发消费者可以完成真实 list/stat/读取，Shared 唯一定义双端字段与预算；无私有类型跨模块引用及无断言代替验证。

### N4：静态交付与剩余验收

按修改范围执行 Shared/backend-next check、根 check、Shared/backend-next/frontend build、format 与 diff 检查。不要重复执行已通过的检查来代替设计审核；不新增自定义架构扫描门禁或源码字符串测试。

```bash
pnpm --filter @nexus-terminal/shared check
pnpm --filter @nexus-terminal/backend-next check
pnpm run check
pnpm --filter @nexus-terminal/backend-next build
pnpm --filter @nexus-terminal/frontend build
pnpm run format:all:check
git diff --check
```

当前未运行行为验证，保留以下验收缺口，用户要求验收时使用现有专项入口并按真实风险补强：

- 协议阶段：HTTP 来源/代理/输入 4xx、认证竞态与登录 429/403、Targets CAS/引用/部分导入、Host Key 信任拒绝、Remote 大输出/ACK/EOF/断线/重复释放/浏览器生命周期、Agent scope/幂等。
- 本批新增：解析期间配置变化、跳板/代理/凭据指纹变化；文件读取期间断线/撤销/取消/超限、符号链接与真实路径语义、资源重复释放和与 PTY 独立关闭、前端过期请求不覆盖新目录。

源码完成、静态通过和真实行为验收分别记录，不把新增断言或编译通过写成 E2E PASS。完成后更新 USAGE/Backend/AGENTS 中实际改变的长期事实，删除本文件已完成任务，仅保留下一批事项。创建本地提交，推送等待明确指令。
