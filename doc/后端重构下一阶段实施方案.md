## 阶段规划（可擦写区域）

### 基线与后端完成标准

当前基线为已提交的 Shared Agent 六接口、Access/Targets 业务规则边界、Remote 清理改动和开发规则整理。静态检查与隔离回归证据见 [E2E 检查点](testing/E2E.md#2026-10-10-重构检查点)。已有 Agent 仅实现状态持久化，不具备 Provider/执行/工具链；Remote 仅有终端与只读 Files。当前后端尚未完成。

后端 **100%** 必须同时满足：

1. 盘点旧后端实际安装的 HTTP/WS、后台任务和持久化能力，形成逐项迁移清单；正常产品结果保留，历史异常和无产品依据的补丁可重新设计。删减正常功能必须有明确决定，不凭 TODO 或类型声明视为完成。
2. 所有保留功能在新后端具有真实实现、安装入口、授权、Shared 通信契约及可执行的后端协议消费者/fixture；没有未实现的必需基础能力或关键 TODO。
3. H-04–H-08 与对应架构成立，适用静态检查和逻辑回归通过，迁移与生命周期方案完整。
4. 最后集中执行后端部署、真实 SSH/SFTP、桌面及 Agent 外部依赖、存储故障和跨模块链路验收，已知失败全部关闭。前端页面尚未迁移不能阻挡可独立执行的后端验收，也不能伪报浏览器通过。

完成后端源码不等于通过最终环境验收；完成后端验收也不等于整个产品或前端已经迁移。百分比不按文件数或 build 通过估算。

### 当前阶段 B1：Remote 有界文件写入与编辑

**状态：待实施。** 本批只完成文件文本写入及基础文件操作，承接已有只读 Files；不实现上传下载任务、批量传输、挂起恢复、RDP/VNC、Agent Provider 或前端界面。

#### A. 功能盘点与契约决策

- 从旧后端文件 HTTP、SFTP 实现和 USAGE 文件管理章节核对文本保存、新建、重命名、删除及目录操作；同时核对旧 Agent SSH 文件工具如何消费同类能力。
- 在本文记录“旧入口/正常语义 → 新 owner/入口 → Shared 契约 → 后端消费者 → 回归用例 → 状态”表。先明确路径、UTF-8/完整 JSON 容量、覆盖方式、符号链接策略、超时、冲突和失败结果，再实现。
- 文本写入明确是否采用临时同目录文件再替换、允许何种覆盖和条件检查。写前 hash/metadata 检查只能提供尽力冲突检测；SSH/SFTP 不具备原子 compare-and-swap 时，禁止宣称绝对避免并发覆盖。若产品要求强保证而底层无法提供，列为待决定，不包装为已完成。
- 不预建 Agent 文件工具或第二套技术底座。通用 SFTP 事实能力归 Platform；用户会话和 Agent 后续执行各有授权、身份及资源 owner。

#### B. 从底层到应用实现

| owner                                                                           | 具体步骤                                                                                                   | 完成判据                                                                                           |
| ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `platform/ssh/ssh-port.ts` 与 `adapters/ssh2/ssh-sftp.ts`                       | 核对已有 write/rename/remove/mkdir/rmdir 的流完成、容量、取消及晚到失败语义；只补实际必要的窄技术能力。    | 不出现 Connection/Run/User 等业务类型；区分尚未派发与结果未知；不把流关闭当作远端回滚。            |
| `modules/remote/files/model/file-types.ts`、`file-resource.ts`、`file-model.ts` | 增加内部命令/结果和应用资源方法；逐字段转换技术输入/输出，Machine/SFTP/Stream 私有持有；处理临时资源清理。 | Service 不取得技术句柄；一项清理失败不阻止其他清理；保留原始操作与清理失败因果。                   |
| `modules/remote/files/service/file-service.ts`                                  | 持有操作顺序、会话授权、目标指纹复查、输入规则、准入/期限、结果分类及关闭协调；复杂纯规则按需独立。        | 写入已派发后的超时、断线、取消可返回 unknown，不自动重试副作用；晚返回不覆盖新状态或提前释放名额。 |
| `modules/remote/public.ts`、实际公开 mapper                                     | 只公开真实后端消费者需要的安全能力；应用输入/输出保持白名单，不透传 storage/技术错误。                     | 后续 Agent 可复用技术能力，不借用普通用户会话权限；没有预留空 API。                                |
| `packages/shared/src/remote/files/{values,model,http,http-codec}.ts`            | 补共同取值、容量、安全错误、请求/成功联合及严格 codec，精确 export；与只读对象隔离写入命令。               | `unknown` 严格解码；双端表示只定义一份；不放本地 UI 状态或私有策略。                               |
| `modules/remote/interfaces/http`、`register.ts`                                 | 安装真实新路由，执行协议校验及安全响应投影；绑定 Access 身份与现有资源 owner。                             | 通过实际 HTTP fixture 消费新 Shared；错误状态、输入预算、权限和请求/响应关联可验证。               |

不得只做到接口占位。路径规则遵循远端文件系统语义，不默认套用本机路径处理；链接、临时文件、权限、替换保证按真实服务器能力说明。

#### C. 适用逻辑回归

优先扩充现有 Remote 集成结构，缺少文件 fixture 时按真实风险补最小专项，不能新建源码文本门禁。

- 写入正常 UTF-8 文本，回读验证内容；空文本、中文字节容量临界及超预算；非法编码/请求拒绝时确认未写入。
- 验证新建/覆盖/重命名/删除及目录操作的实际结果；符号链接策略、目标不存在、引用错误或权限拒绝不返回假成功。
- 身份不符、指纹变化、资源已关闭在派发前拒绝，确认副作用为零。
- 对派发前取消与派发后断线分别断言 not-started/unknown 语义；取消不自动重发，临时文件及资源清理有明确终态。
- 覆盖晚成功/晚拒绝、重复关闭、退订抛错后仍继续清理、多个清理失败聚合、准入名额不提前归还。
- 验证完整 HTTP 请求/Shared codec/Service/技术 fixture 调用链及失败投影。若场景暂时无法独立执行，记录缺口而不关闭 B1。
