### N0：现有边界收口

先完成以下四项，每项独立检查及本地提交。不要为了统一重新造全局 dispatcher、万能 mapper 或每个类一份空 port。

**N0.1：SQLite Worker 技术协议。** 位置：`platform/storage/sqlite/worker-types.ts`、`worker.ts`、`sqlite-runtime.ts`。

- 两侧 message 回调先接收 unknown；由技术 owner 解码完整请求/响应外壳，包括正安全整数 id、操作分支、SQL/绑定参数、value/error 分支及错误结构；成功的 null/void 语义保持明确。不能只把回调参数标成 WorkerRequest/WorkerResponse。
- 响应先校验再关联 pending；不可关联的损坏消息令实例不可用并拒绝全部等待者，避免异常从事件回调逸出或留下永久 pending。不得忽略非法外壳后继续使用可能失去事务对应关系的实例。
- `run` 结果检查 changes/lastId 的安全整数与允许范围，不直接信任从 bigint 转来的 Number；技术失败仍区分 sql、worker_exit、commit_unknown、rollback_failed。
- 保留 Worker 排他事务、tx 生命周期、数据库路径隔离和已有关闭顺序，不引入业务错误码或 Shared DTO。

**N0.2：内部类型与 Remote 内部依赖。** 位置：Access sessions 的 Model 类型文件、Access register、Remote sessions 的 Model/Service/register/interfaces。

- 会话签发输入命名并归入 `access/sessions/model/session-types.ts`；Access 的身份出口 mapper 接收 AuthenticatedIdentity，不复制匿名结构类型。仅类型用途的依赖使用 import type。
- RemoteSessionOwner 的输入/结果采用 `session-types.ts` 的内部应用契约；register 注入内部 session 用例的窄能力，Owner 不借 publicApi 做同模块内部调用。实现可采用 Model 中的应用能力契约或对真实 Service 的窄类型引用，不新建只转发的 Service。
- 后端 Remote public、HTTP 与内部对象仍分别执行白名单映射；公开 close reason 的既定 owner 不移动回私有类型。安全错误映射只在真正出口执行，私有清理失败先保存诊断证据，不能因内部先经过 public 包装而丢失技术原因。
- Owner 追踪完整 open 流程，包含第二次认证与资源登记；每次授权 await 后再检查准入和 owner/generation。停机、认证失效、取消与晚到成功必须关闭已取得的资源，不得在 quiesce 后留下新 owner。

**N0.3：Targets 重复规则与映射。** 位置：`targets/public-mappers.ts`、register、proxies 的 Model 校验与 import Service。

- Host Key 的内部→public 投影提取为同一个具名 mapper，list/confirm 复用；HTTP public→wire 投影仍是另一个真实边界，不能一起删除。
- Proxy 的基础字段验证及规范化由 Proxy 内部 Model 的纯规则 owner 统一，管理与 inline import 同向调用；仅共用同语义字段，密码加密和导入事务决策留原 owner。明确 name/host 的 trim，避免相同输入因入口不同存成不同事实。
- 多处重复的 Targets 正整数 id/version 校验提升到模块纯规则 owner；图深度/数量、协议容量与特定字段校验各留真实 owner，不汇入大 utils。
- 不合并应用/存储/public/HTTP 的安全转换；不能用通用属性复制代替白名单。只删除同一边界的真实重复。

**N0.4：PTY 协议职责。** 位置：`remote/interfaces/http/remote-http.ts` 与新增的同目录 PTY stream owner。

- HTTP 路由/输入输出留 HTTP owner；WS 安装及连接流控按独立职责拆分，ACK、输出队列、EOF 收敛和订阅清理集中在一个协议 stream owner，不迁 Platform 或 Session Service。
- 用明确终态或少量互斥状态替代含义重叠的结束标志；ACK 字节信用、输入背压与发送任务标志是不同事实，不能机械合并为单一状态。
- 保留权限复查、正常 EOF 的已读输出排空、断线/清理失败、安全错误、完成关闭 Promise 和有界缓存。await 后复查终态，避免关闭后继续操作已退役资源。文件 HTTP 不再追加进 PTY 路由文件。

完成判据：复用应用命令有唯一类型 owner；内部业务路径不依赖本模块 public 安全包装；Worker 完整外壳有运行时解码；Targets 相同规则/投影只有一个 owner；PTY 协议拆分后责任明确。

### N1：Targets 同快照解析与指纹核对

位置：`targets/public.ts`、resolver 的 Service/Model/storage/SQLite Adapter、public mapper、所有解析消费者。

1. 增加具名后端公开解析请求，包含 targetId、可选 expectedFingerprint；逐字段转换为 resolver 内部请求，不把 Run/权限/审批放入 Targets 或 Platform。
2. 复用现有 `SqliteSshTargetStorage.get` 单事务快照读取目标、凭据、代理和全部跳板；这部分已存在，不能当成尚未实现重建。Model 根据这同一份事实计算 fingerprint，核对 expectedFingerprint 后才解密/返回可信结果。配置变化明确返回安全冲突类别，不返回明文、SQL 或 destination 诊断。
3. 不能先调用 fingerprintStored 再 resolveStored 来证明快照一致。盘点真实调用者后，保留确有独立展示/检测用途的 fingerprint 能力；无消费者方法删除，不建立兼容别名。
4. Remote 和后续 Agent 都使用该窄解析能力；Targets 不获得 Agent grant、用户 PTY 或调度生命周期。
5. HTTP 解码与后端可信请求分离，expectedFingerprint 是后端冻结核对能力，不自动允许普通浏览器自报 Agent 授权。精确限制 fingerprint 表示并同步相关错误/消费者；保留测试源码消费者的可编译引用，不新增或运行测试。
6. 明确保证仅是此次解析结果与预期配置一致，不是配置永久锁定，也不是后续 SSH 建连期间不可变化。文件资源创建时绑定该结果；后续操作复查配置，不静默换机器。Host Key 信任是独立事实：沿用显式信任和用途边界，不宣称 target fingerprint 覆盖独立信任撤销。

完成判据：一次解析可以证明返回机器目标与核对指纹来自同一次快照；公开类型不引用私有应用类型；没有先比较后重新读取的窗口。

### N2.1：SFTP 技术读取保证

位置：`platform/ssh/ssh-port.ts` 与 `adapters/ssh2/ssh-sftp.ts`，实际消费者同步迁移。

1. 通用 list 增加明确技术预算（条目数与 metadata 字节），在读取过程中限制。现有 `sftp.readdir(path)` 会先积累完整目录，再截断无效；采用 opendir/分批 readdir(handle)/close(handle) 或等价的真正有界实现。超过限制明确返回技术超限失败，本批不把部分列表伪装完整目录，也不造无持久快照保证的分页 cursor。
2. read 的 start/end 校验为非负安全整数、end ≥ start，说明 end 是否包含末字节；技术期限贯穿完整操作，不能每读一批重置。文本用例按实际消费累计 bytes，stat 预检不能代替读取时预算。
3. 第三方文件 metadata 与 entry 在技术边界验证后投影：尺寸、mode、mtime 的表示/范围，文件种类及文件名；不靠 Stats 的 TypeScript 注解证明有效，不返回 SSH2 对象。metadata 不可信时明确失败。
4. 目录 handle、读流、lease、machine 各有关闭责任；正常结束、取消、超时、断线、超限及晚到回调都清理。保留派发前失败/派发后 unknown；关闭的本地保证与远端保证分别说明。当前写能力不扩展成功语义、不提前实施文件写入。
5. 上限属于纯技术执行参数与硬限制；模块传入产品预算。只有双端实际消费的产品额度放 Shared，Agent 自有授权及预算不进入 Platform。

完成判据：不全量累积目录或文件再截断；所有外部 metadata/range 有真实验证；读取终态及资源清理可从接口和实现直接追踪，后续 Agent 能使用同一技术能力而不依赖用户 Session。

### N2.2：Remote 文件应用资源与只读用例

位置：`modules/remote/files/{model,service}`、Remote register、公有能力，按真实持久化需要才增加 storage。

1. 盘点旧文件 list/stat/文本读取消费者、路径表示、排序与界面限制；遵守现行路径规则，不假定“SSH 文件管理器必须锁定项目目录”。Agent 项目目录授权是独立能力，不能直接套普通用户会话权限。
2. 建立 `model/file-types.ts` 的内部路径命令、文件记录、读取结果及资源类型。Model 只取得 Targets 可信解析和 Platform SSH/SFTP，逐字段转换技术目标/结果；Service 不接触 SSH2、Node Stream 或 SqlExecutor。
3. 为普通用户定义 Remote 自有文件资源 owner，绑定 Access 会话、目标 ID/指纹、准入、期限、并发、闲置回收与关闭。本批使用独立 machine/SFTP lease，不复用 PTY、不引入连接池；创建者拥有关闭责任。共享会话权限原则不等于复制 PTY owner 的可变状态，也不让文件借用者关闭共享技术实例。
4. 实现目录列表、stat 与有界文本读取；源记录解码、symlink 信息、编码/二进制识别、内容大小和取消由明确 owner 负责。下载流与全量目录分页的支持方式须根据真实消费者制定，不以截断数据伪装完整结果。
5. 接入 N2.1 的真实有界技术能力。Agent 后续文件能力复用技术接口，保留自己的 grant/inspection/冻结目标与资源管理，不调用普通用户文件会话；不要为了未来消费者本批预建 Agent 文件 Service。
6. 操作前取得服务端身份并验证文件资源绑定；await 后复查关闭/撤销/配置变化，关闭取消所有进行中读任务并等待清理。整个建连/读取操作有单一 deadline，迟到结果不能写回已关闭资源。
7. 本批读取完整的有界目录与有界 UTF-8 文本，超限或不支持编码/二进制返回安全具名类别；不返回替换字符假装有效文本、不静默截断。stat 和 lstat 的跟随链接语义分别明确，symlink 不伪装普通文件；目录排序由 Remote 决定，mtime 从技术秒数明确转换为应用/共享单位。
8. sessions/files 已有两个真实消费者后，Remote 内相同的可信目标→MachineEndpoint 映射及显式 Host Key 策略提取到模块共用的 Model owner，两个功能同向消费，文件 Model 不导入 Session Service 或其实现文件。该内部 helper 不向 Agent 暴露；Agent 的技术转换由自己的 Model 持有，不能为消除相似代码让 Platform 接收 Targets 对象。每跳及终点仍验证人工确认 pin，不恢复 TOFU/accept-all。

完成判据：真实数据读取而非假内容；失败、取消、超时、断线和晚到资源均有关闭责任；内部应用结果不含第三方句柄或凭据。

### N3：Shared 文件协议与独立开发消费者

位置：`shared/remote/files` 精确 exports、Remote interfaces、Frontend `runtimes/remote-next` 的公开入口及 transport、独立开发页。

1. 同时设计实际请求、完整响应、分页/有界读取事实、错误码和容量；基础取值与容量在 `values`，双端对象在 `model`，完整 HTTP 在 `http`，复杂纯解码在 `http-codec`。没有 WS 消费者就不创建 events。
2. 协议输入严格解码后，经 Remote mapper 转内部命令；输出经白名单转 Shared。操作状态、文件大小/截断事实及错误联合不能由前端自行猜测，后端私有资源 ID 与令牌的用途需明确。
3. Frontend transport 持有 HTTP、取消、响应解码和迟到响应处理；View 只消费能力与展示状态。先接独立开发入口，不提前替换正式 Workspace 文件管理器；中英日文案同步。
4. 管理员/会话权限与资源归属由 Access/Remote owner 保证，客户端不能自报 owner；公开错误不带路径、命令、私钥或底层 cause。
5. 最小接口覆盖创建文件资源、关闭资源、list、stat/lstat、readText。HTTP 位置在 Remote files 自有接口 owner，URL/path/query/body 的未知及重复字段规则明确；正文路径使用实际解码后的字符串，不混淆 URL 路径编码和远端路径。沿用 HttpOnly Access cookie，不发明文件 bearer 或下载 ticket。
6. 开发页支持选目标、开/关文件资源、目录导航、metadata 和文本查看、取消/错误/超限展示；每次切目标/路径或卸载取消旧请求，以 generation 防止迟到结果覆盖，主动释放资源。产品预算写入 files/values 并同时约束读取、完整响应 UTF-8 大小及前端解码；不能只限制原始文件字节而忽略 JSON 转义。
7. 先盘点旧普通文件管理的真实限制，在 USAGE 标明本批独立入口支持范围及明确限制；Agent 的读取额度不冒充普通文件预算。没有前端消费者的后端秘密、资源句柄和内部取消类型不共享。

完成判据：一个开发消费者可以完成真实 list/stat/读取，Shared 唯一定义双端字段与预算；无私有类型跨模块引用及无断言代替验证。
