# 后端重构下一阶段实施方案

当前工作先补齐已实现 Agent 状态切片的 Shared 与实际前端消费者，不在协议链缺失时宣称当前批次全部完成。开发前完整读取 [AGENTS](AGENTS.md) 所列入口；模块设计按 [模板](architecture/MODULE_TEMPLATE.md) 写入对应架构，产品行为每版维护 [USAGE](USAGE.md#每版产品行为维护)。下面各项均按实际完成状态维护，不代表已授权立即施工。

## 任务组织与阶段门禁

每阶段任务必须写目标、具体 owner、消费者、依赖、实现步骤、静态命令与行为判据。阶段中允许暂时不通过，阶段结束必须修复所有已知检查失败；明确环境阻断记录状态与证据，不能关闭该阶段或把依赖它的切片标为完成。

通用静态门禁：Backend-next check/build；Shared 变化执行 Shared check/build；双端变化执行 Frontend `vue-tsc --noEmit` 和 build；根 `pnpm run check`、`pnpm run format:all:check`、`git diff --check`。记录 SHA/工作区、命令、范围和退出结果，不以根 check 替代新后端检查。行为验证按当前授权实施，静态通过不关闭未执行的实机场景。

## S1 Agent 共享协议与真实消费者

**状态：待实施。依赖：现有 Agent scope/runs 状态 HTTP。** 仅迁移已经实现的有限切片，不预建 Provider、工具、审批或执行结果。

1. 盘点 `/api/v1/agent` 的 App 创建、Thread 创建、Run 创建/读取/取消、事件分页，列完整请求、响应、安全错误、operationKey header、版本、游标与容量；核对 `agent/public.ts`、HTTP、内部 Model、存储、测试和脚本消费者。
2. 增量建立 `packages/shared/src/agent/scope` 和 `agent/runs`：values 放基础状态/取值/安全码/真实协议容量，model 放双端对象，http 放完整请求响应及安全错误，确需复杂解码时新增 http-codec。分页事件目前通过 HTTP 返回，不为目录形状预建 events。Shared 不包含 userId 授权上下文、prompt 存储行、hash、技术错误或资源句柄。
3. 后端内部应用/存储类型保持独立；public 仅保留后端能力所需输入与结果，实际双端对象/基础值引用 Shared。HTTP 从 unknown 解码再白名单转换，内部结果分别经过公开和 HTTP 投影，不借相同字段直接透传。同步 Shared package exports，删除同义重复定义及无消费者兼容转导出。
4. 为新 Agent 状态切片接入独立开发消费者，在现有 `features/agent` 下按真实职责组织新 API/controller/view，先按 Frontend 模板明确安装位置；不接正式生产 API、不复用普通 PTY 授权。支持 App/Thread 创建、Run 创建/取消/读取、事件分页及错误展示，明确“尚不执行任务”。不为了有消费者塞入 Targets 业务模块。
5. 前端发送前按真实 UTF-8 body 预算检查，未知响应严格解码；幂等键重试规则、expectedVersion 冲突、事件游标和 generation 管理一致；界面翻译放所属 i18n owner。同步所有实际脚本/测试消费者，不新增以源码文本扫描代替架构审核的门禁。
6. 同版更新 USAGE 的开发入口、有限能力、失败/重放/版本语义与限制；同步 Backend/Frontend/Shared 的实际入口与已实现状态。

**静态完成判据：** 通用门禁全部退出 0，Shared exports 和双端 build 有效；架构审核确认类型 owner、协议/应用/存储转换和权限不偏移。**行为完成判据：** 实际开发消费者能操作有限状态、展示安全失败/重放/冲突及分页；不能只创建 Shared 文件就关闭该项。未执行浏览器与故障验证明确保留。

## S2 当前切片真实行为验收

**状态：待执行；与 S1 的源码施工分别判断。** 使用 [待实机验证](testing/后端重构待实机验证.md) 的实际场景，覆盖 Worker/事务未知结果、Targets 竞争、SSH/Host Key、PTY ACK/EOF、SFTP 限额/取消及 Files 晚到 resolve/reject 清理。补充 S1 的真实 Agent 状态消费者验证，不假定旧正式 Agent 的 E2E 覆盖新 API。

具体源码或消费者变更先重新执行适用静态门禁。专项记录实际 SHA、故障窗口和终态证据，失败回真实 owner 修复；未执行不能改为通过。当前未授权立即运行或新增测试，仅保留实施与验收要求。
