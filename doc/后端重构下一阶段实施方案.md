# 后端重构下一阶段实施方案

## 第二批施工状态（2026-10-09）

已写入数据库底座和 Targets 第二批源码。已在独立临时数据库中实际验证原来的 v1→v2 升级及迁移失败回滚，再按最新要求把**未发布的完整结构合并为唯一 v1 初始 Schema**；通用迁移机制保留作为日后已发布版本的升级基础，不在生产迁移清单中保留 v2。新包仍不监听 HTTP，旧 Backend 继续服务正式产品。

- **数据库与实例底座**：Platform 保留按编号的事务化 SchemaMigration 及固定签名校验；**当前唯一生产版本是 v1**。v1 初始安装一次创建连接、Proxy、Tag、SSH Key、连接密码/Key 引用和 Proxy 密文表，Proxy/Tag CAS 版本字段直接属于各自 v1 DDL，不由 ALTER TABLE v2 添加。业务 Schema 由对应 Targets 子功能持有，Bootstrap 配置加密密钥、启动顺序与关闭。旧的第一批开发数据库没有最新 v1 签名，启动明确拒绝，需重建独立开发库；不做隐藏的数据合并或假兼容。
- **Targets 管理**：Proxy、Tag、SSH Key 增加实际 Service → Model → 存储契约 → SQLite Adapter 的管理调用。Proxy/SSH Key 私密字段使用应用提供的 32 字节密钥和 AES-256-GCM 加密，公开读取只有 ID、名称、版本等非敏感元数据；无加密密钥时可读取公开元数据，但写入/解密凭据明确拒绝。连接密码和 SSH Key 引用有独立事务更新与 CAS，Proxy、Key、跳板引用受保护，标签被使用时不可删除。
- **SSH 目标解析**：Targets 内 `resolver` 使用同一次 SQLite 事务抓取连接、Proxy、SSH Key、密文与有序跳板链，拒绝循环/无凭据/丢失引用；指纹只包含实际 SSH 建连依赖：目标身份、主机/用户/端口/路由、密文与引用 Key/Proxy 的机器配置、跳板链顺序；不包含连接备注、标签、展示名称和普通 CAS 版本，避免无关 UI 更改误使运行会话失效。解密的机器连接配置仅经 Bootstrap 单独的 `trustedSshTargets` 能力提供，不进入 `targets` 的普通公开管理结果，不挂 HTTP/WS 路由。
- **Targets 出口边界**：`public.ts` 独立定义管理输入、视图和状态结果，既不导入也不再导出内部 `storage/` 类型。`public-mappers.ts` 显式建立输入与输出的逐字段允许清单，Connection 列表/详情/写入/导入、Proxy/Tag/SSH Key、凭据状态以及多条导入结果均通过此边界。`trustedSshTargets` 独立映射包含明文凭据的机器配置、Proxy 和递归跳板链，不复用 Resolver 对象。新增的内部字段不会被类型标注伪装成出口字段；对应 `backend-next-public-boundary.integration.mjs` 测试运行时字段排除、集合身份隔离和现有 API 调用。
- **应用/存储转换**：Proxy、SSH Key、Tag、连接凭据均使用独立应用类型，Model 显式转换命令、记录、列表与状态结果，Service 不引用存储类型。Connection/Import 与 Resolver 同样按字段清单转换；Resolver Model 只形成密文快照与指纹，解密已移至 Resolver Service，写入加密留在各 Service。
- **当前待收口边界**：模块错误结果仍可能包含底层错误正文；SQLite 回滚失败/关闭等待的生命周期契约、跳板图深度与祖先引用复验尚未补齐。具体证据与方向见[架构重构的当前边界](架构重构.md#当前仍需收口的边界)。本轮未运行集成测试，前面的执行结果仅是此前 Schema 合并时的记录，不证明本轮转换调整的运行行为。
- **尚未施工**：Access 认证及连接 HTTP/前端切换、Platform SSH/SFTP/远端执行、Remote 会话/传输与 Agent 持久状态提交（下面第 2 节第 3 点、以及第 3、4 节）。不创建假路由、虚假 SSH 连接结果或无生命周期 owner 的服务。

## 起点与待收口事项

第一版的代码范围已实现（其中以下说明描述第一版起点，并非第二批验收结果）：独立 `backend-next` 与 `shared`；应用实例独占的 SQLite Worker、参数绑定、显式排他事务、关闭与故障拒绝；Targets 内的 Connection Service → Model → 存储契约 → SQLite Adapter；连接元数据 CRUD、CAS、标签和跳板关系、跨 Proxy/Tag 的单条导入事务。`targets` 是当前唯一装配的业务顶层模块。旧 Backend 仍服务正式产品，新包不监听 HTTP，也不读取旧数据库。

第一版实施清单不再作为施工任务保留。第一批与第二批 SQLite 集成脚本在旧迁移清单阶段及新 v1 Schema 合并之后均已执行通过；完整的 Runtime 故障退出、事务误用和过期事务句柄反例，以及第二批进入正式应用前的授权、远程行为验证仍须独立完成，不把存储测试视为完整产品验收。

## 1. 先稳定数据库与应用实例底座

1. 已将只识别版本 1 的 Schema 初始化扩展为**按编号、签名校验、一次性和失败回滚的迁移机制**。本阶段仍只安装完整的 v1，测试时模拟 v2 不意味着已发布升级；正式新版本发布后再新增不可变迁移。Platform 管版本、执行顺序和事务；每个业务模块拥有自己的 DDL/数据迁移内容。明确迁移失败后的数据库状态与启动拒绝规则，避免以后直接改 `CREATE TABLE IF NOT EXISTS` 来冒充升级。
2. 保持 `SqliteRuntime` 只提供通用 SQL 执行、显式事务、故障与关闭能力。Worker 失效后所有新调用明确失败；不自动重放提交结果未知的写入。事务参与者只能使用收到的 `tx`，不能在回调中调用默认入口、嵌套事务或等待网络/用户交互。
3. Bootstrap 逐步形成应用实例生命周期 owner：初始化数据库与模块，最后开放请求；停机或恢复时先停止接纳新工作，收敛 Agent/Remote 的运行资源，最后关闭数据库。此阶段只建立必需的生命周期接口，不实现备份恢复或全量模块注册。

## 2. 补全 Targets，使 SSH 目标真正可解析

1. 在 `targets` 内增加 Proxy、Tag、SSH Key 的真实管理用例及存储契约；引入凭据加解密能力；由于新 Backend 尚未发布，所需结构直接并入 v1 初始 Schema，不保留为 v2 迁移。密文只进入后端存储，公开结果不得泄露；Proxy/Key/跳板的引用保护继续在写事务内复验。
2. 增加 SSH 目标解析和配置指纹：从连接定义、密钥、代理、显式跳板链生成一次连接所需的不可变配置；依赖变化必须改变指纹。RDP/VNC 的连接定义仍由 Targets 管，运行中的票据和会话归 Remote。
3. 首次接入连接 HTTP 时，同批迁移对应的前端模型、API 客户端及 `protocol` 消费者，补 `shared/connections|proxies|ssh-keys|tags` 中确实共用的 `values.ts`、`api.ts`。请求从 `unknown` 校验；旧 wire 的 `route: null` 与新内部的 `direct` 在 API 边界显式转换。认证接入之前不开放无保护的管理路由。

## 3. 建立供 SSH 应用与 Agent 共用的机器能力

Platform 提供业务无关的 SSH 连接工厂、Proxy/Jump 建连、命令通道、交互式 Shell、SFTP 文件句柄/流、取消、断连与资源关闭。其参数只描述机器连接和通道，不包含 Connection ID、Workspace ID、Agent Thread、grant 或审批类型。Targets 负责把业务配置转换为机器连接参数；Remote 和 Agent 分别决定何时建连、授权、保留及关闭自己的会话。

先用 Remote 的最小 SSH 终端会话纵向接入，确认断连、关闭、取消和终端输出资源的归属；再接入文件操作与 Transfer 的独立任务生命周期。Agent SSH 会话、后台 Job 复用机器能力，但其身份绑定、配置指纹复验、授权、未知结果和恢复规则留在 Agent。

## 4. 单独设计 Agent 持久状态提交后再迁移 Agent

Agent 模块内部按 Run/状态提交、会话与 Memory、Provider、Plugin、App Storage、协作及授权等真实 owner 定义存储契约；不在 Platform 添加 `agentRuns` 等业务槽位。第一批先完成 Run、审批、事件和幂等记录的一次原子提交，以及重启后的状态恢复，再扩展其他 Agent 能力。

当前 SQLite Platform 的 `transaction(tx)` 能承载事务内“读最新持久状态 → 判断 → 条件更新多表 → 提交”。Agent 模块应拥有状态决策和事务内存储参与者；SQLite Adapter 使用同一个显式 `tx` 执行 SQL，并在提交成功后才把事件交给 Agent 调度/通知。不能把一次状态转换拆成多个普通 CRUD 调用，也不能让 Model 直接拿到通用 `SqlExecutor`。若选择事务外预生成提交计划，必须额外证明 Run、Thread、App、审批、子任务及幂等记录的版本条件完整；当前不把该候选方案作为默认实施前提。

## 本轮字段与能力边界判断

- **Connection 公共元数据**：保留 SSH/RDP/VNC 共用的主机、用户、路由、标签、跳板关系；RemoteApp 别名、目录、参数属于 _RDP 专用_ 配置，Service 与数据库 CHECK 禁止 SSH/VNC 携带。跳板关系保持有序独立表而非存储 JSON 字符串。
- **密钥/Proxy/认证**：SSH Key 是可复用的密钥资源，不重复复制其明文到每条连接；连接认证单独引用 Key 或使用加密密码；Proxy 密码单独加密存储。SSH Key/Proxy 仅提供当前用例所需的管理操作，不搬运旧表中的 Proxy 私钥、任意 `auth_method='key'` 或与现行机器连接技术不匹配的字段。
- **类型和数据归属**：普通连接快照不携带密文字段；密文仅限存储与可信解析路径，Proxy 创建服务首先剥离明文密码再传给 Model/存储，防止动态对象展开导致意外跨层传播。连接、Key、Proxy 各有自己事务写入和 CAS，Import 只负责同一条记录的 Proxy/Tag/Connection 组合提交；不把所有子功能并成巨型 Service。
- **SSH 指纹**：展示名、备注、标签、CAS 版本和更新时间不构成真实机器配置，不因此改变指纹；主机、账号、密文、代理配置、跳板顺序等改变必须改变。连接克隆需原子保留认证引用或密文配置，不能只复制可见字段导致克隆不可连接。
- **目前不应迁移的内容**：运行中 SSH、SFTP、RDP/VNC ticket、文件/传输任务、Agent Run/审批、HTTP/认证、审计通知和正式备份恢复，仍由后续真实 owner 实现；不新增模拟执行结果或开放无认证管理路由。
