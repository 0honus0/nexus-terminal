### 文件管理器目录切换优化（2026-10-21）

按用户随后提出的更长缓存要求，默认TTL为5分钟，从列表成功取得时计算，不因访问无限续期；刷新、写入/传输变化及不可用仍提前失效。前端TTL回归使用浏览器时钟跨过两分钟及五分钟边界，网络与SFTP仍为真实链路，不增加CI五分钟实等；此前Workspace闲置125秒用例保持真实等待，二者不混为相同证据。

本批按用户要求优化目录浏览，遵守 H-04–H-09、H-13、E-05、E-07、E-08、E-10：保留既有布局和操作，新增会话内有界短期目录快照、同路径在途合并及悬停/键盘定位目录预读；不改后端协议、不缓存文件正文、不持久化目录、不把快照当操作授权。D17 本地仅静态，延续上一轮授权补充远程 E2E；用户随后明确授权提交与推送本批修改，不额外触发远程任务。

### 文件管理器现场反馈修复（2026-10-21）

范围为 HTML/文本打开、目录 ZIP 下载及频繁操作拒绝，依据 H-04–H-09、H-13、E-03.3、E-05.3、E-06、E-10、E-13，对照 `75289ef9^` 的正式 Files、编辑器及下载实现；保留当前未提交修改。沿现有 owner 修复，不恢复旧协议或调整布局。

补充根因：owned 与 runAdmitted 原先将独立 HTTP Files 的两分钟 idle TTL 同时施加到 Workspace，而定时回收已正确排除 Workspace。已将两处准入统一为只检查独立资源过期；Workspace 继续按原 SSH 生命周期、身份和指纹授权。该缺陷会使闲置后的 HTML 读取拒绝再落入通用错误边界，同时令目录下载 not_found。待远程覆盖闲置超过两分钟后列目录、打开 HTML、修改文件、申请票据及目录下载，以及独立资源仍按原 TTL 拒绝；具体现场文件仍未复现，不据此推断 HTML 语言组件本身存在缺陷。
