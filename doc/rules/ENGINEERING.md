# AI 工程经验规则

本文只维护经确认并提炼的共性开发规则。具体缺陷、模块修复清单、阶段状态、交接沟通和检查日志分别归当前实施方案或验证文档。开发前完整读取；与 [人工规则](HUMAN.md) 冲突时修正本文，不修改人工条目。

## 规则列表

主规则使用 E-xx，细则使用 E-xx.n；细则归属主规则，不另起重复主规则。编号保持稳定，新项顺序追加，删除后不复用；引用使用完整编号。

| E-01 | 分层与应用资源   | 技术句柄封装于技术转换边界，业务层只取得应用能力及明确的资源生命周期。                              | 沿返回对象核对字段、可调用能力及创建/关闭 owner，不能只看目录。                                                                       | 技术资源穿透业务边界。                                                     |
| E-02 | 类型与能力归属   | 复用类型和能力由真实业务 owner 唯一定义，低层不反向引用上层实现，公开契约不借用私有类型。           | 追踪定义、全部消费者和依赖方向；跨功能复用经所属 owner 的公开入口。                                                                   | 类型反向依赖、共用能力误放与重复定义。                                     |

| E-06 | 错误与清理       | 错误使用具名类别和受约束 code，未知异常安全兜底；一项清理失败仍执行其余清理，多项失败保留全部因果。 | 沿完整调用链核对错误映射，禁止比较错误正文；检查早退、退订、释放和关闭路径。                                                          | 文本驱动业务判断、技术正文外泄、清理中断或虚报成功。                       |
| E-07 | 状态与竞态       | 异步返回后复查权威状态、身份及操作有效性，失效结果不得发布或覆盖新任务状态。                        | 核对每个 await 后的版本/generation/终态保护，包含旧 finally 和取消后的返回。                                                          | 晚结果覆盖新状态、通过断言或放宽类型删除必要保护。                         |
| E-08 | 共享取值与容量   | 同义同表示的双端取值及协议容量归 Shared；私有配额、缓存和清理策略留实际 owner。                     | 核对语义和真实消费者，区分原始数据、完整编码预算、route 显式预算与 Platform 技术硬上限；技术上限须容纳已授权 route 但不替代业务限额。 | 重复协议定义、只算字段长度、route 预算超过技术上限、将私有策略无依据共享。 |
| E-09 | 封装与转换       | 跨边界保留白名单转换，同一边界只有一个转换 owner；封装和复用必须有契约价值。                        | 核对输入/输出、联合分支和嵌套字段，删除重复转换及无消费者包装。                                                                       | 边界透传、重复 mapper、万能组件和机械拆层。                                |
| E-10 | 阶段完成与证据   | 源码实现、架构符合、静态检查、逻辑回归和实机验收分别判断；报告不替代源码与实际执行证据。            | 对照当前工作区、检查命令/环境/输出及未覆盖范围，已知失败本阶段修复。                                                                  | 复用历史 PASS、混合不同环境证据、将源码缺口推迟为验收任务。                |
| E-11 | 副作用与未知结果 | 本地取消、连接关闭或响应失败不证明远端停止或写入回滚；幂等写入结果未知时保留原意图与键。            | 区分未派发、确定结果和未知结果，核对重试及恢复是否会重复副作用。                                                                      | 自动换键重试、把预检查或本地清理当作远端原子性保证。                       |
| E-12 | 产品文档         | 行为变更同版维护 USAGE 对应功能章节；纯内部重构核对原说明，保留仍真实的产品约束。                   | 对照操作、权限、容量、输入输出及失败恢复，不以架构或变更日志替代使用说明。                                                            | 文档与真实产品脱节、精简时误删有效行为。                                   |
| E-13 | 响应与请求关联   | 响应解码同时验证字段形状与请求上下文；正确形状不代表属于本次操作。                                  | 在持有上下文的边界核对资源身份、范围、允许状态及分页语义，再发布应用状态。                                                            | 接收错误资源、非法状态组合、游标倒退或超出请求范围。                       |
| E-14 | 规则维护         | 已确认经验先提炼为长期共性约束，再按唯一 owner 和稳定编号维护；具体任务不进入规则。                 | 核对事实、适用范围和可复用性，引用规则展开任务，工程演进时修正失效条目。                                                              | 把临时沟通或修复清单写成永久规则、重复规则或随意重编号。                   |

## 通信迁移完整性检查

**E-03.1**（关联 E-02/E-08/E-09）：从真实安装的通信入口建立“契约—生产者—消费者”清单，覆盖请求、成功联合、安全失败、基础值、容量和包出口；同一路径的各媒体类型及保存/未保存用例分别核对，不能用其中一条成功链代表全部能力。多个入口复用同一底层执行时，沿每个真实入口身份核对准入、嵌套授权、父子关联及最终消费；不能只接通执行转换而遗漏持久权限检查，也不能用入口等价代替逐次授权。入口盘点同时核对部署健康探针及运维脚本的真实路径、身份要求和成功判据，不能只按业务 UI 收集。检查所有消费者及转换 owner；没有新消费者的能力明确列缺口，不解释为无需迁移。模型或内部调用入口与人工管理、查询、配置入口分别盘点；核心执行链完成不能代替管理功能完成。盘点还须覆盖配置在其他入口的实际消费者、包内嵌资源的实际运行读取、嵌入式 SDK/RPC、静态内容及跨功能数据引用，不能只按同名模块路由收集；资源已存储或可备份不证明有实际业务消费者。交付可执行模块时核对整个运行时import依赖图及实际地址，不能只提供入口文件；协议和纯编解码可共享，窗口、进程、连接和计时器仍归实际运行/交付owner。观察接口必须与业务读取/确认动作分开，安全投影不能暗中推进消费或授权状态。共用能力先归所属业务 owner，再通过窄公开入口复用，不跨功能引用私有实现或复制一份。整页迁移须核对嵌入功能的真实契约依赖；独立功能延期不能掩盖当前页面已消费链路的缺口，局部错误隔离也不代表该链路已完成迁移。 验证入口迁移同时核对实际启动包、基线数据、依赖缓存和构建指纹；旧运行时或旧数据库种子不能作为新实现的验收基线，受控夹具不默认依赖公网。

**E-03.2**：自动接口文档以真实安装路由关联的协议契约为来源，明确方法、完整路径、参数位置、成功/失败响应、状态码、认证及容量；类型、运行时 schema 和文档不得成为互不关联的多份定义。通用汇总层不引入业务类型；HTTP 与事件通道分别表达。schema 的字段限制不能代替编码字节预算、授权执行或业务规则。认证、审计等路由包装显式保留完整传输元数据，包含正文/路径预算、参数字母表及读取方法的取消参数；核对最终安装的路由，不只核对原定义，防止包装静默恢复默认限制。路径参数的解码字母表与字节预算须容纳实际生产者的合法名称，并与协议校验一致；codec 接受输入不能代替最终路由可达性核验。

## 能力与目录审核

**E-01.1**（关联 H-06、E-06.2/E-09）：Model 转换边界同时持有技术调用、资源能力和失败转换；失败转换须覆盖命令构造中的同步技术调用，不能只处理返回 Promise 的拒绝；只有字段 mapper、但 Service 仍接收原始句柄或直接调用 Port，不构成完整边界。沿实际调用与关闭链核对，Service 只取得实例绑定的应用能力，不能用新增包装文件替代边界隔离。Platform 的 Port 是通用技术契约，允许由 Model 消费和 Adapter 实现；审核判断其字段、依赖和实际调用，而非依据文件名。应用事实及纯规则不能夹带第三方实例，Model 还须把技术失败转为应用失败，不延迟到公开出口。秘密加解密同属技术表示转换，业务校验与保留/清空意图仍归应用规则；迁移调用时同步删除失去用途的中间表示和旧安装依赖。 技术配置的作用范围也须限定于实际持有的资源实例，不能以局部释放能力掩盖对共享宿主或其他实例的配置副作用。扩展第三方生命周期时核对原有同名方法及全部实际加载产物，不能覆盖协议操作来增加资源释放。

**E-01.2**（关联 E-02/E-04/E-08/E-09）：层级审核同时追踪判断与表示转换。用例允许范围、期限、配额及恢复政策归 Service 或所属纯规则，Model 接收明确应用命令并转换技术/存储能力，不自行选择业务政策。默认值、资格选择、缓存失效、删除准入、别名冲突和损坏数据恢复属于应用决策，按职责放在Service或纯规则；Model只转换下层事实和明确应用命令。协议时间单位及编码表示只在通信边界转换，第三方表示只在技术 Adapter 处理；产品名称、显示标签和应用默认值由应用传入通用技术能力。技术硬上限仍归技术 owner，不因其是数字就移入 Shared。

**E-02.2**：目录按真实业务 owner 和消费者范围组织。多个子功能共用的转换与资源能力须明确所属子功能及允许依赖，不能因共用而直接放入技术底层，或藏入无明确职责的根级目录；也不为符合目录形式创建空 Service、Storage 或包装层。

**E-09.1**：公开能力以真实运行时消费者为依据；仅供测试方便或重复表达同一操作的出口不自动保留。合并能力前核对授权、校验、事务、副作用、版本及失败语义，再同步全部消费者。内部实现可以复用而不扩大公开能力；语义不同的操作不得仅凭字段或调用相似合并。秘密在所需转换或技术调用完成后，不随完整上游对象继续返回；后续消费者只需资源身份或摘要时，定义独立窄结果并逐字段投影，同时核对嵌套字段和全部消费者。

**E-09.2**：类型别名若明确表达模块语境可以保留，别名不复制同义字段定义。固定取值字段是否冗余应结合完整响应联合、协议意图与消费者判断，不能仅凭当前恒定值删除；白名单边界转换仍按 H-06 保留。

**E-09.3**：协议适配留实际通信边界，用例以业务语义命名，不以新旧版本标签重复维护应用流程。复用前确认输入前提、副作用、错误与生命周期等价；不同政策保留明确用例，相同机制只保留一个 owner。保留参考实现不等于新增兼容桥接；真实消费者迁移才可声明共享契约已接通。校验或规范化返回新命令时，实际执行必须消费该返回值，不能验证规范值后仍写入原输入。

**E-09.4**（关联 E-08/E-09）：可编辑数值的展示与解析须可精确往返，单位缩写不能改变原值，不以静默舍入满足整数契约。无效草稿保留明确的无效状态并阻止派发，不能回退到旧有效值后继续保存；拆分控件、分类或确认步骤时，校验状态仍归同一编辑 owner。

**E-05.1**：资源交付同时明确内部 owner 的窄释放能力；异步获取成功后的取消或终态复查失败，仍由原 owner 使用绑定能力收尾，不能先丢弃取得的资源；会话撤销或取消不能阻止已获资源的清理。外部按 ID 操作仍认证，内部关闭绑定具体已授权实例，不开放任意资源的无认证入口；并发关闭共享结果，失败与晚到任务由原 owner 追踪。

**E-13.2**：流式读取分别定义容量上限、实际范围与内容一致性。消费前按应用事实确定允许范围，底层按范围执行；新增数据不默默扩张读取，空范围不产生无界流，也不能跳过当前身份、资源版本及交付条件的检查；短读和超量都保留失败。固定范围不能解释为内容快照，生命周期约束覆盖流获取、消费和提前终止。

## 授权与异步复查

**E-07.1**：同一入场阶段的身份认证与授权由明确 owner 执行，上下层不重复查询同一权威状态。协议解码、资源归属和业务权限仍各有职责；跨异步建连、资源交付、敏感操作或会话撤销窗口时，按实际风险复查权威身份及操作有效性。去重不能删除这些时间边界上的安全检查，也不能把原应传播的认证或存储失败降为资源不存在。明确每次复查所在时间边界及保证：正文读取后复查不替代排队后的事务准入；未安装实际事务校验时，文档和验收不得宣称身份撤销与写入原子排序。批处理中身份或权限失效终止后续写入，不降为普通单项失败继续；此前已提交项与当前拒绝分别表达。独立数据通道与控制通道共享实际业务 owner 的当前权限，周期清理扫描不能替代派发、排队后及分块交付前的有效性检查；绑定原实例，不凭可复用名称重新取权。权限失效仍执行原资源清理，已派发效果和清理未知分别保留。

**E-07.2**：文件路径规范化不能省略真实路径遍历的前提；检查原始路径实际经过的中间节点，再验证规范路径与允许范围。含父目录跳转的路径不能仅凭最终字符串位于范围内就放行。类型/规范路径复查只证明检查时的事实，不冒充跨系统调用的原子隔离。

**E-07.7**（关联 E-04.2/E-07/E-11）：授权绑定具体操作内容的独立修订，不借用父聚合的生命周期版本；可复用名称/路径删除重建后，旧修订不得命中新实例，采用稳定实例身份或持久单调修订，不从初值重置并接受旧 CAS。明确数据清除同时定义正文、历史结果正文及防重放元数据的处置，推进原授权修订；清除不能复活旧写意图，保留的操作证据和墓碑也须有容量约束。内容变化与状态变化分别表达。单调版本在递增前核对表示上限，批量和级联写入同样拒绝耗尽，不能先提交再依赖结果解码发现越界。多阶段副作用在准入时预留必要结算的全部递增空间，不能完成外部操作后才发现无法持久收口。同一幂等身份须核对绑定内容一致，不能只比较调用方提供的摘要或哈希。持有历史批准或重放决议不等于当前执行许可；在实际消费事务复查当前事实、期限及未消费状态，并将许可 CAS 与唯一派发意图原子提交。许可类型只授权其绑定的操作，不替代父/子操作的授权；跨资源授予同时登记真实资源owner的删除保护，撤销/期限与流式交付lease分别追踪，返回描述不代替实际读取时的授权复查；数据库提交未知时不得派发。父聚合终态、关联操作围栏与事件在同一持久事务收口；恢复须覆盖每类真实副作用账本，不能只检查其中一类。未确认的子操作阻止父聚合报成功，晚结果不能覆盖既有围栏。外部可复用的调用标识须绑定真实步骤，不假定在整个聚合内唯一；子步骤完成与聚合完成分别定义，跨步骤本地拒绝同样要收口聚合。目标选择只缩窄作用范围，不代替权限授予。 关联任务继续执行与父最终成功分别校验；子任务未完成只阻断需要其完成的父阶段，不能误阻断正常中间步骤。任务终态同时核对其可交付结果和真实资源收敛，单个账本的 completed 不代表整组任务已释放。

## 业务规则与事务检查

**E-04.1**（关联 E-02/E-09）：区分行解码、引用完整性和版本检查与业务政策；依赖方向正确不代表职责分离。业务规则只消费应用事实，Model 持有应用/存储转换，Adapter 执行 SQL 和事务。持久事件与当前快照的读取在同一事务核对范围、应有数量、顺序及末项对应关系；逐行形状合法不代表历史完整或与当前事实一致，损坏不能作为正常空页或旧状态返回。 历史与恢复投影保留失败、取消、未知状态及证据缺失，不只选择成功记录或把缺失结果补成成功。内容哈希不能代替实际持久内容；来源版本须覆盖被引用事实的变化，修改关联账本时原子推进该版本。跨owner快照明确登记覆盖集及排除理由，核对完整表列、嵌套引用与实际内容；结构新增但注册未同步时拒绝采集，不以筛选已知列或只验证记录hash冒充完整覆盖。恢复预检同时复用真实持久解码器、跨表读取和规则转换，校验候选数据的数据库约束；结构/hash/外键合法不能代替应用不变量或受信声明核对。预检使用隔离资源与目标实例的受信身份，不能从载荷导入目标认证事实。全量校验按批构建关联索引或关系图，不为每条记录重复重建全量集合或逐项扫描全集；路径校验同时索引祖先关系，保留重复、文件/目录冲突和嵌套归属检查。跨存储恢复用同事务提交证据决定保留或回滚文件，提交异常不能代替证据；恢复日志须在业务 owner 初始化前对账。持久数据恢复与任务执行恢复分别定义，不能因常规启动会派发队列或扩展入口而在恢复初始化中重放历史副作用。

**E-04.2**：需要最新事实的业务判断通过存储契约中的窄同步回调在原事务内执行；回调签名仅使用 storage 类型；Model 在回调内转换为应用事实、执行纯判断，再投影为存储任务。Adapter 不导入规则实现或应用类型，register 只装配，不将应用对象直接传给 Adapter；回调不执行网络、异步任务或嵌套事务。所有参与写入的入口使用相同约束，规则拒绝不能留下部分业务写入；明确的状态刷新与拒绝结果分别表达。依赖时效的判断在事务实际执行时取时钟事实，不能把入场时刻当成排队后的当前时刻；同一次决策的校验和持久时间使用同一事实。用于排序或生命周期的持久时间须明确时钟回退时拒绝或维持单调的策略，不能让较晚写入破坏既有时间关系。创建回调只根据已读取的权威事实生成记录，不填虚构 revision 或状态等待 Adapter 修补。 幂等重放先验证当前身份、资源归属及绑定内容，再返回原结果；新增容量准入只约束新记录，不因集合已满拒绝合法重放。

**E-04.3**（关联 E-04.2/E-07/E-11）：持久设计允许缺省的可选记录与必须存在的关联记录分别校验；导出、恢复预检和运行时采用同一缺省语义，不为通过快照校验伪造持久记录。初始默认事实只在首次创建事务内安装；同事务必需的关联记录缺失视为完整性失败，不在读取或普通写入中静默补建或伪造默认事实。预发布初始结构变更同步更新精确签名，拒绝不匹配的开发库，不追加兼容升级。重启、读取和恢复不能重新授予已撤销的权限或覆盖用户选择。声明来源、实例身份和授权分别表达，不能从名称、客户端字段或资源存在推导受信来源；同一声明版本的内容不可原地改写。撤销与关联持久状态围栏在同事务提交，跨资源收尾归实际 owner；提交后的回调复查具体实例，不能误停随后获准的新任务，未知结果不假称回滚。

**E-02.4**（关联 H-05/H-06、E-09）：安装/公开契约独立定义在其正式出口，并由安装边界显式转换到内部事实；不能因字段相同而借用私有 Model 类型、实现的 ReturnType 或第三方对象。核对导出的完整类型依赖图及真实消费者，避免表面只引用 register/public、实际仍依赖内部结构。公开边界同时转换成功对象与同步/异步拒绝，不能只投影成功结果而将私有错误或 cause 传到其他模块。

**E-07.8**（关联 E-03.3/E-04.3/E-07.5/E-11）：持久配置区分已保存状态与实际生效状态，明确激活范围、时点及失败恢复；多个消费者不得通过独立缓存或局部更新形成矛盾权威。首次默认与环境初始化只在首次创建时求值，重启不得覆盖用户配置或因未使用的旧初始化值拒绝加载。站点/身份等配置必须接入真实传输与验证消费者；允许多个站点不等于允许请求跨站使用权限。配置保存不能假称外部依赖已验证或交付已完成。每个可写配置字段须追踪到实际消费者；展示有效值、事务冻结、运行时期限/容量及撤销必须使用同一政策 owner，迟到激活不能覆盖新版本。数据恢复或运行时重建先停止受影响 owner 的准入并排空；终止关闭的实例不再复用，新实例与全部消费者/订阅按最终存活数据重新绑定。未确认提交或资源收敛时不能宣布恢复完成。维护任务及其外层包装占位不能进入自身等待的排空集合；排除项须绑定真实任务身份，不以路径或名称排除整类调用。异步准入绑定原实例代次，完整消费者集合先校验后发布；传输排空与业务排空分别确认。

**E-07.9**（关联 E-03.1/E-04.2/E-07.5/E-10.4）：迁移收藏、历史、快捷数据等个人持久状态，先从实际生产者确认其归属，不因旧表未分用户而继承全局可见性，也不为假设的生产者增加公开能力。身份来自受信认证，读取、关联和变更均限定原用户；有多阶段等待的写入在提交事务核对原身份。批量关联和级联变更同时维护被影响记录的版本，使已有编辑不能静默覆盖关联变化；集合上限由应用规则根据同事务存储事实决定，Adapter 不自行承担业务容量政策。

## 前端通信收口检查

**E-02.1**（关联 E-06/E-07/E-09/E-11/E-13）：沿通信、状态协调、展示及跨功能消费者核对错误和类型契约，不只验证 transport。服务端安全取值引用 Shared，本地通信失败归前端 owner；复用应用类型与单文件局部类型按各自消费者放置。共享列表缓存区分读取完成、读取失败和缓存重置；不能把后两者当作权威空列表清除用户选择。变更使先前读取失效，旧结果及旧finally不能覆盖已确认写入或新任务。确认等待绑定原页面/弹窗实例，离开时取消本次确认并释放监听，不影响后来建立的确认；确认后的派发仍复查原操作有效性。刷新同时核对原内容修订，不仅检查资源仍存在；普通资源断连的草稿保留与身份撤销后的私有内容清除分别定义。恢复必须重读实际被修改的事实；无关摘要或另一组件的刷新，不能解除原操作及原界面的恢复围栏。异步流程的后续副作用同样绑定原视图、身份与资源实例；派发前和排队执行时复查有效性，不能让旧回调借新会话继续提交。视图撤销与已派发任务的结果追踪分别归属。 同一聚合内的自动保存须协调编辑与在途确认，较早确认不得回填覆盖其他未提交草稿；选择互斥或明确提交，合并时核对原修订，不以无条件套用最新版本掩盖冲突。

**E-13.1**：关联请求须在响应完整解码成功后才解除等待归属；畸形响应、消息关联失败和连接终止同样结清对应等待及子回调，不能留下无owner的悬挂Promise。终态后拒绝新的子请求，已交付但仍待持久确认的子任务继续由原owner收口。形状校验归协议解码，请求关联校验归持有上下文的通信边界，状态有效性归实际状态 owner。资源身份、状态组合和分页语义按各端点契约验证，不对所有接口强加同一种分页或重放行为。列表若约定返回可见结果，limit约束最终可见项，不能先截取候选再过滤而漏掉后续有效项；存储在稳定顺序/原事务内按有界批次继续扫描，业务可见性判断仍经Model转换由应用owner执行。回归覆盖超过一个候选批次的失效项、全不可见及满页，不以单页正常结果代替。 独立读取的任务状态与结果正文不能冒充同一快照；依据较新终态停止观察前，补齐该终态所需的结果读取，避免早先空结果被永久保留。

**E-06.1**（关联 E-05/E-09）：响应头、媒体类型、实际读取容量及解码失败均核对资源收尾；响应已排队不等于完成交付，销毁后缓冲清空或迟到的完成通知不能证明成功；同时核对原传输状态和真实完成事件，不把本地完成当作远端收件确认。定长或带结束标记的交付，在最终校验和生产者收尾前保留完成信号；接收方可在长度满足时立即结束读取，不能先交付完整内容再依赖后续异步确认。一次性能力在实际响应完成前保持失败撤销路径，监听随完成或关闭释放；提前拒绝也处理未消费的响应体，已取得 reader 的路径最终释放锁。复用前确认预算、失败、取消及生命周期语义一致，不能用通用包装掩盖契约差异。资源进入错误态后，取消或关闭可能重新传播原操作错误；技术 owner 依据接口语义及错误身份区分原失败与独立清理失败，不按正文判断，不将同一失败再次升级为清理未知；独立清理异常仍须保留。

**E-06.2**（关联 E-01/E-02/E-11）：第三方库或外部协议的原始错误码、状态和错误正文在最靠近它们的 Adapter/技术 owner 归一为具名技术失败契约；上层 Model/Service 只消费该契约，不解析供应商 cause/code/message。外部协议定义的正常终止、导航及控制项也在此处解释，不将合法控制项误报为业务数据损坏；异常数据仍严格拒绝。原始 cause 可保留作诊断，但不能驱动应用结果；技术契约同时区分尚未派发、确定失败与结果未知，避免把本地取消、回调拒绝或传输中断混为同一语义。分类依据协议确认覆盖的完整副作用范围：明确拒绝且证实未发生效果可判确定失败，部分成功或确认缺失仍保留未知；不能仅凭已调用底层方法就一律判未知，也不能从局部拒绝推断整体未执行。输入producer和交付consumer在边界把预期拒绝/取消转为所属应用失败，跨业务owner的回调使用被调用方的失败契约，返回时再转换为调用方契约，不能让畸形请求或消费者断连触发全owner故障停机；取消仍须完成资源收尾，清理未确认不得被取消状态覆盖；已经具名表达的提交或执行未知也不得被较晚的取消重新归类成确定失败。

## 交接证据核对

**E-10.1**：按实际 diff、源码和执行输出审核交接；已正确能力接续维护，确认的源码缺口在原阶段补修，实机未验收单独保留。检查记录包含工具版本与路径、分支/SHA/工作区、场景、命令、输出位置及结果；安装版本与仓库版本约束分别核对，不混写不同环境的证据。变更后重跑受影响检查，不沿用此前 PASS。验收通过实际统一runner，核对其工作目录与资源定位；夹具资源按所属文件定位，不以仅在仓库根目录直接执行通过代替。构建成功后仍须通过实际运行入口加载关键依赖与 Adapter；转译工具的模块互操作不能代替交付产物在原生运行时的验证。恢复/接管回归须核对确认前后的权限、旧凭据失效及原资源身份，不能只断言响应成功；登录权限、附件所有权与后台资源保留分别按已确定契约验收，不将其中一个被撤销推断为其余资源已终止。压力与背压夹具按真实消费者的发送、合并确认和消费节奏构造，正常流控与超额输入分别验收；失败先核对夹具是否误触另一资源预算，不为夹具偏差放宽产品限制。测试夹具的匹配/校验回调保持无副作用；调用计数从实际派发或交付点观察，不能把重复匹配推断为重复执行。验证已派发任务的取消或未知结果时，先以实际生产者证据确认执行已经开始；仅收到接纳回执不能排除任务仍在队列中。跨客户端创建或释放的资源，使用底层权威查询核对实际身份和存活；单个 SDK 客户端的缓存列表不能代替全局资源事实。故障验证使用归属明确、容量受限的隔离资源，先核对实际隔离与容量，再触发底层拒绝；不耗尽共享宿主资源，不把错误码替身当作真实介质证据。恢复验证区分受控关闭、进程异常退出与持久介质故障，分别记录中断时点、实际退出证据及重启后的数据和资源事实；完整步骤之间的检查点不能代替步骤内部故障，提交已确认后的中断不能冒充提交确认丢失。 生成的命令或脚本须通过实际目标解释器验证语法、引用及完整执行结果，字符串匹配和编译通过不能代替该验证；缺少环境时明确保留待验范围。

**E-10.3**（关联 E-01–E-04/E-08/E-09）：涉及功能或架构的阶段，设计时建立、实现后逐项回填以下四份审核表，集中放在当前实施方案的阶段区，不另建施工文档。每项提供可定位的源码或执行证据及结论，不能只填写“符合”；不适用项说明依据。纯文档或格式阶段说明无行为与架构影响后可免填前三表。

| 类型归属 | 新增或修改的复用类型/基础取值、唯一 owner、真实消费者及边界转换位置；同义重复定义、私有类型穿透和底层错误结构依赖明确列为偏移。 |
| 完成证据 | 按功能项分别记录源码、架构、静态、逻辑回归及实机状态，关联命令/结果、待验范围或偏移；历史证据标明原基线，不代替当前工作区结果。 |

审核沿“实际入口 → 解码/转换 → 业务流程 → Model → Adapter/Platform → 结果/错误投影 → 消费者”追踪适用环节，同时核对失败、取消和清理分支；没有的层不补空层。完成实现后按最终 diff 再审核一次，不能用设计表替代实际实现核验。已知源码缺口或架构偏移未修复，不得标记相关项或整体阶段完成，也不得仅作为待测试项后移；明确延期的独立项按 E-10.2 承接，不包装为已完成。行为检查受当前授权和实施决定约束，后置时保留“待验”，不影响源码与架构审核的执行。

**E-10.4**（关联 E-03.3/E-05.3/E-06/E-11.1）：自审以最终变更文件和真实流程为覆盖基线。新增、修改、删除、移动文件及受影响消费者均记录已审范围，职责相同的小文件可合并记入 E-10.3 四表；沿正常、拒绝、提交前失败、提交后确认失败、交付前断开及清理失败分支核对返回结果、已有副作用与剩余资源 owner，不以目录正确或成功路径代替审核。按可闭合调用链分批实现并检查，格式化与同文件写入串行完成；最终修改后重跑受影响静态检查。环境阻断单独记录，不能推断源码通过，也不能暂停仍可执行的源码自审。模型或其他外部协议要求的续接证据必须完整保留并显式转换，不能为了统一接口静默丢弃。本条不扩大当前测试授权。

**E-10.5**（关联 E-05/E-06/E-10.1）：每个用例及其重试独立建立完整基线，覆盖应用、外部夹具、故障开关、计数与资源屏障，不依赖前一用例、文件顺序或分片分配。可变状态由所属夹具集中重置，新增控制项同步维护基线；先等待真实资源 owner 收敛，再重置观察状态，不清零在途计数、不删除未知围栏或强制释放资源来伪造隔离成功。重置失败明确阻断并保留因果；刻意保留未知副作用的场景使用独立运行生命周期，不能靠固定执行顺序隔离。

**E-10.6**（关联 E-10.1/E-11）：验证写入回执时，在原请求交付或页面导航前保存真实响应证据，再严格解码并核对请求关联；浏览器已回收响应体不代表业务失败，不能靠重放写入取回回执。需要截获时转发一次原请求并交付同一真实响应，不伪造成功、不重试副作用；只读核对持久状态与原回执断言分别保留。网络拦截的安装／移除覆盖实际响应消费及其后续依赖读取，不以响应头到达作为整条交互完成；切换拦截时不能使并发请求失去交付。存在持续轮询时，纯回执观察拦截随页面 owner 一起销毁，不在交互中途更改网络匹配；持续轮询中的故障恢复优先切换注入状态并继续交付原请求。修复时同步排查其他回执观察点，不只改当前失败用例。

## 随工程演进维护

**E-14.1**：写入规则前先确认事实与根因，再提炼适用范围、长期约束及核对方法。规则应在更换模块、阶段、分支或工具版本后仍适用；不能提炼的内容留实施方案或验证记录。优先更新已有类别，独立的新类别追加固定编号，不重复近义规则。

**E-14.2**：规则只保留共性约束与问题类型，不记录具体修复文件、临时任务、完成状态、交接对话或本轮环境。具体任务应引用规则编号，展开到实际 owner、消费者、步骤和判据；任务完成后关闭施工项，长期规则继续按工程演进核对有效性。

**E-14.3**：架构改变时修正失效或冲突条目，不把源码偏离改写成规则例外。AI 工程经验不能自动升级为人工规则。使用现有静态工具和适用逻辑回归验证实现，不新建读取源码文本或目录形状的自定义规则门禁。

## 原功能还原与复合操作结果

**E-03.3**（关联 E-10）：功能能力实现与原通信契约还原分别验收。以实际挂载入口、安装配置及现有消费者核对通道、消息名、参数、默认值、编码、响应、副作用及不同配置下的可用范围；新增一种通道不能替代另一种仍被消费的入口。更严格的新前置条件、缩小操作范围或减少合法部署配置也属于正常功能差异，必须显式处理并定位当前修正或明确延期的 owner，不能仅凭同名操作判定等价。外部字段按自身编码语义校验，不能将单行文本或路径的限制套用于合法的多行编码内容；格式拒绝须核对正常生产者。跨主机或多跳流程还须分别核对探测与实际执行的发起端、网络路线、身份和信任依据；控制通道验证成功不证明数据通道采用相同配置，不能静默忽略已配置路线。原功能基线以保留的正式源码和实际消费者为准；迁移中的临时实现、历史方案或推测能力不能冒充旧产品已有功能。

**E-03.4**（关联 H-13、E-03/E-09/E-12）：界面迁移先固定可追溯的原版基线，逐页核对 template、样式及实际交互，将差异区分为协议绑定、必要功能变化和无依据的展示变更；必要变化须有实际后端契约依据，其余按基线恢复。常驻说明、空状态和帮助文案同样属于 UI 差异，不因内容准确就添加接口名、编码预算、事务或内部修订说明；详细约束归对应产品文档，界面仅保留当前操作需要的输入帮助、确认和失败恢复。新增的读取／刷新恢复按钮只在失败、冲突或结果未知等需要核对时显示，不因初始未加载状态在正常页面常驻或闪现；原版已有的刷新、搜索、同步与续读操作逐项核对并保留，不能机械隐藏所有读取入口。核对自动加载、弹窗与分类可见性、焦点、取消、秘密清理、异步晚返回及所有现存消费者；定位同步真实可见入口，保留原行为断言，不为测试新增产品标记。调整布局须核对容器收缩、内容最小尺寸、滚动归属及相邻操作的实际点击区域，元素存在或可见不代表未被其他内容遮挡；实际遮挡修复布局，不用强制点击绕过。同一用户动作涉及多次内部请求时，由实际用例 owner 编排，不把每个请求平铺成产品按钮；拆分展示同一份版本化配置时共用草稿、忙碌和恢复状态，不因卡片拆分创建多个写入 owner。必要的审批、取消和未知结果核对须仍有清晰可达的入口。嵌套浮层的关闭由当前最内层owner消费，空内容导致焦点留在触发器时，外层同样不得抢先响应Escape。契约变化由原状态 owner 和 mapper 消化，源码核对不能替代浏览器外观与交互验收。

**E-11.1**（关联 E-06/E-07）：界面的一次保存若包含多次独立提交，应拆成独立动作，或逐项表达已确认、拒绝和未知；后续失败不抹去先前成功，不自动补偿删除或重做整组。已完整解码并核对请求关联的确认结果，不因随后视图取消改判未知；是否发布界面或当前会话状态另按原实例判断。批量准备先校验完整输入，已确认项保留，未知项阻止继续派发并先只读核对。复合操作的结果按整项副作用判断，包含准备阶段的目录创建、临时写入和部分批量执行。写入已生效后，后续读取、校验或响应失败不能降为确定未写入；无法确认完整结果时保留未知状态与原因。跨文件与数据库的操作分别确认字节、文件句柄、目录持久性与元数据结算；发布可见不等于崩溃后可恢复，未确认前不归还额度。未知结果同时标明所属边界：外部操作结果未知与持久提交未知不能合并为同一种恢复动作；只在原账本身份及提交已确认时收口外部未知结果，数据库提交未知不得推测状态后补写或派发。仅包装副作用后的确认阶段，避免将派发前的确定拒绝误报为未知；确认元数据与内容须满足响应契约的关联约束。幂等写入须保存首次事务提交的完整安全结果快照；重放不可从后续可变状态重新拼接首次结果，也不能以原响应已确认推定业务状态从未改变。 视图暂停与身份终止分别处理：保留原owner在途／未知意图及副作用围栏，不能因暂时隐藏重新生成写意图；会话重置、身份替换和owner销毁仍清除私有数据并隔离晚结果。前置关联／准备与后续执行分别确认，准备未知时不得继续派发；查询对象存在不证明关联或授权已提交。

**E-10.2**：阶段清理区分完成、部分完成、延期与待验；只清除已验收的施工项，未解决子项明确承接到新规划。历史执行证据保留原代码基线及场景范围，修补后的工作区单独记录静态结果和未运行的行为检查，不延用旧 PASS。

**E-05.2**（关联 E-06/E-09）：异步迭代、流和生产者的生命周期涵盖自然结束、break/return、取消及消费者回调拒绝。收尾放在真实 finally/资源 owner，等待已启动生产者与读写者收敛；资源释放使用实例绑定能力，不依赖已撤销会话重新认证。局部 destroy 不证明远端副作用停止，不作竞争清理。传输完成等待同时处理请求中断与原连接关闭，不能仅依赖响应对象的单个通知；解除传输等待仍须等业务处理和清理收敛。取消归类须由具名取消失败及原 signal 共同证明，不能因 signal 已取消就忽略同时发生的存储、内部或清理故障。第三方流的错误结束可能不发送 close；计时器及取消监听由原技术 owner 在错误和关闭路径独立解除，不靠 unref、强制退出或放宽期限掩盖遗漏；解除本地等待不代表远端清理已确认。缓存界面的停用与卸载分别收尾临时秘密、订阅及在途展示；重新启用不恢复已失效意图，已派发写入仍由应用 owner 追踪。操作引发身份失效并重建界面时，原操作的必要收尾独立于旧视图存活，且不得覆盖后续导航或身份。

**E-02.3**（关联 E-01/E-06.2）：第三方命令语法、输出表示、编码库及原始状态归技术 Adapter；Model 显式转成应用事实，Service 决定允许范围、覆盖、发布和恢复政策。复用结果/错误归类型 owner，不能因拆出辅助 Service 就让协议层从该实现借类型；字段相同也保留转换。多重解释边界分别处理语法：shell 引用不能替代工具自身的 pattern/选项转义，字面量名称按最终消费者规则编码。

**E-07.3**（关联 E-05/E-11）：可复用标识不是异步能力的实例身份；能力在创建时绑定具体实例，准入、异步复查、排队执行与释放都核对该实例。配额判断与登记置于同一串行或原子边界；保留在途资源不等于继续许可新请求，释放应具备幂等性。第三方异步构造若依赖共享可变计数或 registry，核对编号分配与实例登记的实际时点；只串行存在竞争的必要步骤，不把完整长任务无依据串行化，也不能用当前计数代替原实例身份。共享事件源的监听设计须承载已允许的并发量，按原实例登记和移除；满额验收核对告警及真实收尾，不通过关闭或无依据提高告警阈值掩盖生命周期问题。资源被多个独立原因暂停或阻断时，由实际状态 owner 在每次解除后重新计算是否可恢复；解除一个原因不得清除其他原因或直接恢复底层资源。显式恢复在发起时绑定故障修订，较早请求的读取不能清除较晚产生的失败或未知围栏；串行排队不免除此检查。 跨生命周期撤销先绑定原实例集合，再等待释放；不能异步获取届时的全局集合而误清新资源。可见界面、已接纳资源和在途清理分别核对，隐藏或移出展示不代表已释放。

**E-07.10**（关联 E-07/E-10/E-11）：后台只读刷新不应周期性禁用可用的用户操作；交互请求可取代原读取等待，原读取的晚结果、错误及 finally 不得覆盖新操作状态。写入仍串行并保留原版本、权限与未知结果围栏，不以自动重试解决竞争。操作控件的可用状态应反映真实owner的准入条件；在途写入禁止关闭时同步禁用对应关闭入口，不能显示可用却静默拒绝。审核覆盖按下至点击派发之间的状态变化，行为验证分别确认请求真实发出、回执及最终业务结果，不把底层效果已出现当作上层回执已完成。

## 长任务、交付与资源核算

**E-05.3**（关联 E-05.1/E-05.2/E-07）：受理、派发意图与实际执行结果分别定义完成判据；受理回执不证明后台任务健康或成功。后台子任务持有持久身份和明确的父生命周期，父任务成功前必须收敛其子任务；等待截止与任务截止分开，完整任务期限不因跨层调用重置。向下调用时区分剩余总期限与该类子操作的技术上限，使用两者较小值；字节流与元数据请求不能混用期限预算。操作生命周期覆盖准入后的排队、获取资源、执行、交付和最终收尾；写完数据或发送终态前置消息不等于完成。取消按实际资源归属传播：未执行的排队取消不破坏健康共享资源，独立任务只收尾自身资源，隔离须覆盖准备阶段的元数据读取和排队后的复查，不能只隔离真正的写入；父 owner 关闭覆盖其全部关联任务，跨 owner 操作由所有相关方追踪。核对各阶段的关闭等待、最终确认、监听退订与晚结果归属。共享在途任务取消后，新订阅不能加入已撤销实例；若旧任务仍可能写入同一状态，先等待其收敛再替换，排队订阅仍独立响应取消，避免旧收尾覆盖新结果。订阅者离开不解除实际任务归属；任务登记持续覆盖结果复查、持久写入和最终清理，不在首个底层调用返回后提前解除。子资源的close等待自己持有的任务，不以父模块已追踪HTTP请求作为立即完成的依据。无人等待时发生的晚失败仍保留到实际owner收口。继承清理的准入有明确截止点；关闭快照建立后不得继续接收未被该关闭覆盖的新任务。 临时请求授权的异步上下文与独立后台任务分别归属；任务交接显式建立自身权限及生命周期，不能偶然继承请求的临时准入scope。排队时捕获原授权，执行事务内复核；脱离原scope不等于免除后台owner自身的持久授权。在线替换须排空传输、公开能力和后台 owner；维护任务与外层观察占位不得等待自身关闭。终止的实例重新安装，缓存能力也须解析新 owner；旧维护 owner 的最后关闭放在维护任务之外并追踪结果。准入包装保留原同步/异步契约，异步能力的拒绝仍返回 Promise；停机先向原任务 owner 发出停止信号，再等待在途任务，不能先等依赖停机信号的任务结束。排队和排空依赖不得构成等待环：被排空任务需要的读取或收尾不能排在正在等待其结束的管理操作之后，独立执行仍归真实 owner 追踪。

**E-05.4**（关联 E-07.3/E-08）：共用同一资源预算的任务类别由唯一 owner 统一准入，计数包含已接纳的排队、执行、关闭及未确认清理的任务；按真实生命周期明确开始占用与允许释放的时点。剩余额度检查与占位之间不能跨 await；异步持久登记完成前也计入总量，绑定真实 owner 时交接占位，确定拒绝与提交未知分别收尾。大输入的读取与解析也纳入准入，不能先缓冲完整输入再申请业务名额；协议 producer 只交付应用输入，实际任务 owner 追踪取消和晚收尾。完成缓存与活跃任务分别核算，重复意图/标识不能覆盖原任务或取得第二份名额。核对混合类别、提交顺序、取消及清理失败，避免局部计数绕过总预算或提前归还名额。派发可能产生需保留的续接或结果时，提前预留其容量，并在真实任务收敛后释放；不能在副作用返回后才因本地容量竞争将它报为确定拒绝。 持久围栏与本地资源取消是独立收尾责任；存储失败仍由原资源 owner 取消并等待关联任务，不能让第一项失败跳过其余清理。派发期限与结算期限分别处理，期限到达不得阻止已派发任务记录未知结果。冲突身份按实际共享资源归一，不能仅按调用方或配置ID分桶；多资源准入在同一事务获取全部资源。持久占用覆盖最终确认和清理，期限/重启不证明未知副作用结束；结算失败不得触发猜测重写，汇总失败仍保留真实资源清理标记及恢复owner。 同一围栏内并行准入依据真实读写冲突集合，路径别名、递归范围与排队后的事实变化均须核对；共享读不等于写入互不影响。成员确定没有产生副作用且资源已排空的取消，可与其他成员的在途生命周期分开交付，但不得提前释放共享围栏或将其余写入结果提前确认为成功。

**E-05.5**（关联 E-05/E-07/E-11）：跨进程资源的恢复依据先于派发持久化，实例身份与父聚合修订分别表达；内存退出通知不能替代持久效果和清理确认。恢复核对原资源的出生身份及实际归属，不以可复用的数字或路径猜测所有权。身份缺失、提交或收敛未确认时保留现场和未知围栏，不自动重派。人工确认未知事实、解除围栏与启动新任务是独立动作；原未知证据不能被新实例或确认记录覆盖，保留证据的容量满额使用明确拒绝。已有未知事实导致的准入拒绝与本次提交/清理未知分别分类，不能用前者触发无关资源的故障停机，也不能将后者降为普通拒绝。复合排空聚合保留该类别：全部子项仅为已有围栏拒绝时，不用通用 unknown 包装触发新的故障停机；混入真实提交或清理故障时仍保留全部因果并按故障处理。

**E-06.3**（关联 E-06.2/E-11）：技术资源关闭成功不代表其临时文件、生产者或其他副作用已清理。清理失败在跨层转换和复合错误聚合中保留具名类别及全部因果，不能被后续成功或通用错误包装抹除；汇总需保留调用方据以结算的失败类别，只有全部子失败均属已知执行未知时才可按执行未知结算，混合存储提交未知或内部故障不能触发推测性状态写入。直接资源排空与跨任务等待复用所属错误 owner 的同一分类，核对每级聚合后上游仍能按原语义结算；同一失败不重复登记，新增失败不能遗漏。由任务观察器登记失败的 owner，汇总在真实任务及观察器收敛后读取一次，不再从同批等待结果重复追加。队列准入预算不能阻止已经派发任务的结算或恢复排空；容量不足时保留完整意图，不部分丢失，并核对空位释放后的继续处理路径。同步抛错与异步拒绝都进入同一收尾路径，保留任务归属及恢复依据，不虚报完成或释放。批量等待后逐项核对结果，不能把 allSettled 完成视为全部释放成功；区分操作取消与清理失败，清理未确认阻止资源退役及名额归还。启动清理前保存共享 Promise，单项失败不得阻止独立资源开始收尾。批量清理将实际调用纳入Promise任务，不能在构造任务集合时因同步抛错跳过其余项；关闭及停止准入也处理同步拒绝。错误收集保持有界，保留未收敛事实，不只记第一次失败。已在协议边界按契约处理的预期输入拒绝不记为 owner 故障；进入应用安全兜底前转换输入拒绝，原传输状态由接口 owner 保留，不能把参数或容量错误归为内部故障；真实交付失败仍归原任务收口。应用错误类不能整体视为可忽略业务拒绝：已映射的存储失败、未知提交及内部故障仍是收口证据；按明确类别区分，并在任务退出前由原 owner 有界记录。

**E-07.4**（关联 E-07.2/E-11）：批量操作在首个副作用前核对整个计划的相互影响，而不只逐项验证；按实际底层语义检查规范位置、别名、祖先/后代、覆盖与读取依赖。准备结果不是后续执行的永久授权，排队后及执行前复查可变身份、owner 和路径事实；确认阶段区分自身操作造成的变化与外部变化。预检不创建目标、不冒充原子快照，无法识别的别名和竞争窗口明确限定保证范围。

**E-07.5**（关联 E-04/E-06/E-07.1/E-09）：共享安全准入政策只能消费由受信传输边界给出的身份或来源事实，客户端字段和未验证的代理转发头不能构成权限。配置缺失与显式关闭、配置畸形与安全服务不可用分别表达；已启用的认证因素或外部验证不得因技术故障静默降级。含异步第三方校验的准入在副作用提交前再次核对会变化的封禁、凭据和权限；敏感写入在实际提交事务核对原授权仍有效，早先认证不替代当前授权事实。事务内不同拒绝原因保持具名结果并在 Model 显式转换，不能合并成布尔值而误报另一失败；共享策略仅装配一次，跨时间边界的权限复查仍由实际业务 owner 负责。核对配置校验、默认值、信任链、拒绝/异常分类以及异步校验后的事务条件。包签名与目录来源只能证明身份，不能代替执行授权；扩展代码的隔离能力及实际限制明确描述，宿主回调绑定原实例并逐次复查当前权限，不继承宿主秘密或其他用户会话。会话授权与运行实例授权使用明确分支，不能用虚构凭据或伪造身份让后台调用套用会话路径；实际副作用事务和持续读取同时核对原实例存活及权威权限，早先存活检查不能覆盖后续异步阶段。

**E-08.1**（关联 E-08/E-11/E-12、H-20）：新增或收紧预算须遵守 H-20，不以本规则的容量核对要求作为凭经验设置限制的依据。分别说明协议字节预算、声明量预检、实际结果检查、运行时硬限制与部署前提，不将其中一种表述成另一种保证。输入长度上限不证明计算成本有界；不在主线程执行不受控的外部正则或表达式，采用成本有界的算法或明确隔离/中断机制。遍历配额同时覆盖待处理队列，不能只限制已处理计数。外部输出采用有界增量消费，分块和总量均有明确预算，不能先无界缓冲再校验。 捕获上限、展示投影与续读预算分别定义；有限投影保留原始持久事实、明确省略标记及可校验引用，续读不能冒充恢复未捕获数据。分页游标明确字节/码点单位，预算包含JSON转义；引用哈希只证明内容关联，不能替代当前来源权限。带分隔符的流先按协议归一化完整分隔单元，再切分记录；核对跨 chunk、编码及多字符分隔符，不能用可回溯表达式把一个分隔单元误拆成两个。终态快照可能重复完整内容，分别核对普通增量、快照和累计传输预算，不能因快照需要扩大普通事件限制。依赖硬限制时确认其在副作用前实际生效，设置失败不继续执行；已明确接受的技术限制如实维护，不写成已实现能力或测试通过。

**E-07.6**（关联 E-02/E-05.3/E-06/E-07.5）：多阶段认证中，待完成流程与完整身份分别持有明确权限、期限及撤销 owner，部分验证不可被普通能力当作完整身份。密码学交互的请求选项与最终验证条件一致，应用策略与技术证据分离；第三方对象在 Adapter 明确投影，无法可靠分类的供应商异常保留不可用结果，不能冒充确定凭据失败或绕过验证。认证资源在后续确认及响应最终交付前持续由原 owner 管理，失败清理与未知副作用按 E-05.3/E-11 处理。

**E-02.5**（关联 H-04–H-07、E-01.1/E-09）：分层检查覆盖方法签名、返回对象、错误和事务回调，不只检查 import。Service 不接收存储记录或技术请求/结果，Model 不以透传包装代替转换；SQL 行与厂商字段由各自 Adapter 解码，Model 只消费已验证的下层契约。存储自身的冲突/不存在通过独立存储拒绝在 Model 映射；Adapter 不实例化应用错误；审核同时追踪错误类的定义和继承，不只搜索 Model/Service 路径。事务内应用回调的原始拒绝仍可传播。内部协作接口留应用 owner，不用 public 文件借用私有类型；真正跨模块出口独立定义安全契约。必填性由实际用例决定，不能为延后的消费者保留虚假的可选声明。复用观测字段同时核对对象、单位和采样口径，在Model显式转换；白名单投影依据生产者实际表示，不因联合类型允许另一形状就重解释原值；不可变标量直接赋值，可变集合才按其真实结构复制。缺测不冒充实际零值，首次采样不冒充区间变化率。存储边界同时覆盖独立缓存、元数据和持久快照，不能以缓存恢复为由将持久 JSON 解码放入 Model；Adapter 返回已验证的存储事实，损坏数据的业务恢复由应用 owner 决定。

**E-08.2**（关联 E-03/E-08.1）：同一内容经管理、批量导入或临时执行进入时，按真实语义复用所属owner的容量；单位和规范化后的编码仍须一致，内部可信入口不能绕过持久化后公开读取所需的约束。秘密正文不因复用名称校验而被trim或改写。容量核对覆盖完整响应、集合总量、嵌套观察及 JSON 最坏转义。顶层与每级嵌套解码均使用所属契约的预算；存储表示另行核对加密或编码膨胀，不能复用原始输入预算。合法单项和最大集合须能通过协议预算；不能只约束输入或逐项长度。有限输出超限使用明确安全容量错误，不截断结果或伪报内部故障；新预算、消费者读取限制和使用说明同步维护。 压缩内容同时限制完整展开容器、元数据和填充字节，不能只累计被选中的业务文件；最大集合的容量还须匹配查询归属与可达记录数。

**E-08.3**（关联 E-07/E-08.1/E-09/E-11）：有因果关系的输入按完整单元校验后发布，不逐条修改有效状态再发现缺项或超限。下一次派发前核对完整请求、附带定义和输出预留；固定目录/框架与可增长内容分别预算，不能让合法默认配置被固定开销耗尽；声明容量与一次执行批量分别约束，沿实际转换链核对二者不混用；容量估算与真实计量分开，估算不作为已发生用量或精确供应商保证。确定的派发前拒绝仍须结算已接纳任务，结算依据原身份/版本/请求及尚未派发事实，不能覆盖并发终态或未知结果；结算失败保留原拒绝与存储失败两项因果，不自动重试。

**E-14.4**（关联 H-09/H-10、E-10.1/E-12）：开发引导保留入口、流程及编号引用；架构保留当前 owner、依赖、契约和保证限制；USAGE 保留操作与恢复。逐轮修复、环境阻断和命令日志归 testing，当前任务归实施方案。精简删除重复与过时叙述，保留未完成依赖、有效配置差异和验收证据，不将历史状态写成当前结论。核对总览表、目录、分节与使用说明的当前事实一致，不能只改新增段落而保留相反旧结论。

**E-06.4**（关联H-05–H-07、E-02.5/E-06.2/E-08）：公开错误码、状态基础值与其参数空间须有唯一取值契约；相同取值在存储和应用层也引用该基础契约，保持各层对象独立。不能用宽泛string、前缀拼接或只校验字符形状代替有限取值；参数化错误码同时限制参数范围。有限取值按原始类型和精确值校验，不通过字符串或数字强制转换后匹配；结果联合只声明真实分支，不能用预留状态支撑不可达处理。底层失败在Model显式映射，运行时解码核对完整联合及状态与关联字段的一致性，未知值不能穿透出口或驱动业务判断。持久与协议解码同时核对关联时间的先后及有效区间，字段各自合法不能代替整条记录有效。严格解码后的有限对象仍按具名类型表达，不能退化为宽泛字典再靠 typeof 丢弃字段。可复用的同一技术失败转换只保留一个owner，保留内部cause与确定/未知语义。失败后的状态复查不能覆盖原存储或内部失败；独立复查也失败时保留两项因果，不将失败映射后的应用类别误判为可忽略业务拒绝。
