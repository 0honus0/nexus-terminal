# AI 工程经验规则

本文只维护经确认并提炼的共性开发规则。具体缺陷、模块修复清单、阶段状态、交接沟通和检查日志分别归当前实施方案或验证文档。开发前完整读取；与 [人工规则](HUMAN.md) 冲突时修正本文，不修改人工条目。

## 规则列表

主规则使用 E-xx，细则使用 E-xx.n；细则归属主规则，不另起重复主规则。编号保持稳定，新项顺序追加，删除后不复用；引用使用完整编号。

| 编号 | 适用范围         | 共性规则                                                                                            | 核对方法                                                                                                                              | 要避免的问题类型                                                           |
| ---- | ---------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| E-01 | 分层与应用资源   | 技术句柄封装于技术转换边界，业务层只取得应用能力及明确的资源生命周期。                              | 沿返回对象核对字段、可调用能力及创建/关闭 owner，不能只看目录。                                                                       | 技术资源穿透业务边界。                                                     |
| E-02 | 类型与能力归属   | 复用类型和能力由真实业务 owner 唯一定义，低层不反向引用上层实现，公开契约不借用私有类型。           | 追踪定义、全部消费者和依赖方向；跨功能复用经所属 owner 的公开入口。                                                                   | 类型反向依赖、共用能力误放与重复定义。                                     |
| E-03 | 契约迁移完整性   | 以全部已实现通信入口盘点契约与消费者，不以已有前端或共享目录作为迁移范围。                          | 逐项核对共享定义、编解码、出口、双端及脚本/测试消费者，缺失链路进入实施任务。                                                         | 无新消费者的功能被遗漏，成功分支迁移但失败契约缺失。                       |
| E-04 | 存储与事务       | SQL 与存储事务归 Adapter；业务判断归业务 owner，需要当前事实的判断与写入保持同一事务。              | 核对查询、DDL、迁移、事务控制及所有写入入口；规则拒绝能回滚，不在事务外先读后写。                                                     | SQL 越层、业务规则混入技术实现、判断与写入之间产生竞争窗口。               |
| E-05 | 异步等待         | 等待超时或取消不代表真实任务结束；原资源 owner 追踪晚到成功和拒绝直至收敛。                         | 核对准入名额、晚成功资源、晚拒绝因果及停机汇总。                                                                                      | 提前释放配额、遗漏晚到资源或失败。                                         |
| E-06 | 错误与清理       | 错误使用具名类别和受约束 code，未知异常安全兜底；一项清理失败仍执行其余清理，多项失败保留全部因果。 | 沿完整调用链核对错误映射，禁止比较错误正文；检查早退、退订、释放和关闭路径。                                                          | 文本驱动业务判断、技术正文外泄、清理中断或虚报成功。                       |
| E-07 | 状态与竞态       | 异步返回后复查权威状态、身份及操作有效性，失效结果不得发布或覆盖新任务状态。                        | 核对每个 await 后的版本/generation/终态保护，包含旧 finally 和取消后的返回。                                                          | 晚结果覆盖新状态、通过断言或放宽类型删除必要保护。                         |
| E-08 | 共享取值与容量   | 同义同表示的双端取值及协议容量归 Shared；私有配额、缓存和清理策略留实际 owner。                     | 核对语义和真实消费者，区分原始数据、完整编码预算、route 显式预算与 Platform 技术硬上限；技术上限须容纳已授权 route 但不替代业务限额。 | 重复协议定义、只算字段长度、route 预算超过技术上限、将私有策略无依据共享。 |
| E-09 | 封装与转换       | 跨边界保留白名单转换，同一边界只有一个转换 owner；封装和复用必须有契约价值。                        | 核对输入/输出、联合分支和嵌套字段，删除重复转换及无消费者包装。                                                                       | 边界透传、重复 mapper、万能组件和机械拆层。                                |
| E-10 | 阶段完成与证据   | 源码实现、架构符合、静态检查、逻辑回归和实机验收分别判断；报告不替代源码与实际执行证据。            | 对照当前工作区、检查命令/环境/输出及未覆盖范围，已知失败本阶段修复。                                                                  | 复用历史 PASS、混合不同环境证据、将源码缺口推迟为验收任务。                |
| E-11 | 副作用与未知结果 | 本地取消、连接关闭或响应失败不证明远端停止或写入回滚；幂等写入结果未知时保留原意图与键。            | 区分未派发、确定结果和未知结果，核对重试及恢复是否会重复副作用。                                                                      | 自动换键重试、把预检查或本地清理当作远端原子性保证。                       |
| E-12 | 产品文档         | 行为变更同版维护 USAGE 对应功能章节；纯内部重构核对原说明，保留仍真实的产品约束。                   | 对照操作、权限、容量、输入输出及失败恢复，不以架构或变更日志替代使用说明。                                                            | 文档与真实产品脱节、精简时误删有效行为。                                   |
| E-13 | 响应与请求关联   | 响应解码同时验证字段形状与请求上下文；正确形状不代表属于本次操作。                                  | 在持有上下文的边界核对资源身份、范围、允许状态及分页语义，再发布应用状态。                                                            | 接收错误资源、非法状态组合、游标倒退或超出请求范围。                       |
| E-14 | 规则维护         | 已确认经验先提炼为长期共性约束，再按唯一 owner 和稳定编号维护；具体任务不进入规则。                 | 核对事实、适用范围和可复用性，引用规则展开任务，工程演进时修正失效条目。                                                              | 把临时沟通或修复清单写成永久规则、重复规则或随意重编号。                   |

## 通信迁移完整性检查

**E-03.1**（关联 E-02/E-08/E-09）：从真实安装的通信入口建立“契约—生产者—消费者”清单，覆盖请求、成功联合、安全失败、基础值、容量和包出口。检查所有消费者及转换 owner；没有新消费者的能力明确列缺口，不解释为无需迁移。共用能力先归所属业务 owner，再通过窄公开入口复用，不跨功能引用私有实现或复制一份。

**E-03.2**：自动接口文档以真实安装路由关联的协议契约为来源，明确方法、完整路径、参数位置、成功/失败响应、状态码、认证及容量；类型、运行时 schema 和文档不得成为互不关联的多份定义。通用汇总层不引入业务类型；HTTP 与事件通道分别表达。schema 的字段限制不能代替编码字节预算、授权执行或业务规则。

## 能力与目录审核

**E-01.1**（关联 H-06、E-06.2/E-09）：Model 转换边界同时持有技术调用、资源能力和失败转换；只有字段 mapper、但 Service 仍接收原始句柄或直接调用 Port，不构成完整边界。沿实际调用与关闭链核对，Service 只取得实例绑定的应用能力，不能用新增包装文件替代边界隔离。Platform 的 Port 是通用技术契约，允许由 Model 消费和 Adapter 实现；审核判断其字段、依赖和实际调用，而非依据文件名。应用事实及纯规则不能夹带第三方实例，Model 还须把技术失败转为应用失败，不延迟到公开出口。

**E-01.2**（关联 E-02/E-04/E-08/E-09）：层级审核同时追踪判断与表示转换。用例允许范围、期限、配额及恢复政策归 Service 或所属纯规则，Model 接收明确应用命令并转换技术/存储能力，不自行选择业务政策。默认值、资格选择、缓存失效、删除准入、别名冲突和损坏数据恢复属于应用决策，按职责放在Service或纯规则；Model只转换下层事实和明确应用命令。协议时间单位及编码表示只在通信边界转换，第三方表示只在技术 Adapter 处理；产品名称、显示标签和应用默认值由应用传入通用技术能力。技术硬上限仍归技术 owner，不因其是数字就移入 Shared。

**E-02.2**：目录按真实业务 owner 和消费者范围组织。多个子功能共用的转换与资源能力须明确所属子功能及允许依赖，不能因共用而直接放入技术底层，或藏入无明确职责的根级目录；也不为符合目录形式创建空 Service、Storage 或包装层。

**E-09.1**：公开能力以真实运行时消费者为依据；仅供测试方便或重复表达同一操作的出口不自动保留。合并能力前核对授权、校验、事务、副作用、版本及失败语义，再同步全部消费者。内部实现可以复用而不扩大公开能力；语义不同的操作不得仅凭字段或调用相似合并。

**E-09.2**：类型别名若明确表达模块语境可以保留，别名不复制同义字段定义。固定取值字段是否冗余应结合完整响应联合、协议意图与消费者判断，不能仅凭当前恒定值删除；白名单边界转换仍按 H-06 保留。

**E-09.3**：协议适配留实际通信边界，用例以业务语义命名，不以新旧版本标签重复维护应用流程。复用前确认输入前提、副作用、错误与生命周期等价；不同政策保留明确用例，相同机制只保留一个 owner。保留参考实现不等于新增兼容桥接；真实消费者迁移才可声明共享契约已接通。

**E-05.1**：资源交付同时明确内部 owner 的窄释放能力；会话撤销或取消不能阻止已获资源的清理。外部按 ID 操作仍认证，内部关闭绑定具体已授权实例，不开放任意资源的无认证入口；并发关闭共享结果，失败与晚到任务由原 owner 追踪。

**E-13.2**：流式读取分别定义容量上限、实际范围与内容一致性。消费前按应用事实确定允许范围，底层按范围执行；新增数据不默默扩张读取，空范围不产生无界流，短读保留失败。固定范围不能解释为内容快照，生命周期约束覆盖流获取、消费和提前终止。

## 授权与异步复查

**E-07.1**：同一入场阶段的身份认证与授权由明确 owner 执行，上下层不重复查询同一权威状态。协议解码、资源归属和业务权限仍各有职责；跨异步建连、资源交付、敏感操作或会话撤销窗口时，按实际风险复查权威身份及操作有效性。去重不能删除这些时间边界上的安全检查，也不能把原应传播的认证或存储失败降为资源不存在。

**E-07.2**：文件路径规范化不能省略真实路径遍历的前提；检查原始路径实际经过的中间节点，再验证规范路径与允许范围。含父目录跳转的路径不能仅凭最终字符串位于范围内就放行。类型/规范路径复查只证明检查时的事实，不冒充跨系统调用的原子隔离。

## 业务规则与事务检查

**E-04.1**（关联 E-02/E-09）：区分行解码、引用完整性和版本检查与业务政策；依赖方向正确不代表职责分离。业务规则只消费应用事实，Model 持有应用/存储转换，Adapter 执行 SQL 和事务。

**E-04.2**：需要最新事实的业务判断通过存储契约中的窄同步回调在原事务内执行；回调签名仅使用 storage 类型；Model 在回调内转换为应用事实、执行纯判断，再投影为存储任务。Adapter 不导入规则实现或应用类型，register 只装配，不将应用对象直接传给 Adapter；回调不执行网络、异步任务或嵌套事务。所有参与写入的入口使用相同约束，规则拒绝不能留下部分业务写入；明确的状态刷新与拒绝结果分别表达。依赖时效的判断在事务实际执行时取时钟事实，不能把入场时刻当成排队后的当前时刻；同一次决策的校验和持久时间使用同一事实。创建回调只根据已读取的权威事实生成记录，不填虚构 revision 或状态等待 Adapter 修补。

**E-02.4**（关联 H-05/H-06、E-09）：安装/公开契约独立定义在其正式出口，并由安装边界显式转换到内部事实；不能因字段相同而借用私有 Model 类型、实现的 ReturnType 或第三方对象。核对导出的完整类型依赖图及真实消费者，避免表面只引用 register/public、实际仍依赖内部结构。

## 前端通信收口检查

**E-02.1**（关联 E-06/E-07/E-09/E-11/E-13）：沿通信、状态协调、展示及跨功能消费者核对错误和类型契约，不只验证 transport。服务端安全取值引用 Shared，本地通信失败归前端 owner；复用应用类型与单文件局部类型按各自消费者放置。

**E-13.1**：形状校验归协议解码，请求关联校验归持有上下文的通信边界，状态有效性归实际状态 owner。资源身份、状态组合和分页语义按各端点契约验证，不对所有接口强加同一种分页或重放行为。

**E-06.1**（关联 E-05/E-09）：响应头、媒体类型、实际读取容量及解码失败均核对资源收尾；提前拒绝也处理未消费的响应体，已取得 reader 的路径最终释放锁。复用前确认预算、失败、取消及生命周期语义一致，不能用通用包装掩盖契约差异。

**E-06.2**（关联 E-01/E-02/E-11）：第三方库或外部协议的原始错误码、状态和错误正文在最靠近它们的 Adapter/技术 owner 归一为具名技术失败契约；上层 Model/Service 只消费该契约，不解析供应商 cause/code/message。原始 cause 可保留作诊断，但不能驱动应用结果；技术契约同时区分尚未派发、确定失败与结果未知，避免把本地取消、回调拒绝或传输中断混为同一语义。

## 交接证据核对

**E-10.1**：按实际 diff、源码和执行输出审核交接；已正确能力接续维护，确认的源码缺口在原阶段补修，实机未验收单独保留。检查记录包含工具版本与路径、分支/SHA/工作区、场景、命令、输出位置及结果；安装版本与仓库版本约束分别核对，不混写不同环境的证据。变更后重跑受影响检查，不沿用此前 PASS。

**E-10.3**（关联 E-01–E-04/E-08/E-09）：涉及功能或架构的阶段，设计时建立、实现后逐项回填以下四份审核表，集中放在当前实施方案的阶段区，不另建施工文档。每项提供可定位的源码或执行证据及结论，不能只填写“符合”；不适用项说明依据。纯文档或格式阶段说明无行为与架构影响后可免填前三表。

| 审核表   | 必须记录的内容                                                                                                                  |
| -------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 功能对应 | 每个原功能的实际入口/消费者、正常语义、新 owner/实现、差异与状态；新增功能标明需求依据，无旧功能不虚构对应项。                  |
| 职责归属 | 关键判断、流程与资源操作的职责、所属层/owner、实际实现和调用链；核对业务政策、技术转换、事务及生命周期，不只检查目录或 import。 |
| 类型归属 | 新增或修改的复用类型/基础取值、唯一 owner、真实消费者及边界转换位置；同义重复定义、私有类型穿透和底层错误结构依赖明确列为偏移。 |
| 完成证据 | 按功能项分别记录源码、架构、静态、逻辑回归及实机状态，关联命令/结果、待验范围或偏移；历史证据标明原基线，不代替当前工作区结果。 |

审核沿“实际入口 → 解码/转换 → 业务流程 → Model → Adapter/Platform → 结果/错误投影 → 消费者”追踪适用环节，同时核对失败、取消和清理分支；没有的层不补空层。完成实现后按最终 diff 再审核一次，不能用设计表替代实际实现核验。已知源码缺口或架构偏移未修复，不得标记相关项或整体阶段完成，也不得仅作为待测试项后移；明确延期的独立项按 E-10.2 承接，不包装为已完成。行为检查受当前授权和实施决定约束，后置时保留“待验”，不影响源码与架构审核的执行。

**E-10.4**（关联 E-03.3/E-05.3/E-06/E-11.1）：自审以最终变更文件和真实流程为覆盖基线。新增、修改、删除、移动文件及受影响消费者均记录已审范围，职责相同的小文件可合并记入 E-10.3 四表；沿正常、拒绝、提交前失败、提交后确认失败、交付前断开及清理失败分支核对返回结果、已有副作用与剩余资源 owner，不以目录正确或成功路径代替审核。按可闭合调用链分批实现并检查，格式化与同文件写入串行完成；最终修改后重跑受影响静态检查。环境阻断单独记录，不能推断源码通过，也不能暂停仍可执行的源码自审。本条不扩大当前测试授权。

## 随工程演进维护

**E-14.1**：写入规则前先确认事实与根因，再提炼适用范围、长期约束及核对方法。规则应在更换模块、阶段、分支或工具版本后仍适用；不能提炼的内容留实施方案或验证记录。优先更新已有类别，独立的新类别追加固定编号，不重复近义规则。

**E-14.2**：规则只保留共性约束与问题类型，不记录具体修复文件、临时任务、完成状态、交接对话或本轮环境。具体任务应引用规则编号，展开到实际 owner、消费者、步骤和判据；任务完成后关闭施工项，长期规则继续按工程演进核对有效性。

**E-14.3**：架构改变时修正失效或冲突条目，不把源码偏离改写成规则例外。AI 工程经验不能自动升级为人工规则。使用现有静态工具和适用逻辑回归验证实现，不新建读取源码文本或目录形状的自定义规则门禁。

## 原功能还原与复合操作结果

**E-03.3**（关联 E-10）：功能能力实现与原通信契约还原分别验收。以实际挂载入口、安装配置及现有消费者核对通道、消息名、参数、默认值、编码、响应、副作用及不同配置下的可用范围；新增一种通道不能替代另一种仍被消费的入口。更严格的新前置条件、缩小操作范围或减少合法部署配置也属于正常功能差异，必须显式处理并定位当前修正或明确延期的 owner，不能仅凭同名操作判定等价。原功能基线以保留的正式源码和实际消费者为准；迁移中的临时实现、历史方案或推测能力不能冒充旧产品已有功能。

**E-11.1**（关联 E-06/E-07）：复合操作的结果按整项副作用判断，包含准备阶段的目录创建、临时写入和部分批量执行。写入已生效后，后续读取、校验或响应失败不能降为确定未写入；无法确认完整结果时保留未知状态与原因。仅包装副作用后的确认阶段，避免将派发前的确定拒绝误报为未知；确认元数据与内容须满足响应契约的关联约束。幂等写入须保存首次事务提交的完整安全结果快照；重放不可从后续可变状态重新拼接首次结果，也不能以原响应已确认推定业务状态从未改变。

**E-10.2**：阶段清理区分完成、部分完成、延期与待验；只清除已验收的施工项，未解决子项明确承接到新规划。历史执行证据保留原代码基线及场景范围，修补后的工作区单独记录静态结果和未运行的行为检查，不延用旧 PASS。

**E-05.2**（关联 E-06/E-09）：异步迭代、流和生产者的生命周期涵盖自然结束、break/return、取消及消费者回调拒绝。收尾放在真实 finally/资源 owner，等待已启动生产者与读写者收敛；资源释放使用实例绑定能力，不依赖已撤销会话重新认证。局部 destroy 不证明远端副作用停止，不作竞争清理。

**E-02.3**（关联 E-01/E-06.2）：第三方命令语法、输出表示、编码库及原始状态归技术 Adapter；Model 显式转成应用事实，Service 决定允许范围、覆盖、发布和恢复政策。复用结果/错误归类型 owner，不能因拆出辅助 Service 就让协议层从该实现借类型；字段相同也保留转换。多重解释边界分别处理语法：shell 引用不能替代工具自身的 pattern/选项转义，字面量名称按最终消费者规则编码。

**E-07.3**（关联 E-05/E-11）：可复用标识不是异步能力的实例身份；能力在创建时绑定具体实例，准入、异步复查、排队执行与释放都核对该实例。配额判断与登记置于同一串行或原子边界；保留在途资源不等于继续许可新请求，释放应具备幂等性。第三方异步构造若依赖共享可变计数或 registry，核对编号分配与实例登记的实际时点；只串行存在竞争的必要步骤，不把完整长任务无依据串行化，也不能用当前计数代替原实例身份。

## 长任务、交付与资源核算

**E-05.3**（关联 E-05.1/E-05.2/E-07）：操作生命周期覆盖准入后的排队、获取资源、执行、交付和最终收尾；写完数据或发送终态前置消息不等于完成。取消按实际资源归属传播：未执行的排队取消不破坏健康共享资源，独立任务只收尾自身资源；父 owner 关闭覆盖其全部关联任务，跨 owner 操作由所有相关方追踪。核对各阶段的关闭等待、最终确认、监听退订与晚结果归属。共享在途任务取消后，新订阅不能加入已撤销实例；若旧任务仍可能写入同一状态，先等待其收敛再替换，排队订阅仍独立响应取消，避免旧收尾覆盖新结果。订阅者离开不解除实际任务归属；子资源的close等待自己持有的任务，不以父模块已追踪HTTP请求作为立即完成的依据。无人等待时发生的晚失败仍保留到实际owner收口。继承清理的准入有明确截止点；关闭快照建立后不得继续接收未被该关闭覆盖的新任务。

**E-05.4**（关联 E-07.3/E-08）：共用同一资源预算的任务类别由唯一 owner 统一准入，计数包含已接纳的排队、执行、关闭及未确认清理的任务；按真实生命周期明确开始占用与允许释放的时点。完成缓存与活跃任务分别核算，重复意图/标识不能覆盖原任务或取得第二份名额。核对混合类别、提交顺序、取消及清理失败，避免局部计数绕过总预算或提前归还名额。

**E-06.3**（关联 E-06.2/E-11）：技术资源关闭成功不代表其临时文件、生产者或其他副作用已清理。清理失败在跨层转换和复合错误聚合中保留具名类别及全部因果，不能被后续成功或通用错误包装抹除；同一失败不重复登记，新增失败不能遗漏。同步抛错与异步拒绝都进入同一收尾路径，保留任务归属及恢复依据，不虚报完成或释放。批量等待后逐项核对结果，不能把 allSettled 完成视为全部释放成功；区分操作取消与清理失败，清理未确认阻止资源退役及名额归还。启动清理前保存共享 Promise，单项失败不得阻止独立资源开始收尾。批量清理将实际调用纳入Promise任务，不能在构造任务集合时因同步抛错跳过其余项；关闭及停止准入也处理同步拒绝。错误收集保持有界，保留未收敛事实，不只记第一次失败。应用错误类不能整体视为可忽略业务拒绝：已映射的存储失败、未知提交及内部故障仍是收口证据；按明确类别区分，并在任务退出前由原 owner 有界记录。

**E-07.4**（关联 E-07.2/E-11）：批量操作在首个副作用前核对整个计划的相互影响，而不只逐项验证；按实际底层语义检查规范位置、别名、祖先/后代、覆盖与读取依赖。准备结果不是后续执行的永久授权，排队后及执行前复查可变身份、owner 和路径事实；确认阶段区分自身操作造成的变化与外部变化。预检不创建目标、不冒充原子快照，无法识别的别名和竞争窗口明确限定保证范围。

**E-07.5**（关联 E-04/E-06/E-07.1/E-09）：共享安全准入政策只能消费由受信传输边界给出的身份或来源事实，客户端字段和未验证的代理转发头不能构成权限。配置缺失与显式关闭、配置畸形与安全服务不可用分别表达；已启用的认证因素或外部验证不得因技术故障静默降级。含异步第三方校验的准入在副作用提交前再次核对会变化的封禁、凭据和权限；敏感写入在实际提交事务核对原授权仍有效，早先认证不替代当前授权事实。事务内不同拒绝原因保持具名结果并在 Model 显式转换，不能合并成布尔值而误报另一失败；共享策略仅装配一次，跨时间边界的权限复查仍由实际业务 owner 负责。核对配置校验、默认值、信任链、拒绝/异常分类以及异步校验后的事务条件。

**E-08.1**（关联 E-08/E-11/E-12）：分别说明协议字节预算、声明量预检、实际结果检查、运行时硬限制与部署前提，不将其中一种表述成另一种保证。外部输出采用有界增量消费，分块和总量均有明确预算，不能先无界缓冲再校验。带分隔符的流先按协议归一化完整分隔单元，再切分记录；核对跨 chunk、编码及多字符分隔符，不能用可回溯表达式把一个分隔单元误拆成两个。终态快照可能重复完整内容，分别核对普通增量、快照和累计传输预算，不能因快照需要扩大普通事件限制。依赖硬限制时确认其在副作用前实际生效，设置失败不继续执行；已明确接受的技术限制如实维护，不写成已实现能力或测试通过。

**E-07.6**（关联 E-02/E-05.3/E-06/E-07.5）：多阶段认证中，待完成流程与完整身份分别持有明确权限、期限及撤销 owner，部分验证不可被普通能力当作完整身份。密码学交互的请求选项与最终验证条件一致，应用策略与技术证据分离；第三方对象在 Adapter 明确投影，无法可靠分类的供应商异常保留不可用结果，不能冒充确定凭据失败或绕过验证。认证资源在后续确认及响应最终交付前持续由原 owner 管理，失败清理与未知副作用按 E-05.3/E-11 处理。

**E-02.5**（关联 H-04–H-07、E-01.1/E-09）：分层检查覆盖方法签名、返回对象、错误和事务回调，不只检查 import。Service 不接收存储记录或技术请求/结果，Model 不以透传包装代替转换；SQL 行与厂商字段由各自 Adapter 解码，Model 只消费已验证的下层契约。内部协作接口留应用 owner，不用 public 文件借用私有类型；真正跨模块出口独立定义安全契约。必填性由实际用例决定，不能为延后的消费者保留虚假的可选声明。存储边界同时覆盖独立缓存、元数据和持久快照，不能以缓存恢复为由将持久 JSON 解码放入 Model；Adapter 返回已验证的存储事实，损坏数据的业务恢复由应用 owner 决定。

**E-08.2**（关联 E-03/E-08.1）：容量核对覆盖完整响应、集合总量、嵌套观察及 JSON 最坏转义。合法单项和最大集合须能通过协议预算；不能只约束输入或逐项长度。有限输出超限使用明确安全容量错误，不截断结果或伪报内部故障；新预算、消费者读取限制和使用说明同步维护。

**E-14.4**（关联 H-09/H-10、E-10.1/E-12）：开发引导保留入口、流程及编号引用；架构保留当前 owner、依赖、契约和保证限制；USAGE 保留操作与恢复。逐轮修复、环境阻断和命令日志归 testing，当前任务归实施方案。精简删除重复与过时叙述，保留未完成依赖、有效配置差异和验收证据，不将历史状态写成当前结论。核对总览表、目录、分节与使用说明的当前事实一致，不能只改新增段落而保留相反旧结论。

**E-06.4**（关联H-05–H-07、E-02.5/E-06.2/E-08）：公开错误码、状态基础值与其参数空间须有唯一取值契约；相同取值在存储和应用层也引用该基础契约，保持各层对象独立。不能用宽泛string、前缀拼接或只校验字符形状代替有限取值；参数化错误码同时限制参数范围。有限取值按原始类型和精确值校验，不通过字符串或数字强制转换后匹配；结果联合只声明真实分支，不能用预留状态支撑不可达处理。底层失败在Model显式映射，运行时解码核对完整联合及状态与关联字段的一致性，未知值不能穿透出口或驱动业务判断。严格解码后的有限对象仍按具名类型表达，不能退化为宽泛字典再靠 typeof 丢弃字段。可复用的同一技术失败转换只保留一个owner，保留内部cause与确定/未知语义。
