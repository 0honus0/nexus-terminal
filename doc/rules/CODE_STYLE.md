# 编码规范

本文约束前后端与 Shared 的实现质量；类型和出口同时遵守 [人工规则](HUMAN.md)，文件放置按 [模块模板](../architecture/MODULE_TEMPLATE.md) 和对应架构。代码精简以职责清楚、结果明确为前提，不以函数行数或文件数量评判。

## 职责与函数

| 编号 | 要求                                                               | 审核方式                                                                    |
| ---- | ------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| C-01 | 函数围绕一个明确操作，主流程能直接读出验证、转换、执行和收尾顺序。 | 完整子流程用具名函数封装；简单表达式或回调就地保留，不机械拆一行包装。      |
| C-02 | 文件按可独立演进的职责划分，单文件 helper 不导出。                 | 共用代码先确认语义、错误和生命周期一致；不建杂项 utils 或按每个动作拆文件。 |
| C-03 | 复杂条件和错误构造先命名中间含义，减少多层嵌套。                   | 提前拒绝无效状态；三元仅做简单取值，不承担异步流程或副作用。                |
| C-04 | 包装和接口必须提供真实契约价值。                                   | 必要的边界投影、权限或资源封装保留；移除无消费者别名、空转层和兼容残骸。    |

## 命名与类型

类型、接口与类用 PascalCase；函数、参数与变量用 camelCase；源码文件用小写连字符，沿用所属模块语义。读取用 get/list，解析用 resolve，转换用 toX/fromX，校验用 validate，生命周期用 open/quiesce/close；布尔名称表达 is/has/can 等含义。避免核心接口使用无上下文的 data、manager 或自造缩写。

公共用例方法写明返回类型，稳定输入/输出与复用联合状态具名定义；局部简单对象允许推断。不同状态使用可辨识联合，状态与字段对应，不能改成宽泛 status 加大量可选字段。复杂参数采用具名对象，避免多个位置布尔参数。类型按语义和消费者归属，不建立全局大集合任意 Pick。

外部 JSON、数据库、Worker/IPC 和第三方结果在真实边界校验；不使用 any、as 或非空断言替代验证。必要第三方断言限于技术边界并说明依据。跨边界对象逐字段构造，数组与嵌套对象同样白名单；错误按具名类别处理。

## 错误、状态与资源

catch 只用于安全映射、补充因果、清理或明确恢复，不能吞未知失败并报成功。内部保留 cause，多项失败使用 AggregateError；技术异常正文和秘密不越过安全出口。

每个 Promise、timer、listener、stream 和 lease 有真实 owner；后台任务说明追踪与拒绝处理。关闭开始前先保存共享 Promise，并发调用共享同一完成和失败。期限按完整操作计算，不逐步重置；取消不证明已派发副作用被回滚。状态保持单一权威，await 后复查身份/版本/generation/终态，失效结果不能覆盖新状态。

## 注释与格式

注释解释原因、授权、事务、取消和未知结果，不重复显然语句。TODO 写明缺失能力与 owner，当前阶段必需的基础能力不能用 TODO 替代。

格式由 `.prettierrc`、`eslint.config.mjs` 和 `scripts/format/` 执行：TypeScript 使用 Tab、单引号、分号、120 列，箭头参数保留括号；函数/方法与独立 export 声明之间保留一行空行，注释紧邻声明，连续 import 不强制隔开。控制语句使用花括号。不局部改配置、滥用 prettier-ignore 或放宽规则换绿；复杂代码先调整结构再格式化。

## 阶段检查

按 [AGENTS 开发与收口流程](../AGENTS.md#开发与收口流程) 及实施方案执行适用的类型、ESLint、Prettier、构建和验证。静态工具只能证明其覆盖范围，不能证明架构、资源收敛或真实行为正确。检查失败在当前阶段解决，未知工作区变更不覆盖或代为提交。

代码阶段执行 `pnpm run check`、`pnpm run format:all:check`、`git diff --check` 和适用包 build；涉及新后端单独执行 Backend-next check，根 check 不替代它。Shared 改变同步 Shared check/build 和双端消费者检查。逻辑回归按 [阶段逻辑回归](../testing/E2E.md#阶段逻辑回归) 及 E-10 执行；文档任务核对格式、链接和 diff。
